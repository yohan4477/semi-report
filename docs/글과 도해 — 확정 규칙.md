# 글과 도해 — 확정 규칙 (2026-09-02)

읽는 사람이 하루 동안 Semi Doped 전략 판 한 장을 놓고 말한 것을 규칙으로 옮겼다. **새로 쓰는
글과 그림은 이 문서를 따른다.** 다른 장(대시보드)과 원문 변환에도 같이 적용한다. 이 문서와
어긋나는 옛 규칙(앞머리 물음·바탕·축, 목차 두 칸, 절 제목의 방법 표기, so-what, 한계 절,
「누가·성격」 열, 임팩트 표)은 그 장의 문서를 고칠 때 이쪽으로 맞춘다.

왜 갈아엎었나 — 저장소의 문서 꼴을 그대로 씌운 판이 「같은 사실이 서너 번 서고 방법 이름이
글을 덮는다. 첫 판이 훨씬 읽기 좋았다」는 말을 들었다.

## 1. 독자

반도체·AI 뉴스를 따라가는 사람. 제품·회사 이름(Blackwell·Groq·UALink)은 안 풀어도 되고,
용어(RTL·NUMA·KV 캐시)는 첫 등장에 괄호로 짧게 푼다.

## 2. 글

**자세** — 전략 컨설턴트 출신 애널리스트. 특정 회사의 의뢰를 받은 것이 아니고 종목을 추천하는
것도 아니다. 원문을 읽고 **업계에 무엇이 보이는지**를 쓴다. 회사가 무엇을 해야 하나가 아니다.
회사의 결정(팔까·좁힐까)은 다뤄도 좋지만 글의 축은 아니다.

**도구는 이름 없이** — 빠짐없이 겹침 없이 나누기, 순서로 보이기, 공급망을 따라 짚기는 하되
MECE·프로세스·밸류체인·대비·부분 나눔 같은 방법 이름은 글에 안 나온다. 구조는 절의 배열로만
드러난다. (밸류체인이 **대상**일 때 — 공급망 자체를 말할 때 — 는 그 말을 쓴다.)

**문체** — 절마다 산문이 흐른다. 절은 다섯에서 일곱. 마지막 절은 원문이 말하지 않은 것과
무엇이 나오면 판단이 바뀌는지. 첫 절 앞에 여는 문단 둘셋 문장. 라벨(물음·바탕·축)은 안 붙인다.

**길이** — 5,500~6,500자. 1만 2천 자는 너무 길다.

**중복 없음** — 같은 사실을 두 번 쓰지 않는다. 표가 바로 위 산문을 되풀이하면 표를 걷는다.
앞 절의 말을 뒤 절에서 다시 하지 않는다. 그림이 글보다 앞에 서서 같은 값을 보이는 것은
중복이 아니다(그림 먼저, 글 나중).

**구성을 말하면 ①②③** — 「둘이다·셋이다·두 구간」으로 열면 항마다 동그라미 숫자.

**인용은 한국어로** — 원문(영어)은 줄 번호로 원본 파일에서 따라간다.

**번역체 낱말** — 이날 걸린 것. 보이면 바꾼다.

```
값이 움직인다        →  새 수요가 생긴다 · 돈이 갈 자리가 생긴다 · 값을 받는다/못 받는다
(자리가) 열린다      →  새 수요가 생긴다 · 기회가 생긴다
자기 몫 · HBM 몫     →  전용 HBM · 따로 둔다
단(段)               →  밸류체인 · 자리   (「아래 단」「세 단」처럼 공급망 층을 뜻할 때)
```
이미 `check_prose` 가 막는 것(돈을 댄다 P18, 은유 주어 P14, 「A 가 아니라 B」 밀도 P9,
대시 밀도 P8)은 그대로 살아 있다.

**정확성** — 값·이름·인용은 원문에 있는 것만. 진행자와 발표자, 말한 사람과 인용된 기사를
구분한다. 문장 끝에 (L줄번호)를 붙여 두고, 받은 뒤 **다른 에이전트**가 원문과 대조해 어긋난
것을 고치고 frontmatter `fixed` 에 적는다. 줄이거나 다듬은 뒤에는 커밋본에 없던 값·이름이
끼지 않았는지 기계로 견준다.

## 3. 도해

**어려우면 그린다. 한 절에 하나라는 제한은 없다.** 글을 쓴 에이전트가 후보(절 · 무엇을 ·
어떤 꼴 · 판 위 글자와 값)를 내고, 그림은 메인 세션이 코드로 그린다.

```
모듈로 그린다     글을 상자에 넣어 세로로 늘어놓은 것은 그림이 아니다. 가속기·랙·칩처럼 대상을
                  모듈 하나로 두고 여럿을 그려 관계(나눠 쓴다·따로 둔다·모인다)가 보이게 한다
견줄 때는 같은 꼴  왼쪽과 오른쪽이 같은 방향·같은 배치여야 다른 한 곳이 보인다.
                  둘 다 위에서 아래로, 다른 것은 아래 상자 하나
누가 무엇을 맡나   한 대상(트랜시버 모듈) 안에서 나라·회사마다 맡은 부품을 견줄 때는 **같은 대상을
                  줄마다 한 번씩** 그리고, 줄마다 그 주체가 맡는 부품만 짙게 칠한다. 나머지는 흰 상자.
                  테두리 배경은 줄마다 같게 두고, 대상 전체에 걸친 것(조립)은 줄 이름에 적는다. 안 되는 꼴 둘 — 줄마다 다른 부품만
                  늘어놓으면 다른 그림 둘로 읽히고, 한 그림에 색만 갈라 넣으면 견줌이 안 된다
                  (2026-09-02 광트랜시버 도해, 세 번 그려 세 번째가 남았다)
값               원문에 있는 것만. 칸 개수도 값이다 — 보기용 수(가속기 넷)를 그렸으면 캡션에
                  「보기용 수, 실제는 원문에 없다」. 자리가 질적인 그림(스펙트럼)은 「값은 없다」
색은 회색만       흰 상자·회색 선(기본) · 옅은 회색 채움에 짙은 선(이 글의 선택, 판에 한 곳) ·
                  점선(문제·아직 없는 것). 화살표·범례·번호도 회색. 주황·청록 없음
글자             판 위에 설명을 안 얹는다. 판단은 캡션에. 줄임말(Gb/s) 대신 풀어 적는다
밸류체인은 끝까지  사슬을 그리면 원문에 나온 단을 끝에서 끝까지 다 그리고, **그 절이 말하는 단만 짙게**
                  표시한다. 말하는 두 단만 뽑아 그리면 층이 셋으로 읽히고 사슬 어디인지도 안 보인다
                  (2026-09-02 광트랜시버 — 부품 → 광원 → 조립 → 구축 넷을 그리고 광원·조립만 짙게)
판 위에 결론 없음  판단 문장(「아래가 빠지면 위도 줄어든다」)을 상자로 판에 두면 그것도 층으로 읽힌다.
                  판 위에는 대상만, 판단은 캡션에
자리             그 이야기가 시작되는 문단 앞. 절 머리에 쌓지 않는다. 절이 다른 이야기로
                  열리는데 그림을 머리에 두면 독자가 무엇인지 모른 채 만난다
검사             생성기가 값을 원문과 대조하고 배치 겹침을 잰다. 도형 개수는 사람이 센다
```

## 5. 확인

- **스크린샷으로 본다.** 검사기 열넷이 FAIL 0 이어도 표가 한 글자씩 세로로 늘어진 것,
  절 머리가 화면 위에 붙은 것, 색이 정신 사나운 것은 눈으로만 잡혔다. 데스크톱 1280 과
  모바일 390 을 찍고, 차례 링크를 하나씩 눌러 절 머리 y 를 찍는다(`scratchpad/shot_toc.js`).
- **라이브도 본다.** 푸시가 곧 배포가 아니다. 2026-09-02 에 다른 세션이 생성기만 커밋하고
  산출물을 안 올려 `gen_site.py` 가 깨끗한 체크아웃에서 죽었고 세 시간 동안 아무도 못 봤다.
  `git archive HEAD` 로 깨끗한 폴더에 풀어 `gen_site.py` 를 돌려 보고, 라이브 페이지의
  도해 수·색·문장을 기계로 센다.

5  도해를 그린다(메인). 생성 → 검사 → 스크린샷 → 커밋 → 푸시 → 라이브 확인

## 이 문서가 아직 안 정한 것

- 번역체 낱말 목록을 `check_prose` 규칙으로 옮기는 일. 「열린다」는 문이 열리는 뜻과 갈라야
  해서 말 그대로 막을 수 없다 — 「자리·시장·수요 + 열린다」 꼴로 잡는 규칙을 세울 때 결함을
  넣어 무는지 먼저 본다.
- 모바일에서 도해 글자가 작은 것(520 판이 350 으로 줄면 10px). 그림이 스무 장쯤 되면 한 번에.
- 기술 판. 첫 실물을 받은 뒤 적는다.
