# Semi Doped 대시보드 — 만드는 규칙

회차 하나에 판이 둘 선다 — ⚖ 전략과 🔧 기술. 판은 다른 모델에게 전사 전문을 읽혀 받은
글이고, 받은 문장은 고치지 않는다(값이 틀린 것만 고치고 frontmatter 에 적는다). 화면 조립은
`scratchpad/gen_semidoped.py`, 규약은 같은 파일 `check_ui()`.

2026-09-02 에 규칙을 한 번 갈아엎었다. 저장소의 문서 꼴(앞머리 물음·바탕·축, 목차 두 칸,
절 제목의 방법 표기, so-what, 한계 절, 「누가·성격」 열, 임팩트 표)을 전략 판에 그대로 씌웠더니
같은 사실이 서너 번 서고 방법 이름이 글을 덮었다. 읽는 사람이 「첫 판이 훨씬 읽기 좋았다」고
했다. 그래서 이 장은 **그 꼴을 쓰지 않는다.** 아래가 전부다.

## 전략 판

**누가 쓰나** — 전략 컨설턴트 출신 애널리스트. 특정 회사의 의뢰를 받은 것이 아니고 종목을
추천하는 것도 아니다. 회차를 읽고 업계를 읽는 독자에게 전략적 해설과 인사이트를 쓴다.

**무엇을 쓰나** — 이 회차를 읽으면 업계에 무엇이 보이나. 회사가 무엇을 해야 하나가 아니다.
「팔 것인가」 같은 회사 결정은 다뤄도 좋지만 글의 축은 아니다.

**어떻게 쓰나** — 컨설턴트의 도구(빠짐없이 겹침 없이 나누기, 순서로 보이기, 공급망 단 따라
짚기)를 **이름 없이** 쓴다. MECE·프로세스·밸류체인·대비 같은 말은 글에 안 나온다. 구조는 절의
배열과 표의 꼴로만 드러난다.

**문체** — 첫 판(2026-09-02 첫 실물, git ed57caac)이 기준이다. 절마다 산문이 흐르고, 표는
정말 견줄 것이 둘 이상일 때 절에 하나 이하. 진행자 둘의 말과 발표자의 말을 구분해 옮긴다.
같은 사실을 두 번 쓰지 않는다. 절은 다섯에서 일곱, 마지막 절은 이 회차가 말하지 않은 것과
무엇이 나오면 판단이 바뀌는지. 길이는 1만 3천~1만 6천 자.

**정확성** — 값·이름·인용은 전사에 있는 것만. 인용은 원문 그대로 + (L줄). 받은 뒤 다른
에이전트가 전사와 대조하고, 어긋난 것은 고쳐 frontmatter `fixed` 에 적는다.

**frontmatter** — slug · lane · persona · model · source · sent · date · title. title 은 결론 한 문장.

## 도해

어렵거나 복잡한 대목은 그림으로. 글을 쓴 에이전트가 후보 셋(절 · 무엇을 · 어떤 꼴 · 판 위
글자와 값)을 내고, 그림은 메인 세션이 `scratchpad/semidoped_figs.py` 에 코드로 그린다. 받은
글 안에는 그림이 없다 — 절 제목 머리(「2.」)로 걸고 생성기가 그 제목 바로 아래에 세운다.
값은 전사에 있는 것만(칸 개수도 값이다). 생성기가 값을 전사와 대조하고 배치 겹침을 재서
통과해야 실린다.

## 화면

독자는 **반도체·AI 뉴스를 따라가는 사람**이다(2026-09-02 결정). 제품·회사 이름(Blackwell·
Groq·UALink…)은 안 풀어도 되고, 용어(RTL·NUMA·KV 캐시…)는 첫 등장에 괄호로 푼다.

회차 목록 한 장과 회차마다 글 한 장. 접힘·타일·카드 없음. 글 페이지는 제목 → 회차 메타 →
판 제목(결론 한 문장) → 차례(절 제목, 앵커) → 절. 절 제목은 번호와 물음만. 본문 폭 760.
전사 줄 번호 (L97) 는 대조용이라 **원본 파일에만 남기고 화면에서는 걷는다**. 영어 인용은
옅은 색 — 앞뒤 한국어 문장이 뜻을 말하고 인용은 근거다.
640px 아래에서 표는 행 블록으로 접히고(칸마다 열 이름), 390px 에서 옆으로 밀리면 생성기가
멈춘다(`check_scroll.js`, Playwright). 2026-09-02 에 Playwright 로 찍어 보고 세운 규약이다 —
5열 표가 모바일에서 한 글자씩 세로로 늘어졌고 검사기 열넷은 그걸 못 봤다.
