# Semi Doped 대시보드 — 만드는 규칙

회차 하나에 판이 둘 선다 — ⚖ 전략과 🔧 기술. 판은 다른 모델에게 전사 전문을 읽혀 받은
글이다. 화면 조립은 `scratchpad/gen_semidoped.py`, 도해는 `scratchpad/semidoped_figs.py`,
규약은 `check_ui()` 와 `check_scroll.js`.

2026-09-02 에 규칙을 갈아엎었다. 저장소의 문서 꼴(앞머리 물음·바탕·축, 목차 두 칸, 절 제목의
방법 표기, so-what, 한계 절, 「누가·성격」 열, 임팩트 표, 구조 절과 트리)을 씌웠더니 같은 사실이
서너 번 서고 방법 이름이 글을 덮었다. 읽는 사람이 「첫 판이 훨씬 읽기 좋았다」고 했다. 이 장은
**그 꼴을 쓰지 않는다.** 아래가 전부고, 전부 그날 읽는 사람이 말한 것에서 나왔다.

## 독자

반도체·AI 뉴스를 따라가는 사람. 제품·회사 이름(Blackwell·Groq·UALink)은 안 풀어도 되고,
용어(RTL·NUMA·KV 캐시)는 첫 등장에 괄호로 짧게 푼다.

## 전략 판 — 글

**누가 쓰나** — 전략 컨설턴트 출신 애널리스트. 특정 회사의 의뢰를 받은 것이 아니고 종목을
추천하는 것도 아니다. 회차를 읽고 업계에 무엇이 보이는지를 쓴다. 회사가 무엇을 해야 하나가
아니다 — 「팔 것인가」 같은 회사 결정은 다뤄도 좋지만 글의 축은 아니다.

**어떻게 쓰나** — 컨설턴트의 도구(빠짐없이 겹침 없이 나누기, 순서로 보이기, 공급망 단 따라
짚기)를 **이름 없이** 쓴다. MECE·프로세스·밸류체인·대비·부분 나눔 같은 말은 글에 안 나온다.
구조는 절의 배열로만 드러난다.

**문체** — 첫 판(git ed57caac)이 기준. 절마다 산문이 흐른다. 절은 다섯에서 일곱. 마지막 절은
이 회차가 말하지 않은 것과 무엇이 나오면 판단이 바뀌는지.

**길이** — 5,500~6,500자. 1만 2천 자는 너무 길다고 했다.

**중복 없음** — 같은 사실을 두 번 쓰지 않는다. 표가 바로 위 산문을 되풀이하면 표를 걷는다.
2026-09-02 에 세 절의 표가 그래서 걷혔다. 앞 절의 말을 뒤 절에서 다시 하지 않는다.

**구성을 말하면 ①②③** — 「둘이다·셋이다·두 구간」으로 열면 항마다 동그라미 숫자를 단다.

**인용은 한국어로** — 원문(영어)은 전사 줄 번호로 원본 파일에서 따라간다.

**정확성** — 값·이름·인용은 전사에 있는 것만. 진행자 둘의 말과 발표자의 말을 구분한다. 문장
끝에 (L줄번호)를 붙여 두고, 받은 뒤 다른 에이전트가 전사와 대조해 어긋난 것을 고치고
frontmatter `fixed` 에 적는다.

**frontmatter** — slug · lane · persona · model · source · sent · date · title. title 은 결론 한 문장.

## 도해

어렵거나 복잡한 대목은 그림으로. **한 절에 하나라는 제한은 없다 — 어려우면 그린다.** 글을
쓴 에이전트가 후보를 내고, 그림은 메인 세션이 코드로 그린다. 절 제목 머리(「4.」)로 걸어
절 제목 바로 아래, 글보다 앞에 선다.

```
모듈로 그린다     글을 상자에 넣어 세로로 늘어놓은 것은 그림이 아니다. 가속기·랙·칩처럼 대상을
                  모듈 하나로 두고 여럿을 그려 관계(나눠 쓴다·각자 갖는다·모인다)가 보이게 한다
견줄 때는 같은 꼴  왼쪽과 오른쪽이 같은 방향·같은 배치여야 다른 한 곳이 보인다.
                  둘 다 위에서 아래로, 다른 것은 아래 상자 하나
값               전사에 있는 것만. 칸 개수도 값이다 — 보기용 수(가속기 넷)를 그렸으면 캡션에
                  「보기용 수, 실제는 전사에 없다」를 적는다
색은 셋           흰 상자·회색 선(기본) · 옅은 청록(이 회차의 선택, 판에 한 곳) · 점선 회색
                  (문제·아직 없는 것). 화살표도 회색. 주황·강조색 여럿은 정신 사납다
자리             절이 그 이야기로 바로 열리는 곳에만. 절 중간 이야기의 그림을 절 머리에 두면
                  독자가 무엇인지 모른 채 만난다(5절 스케일업 그림이 그래서 걷혔다)
검사             생성기가 값을 전사와 대조하고 배치 겹침을 잰다. 도형 개수는 사람이 본다
```

## 화면

회차 목록 한 장과 회차마다 글 한 장. 접힘·타일·카드 없음.

```
글 페이지     제목 → 회차 메타(날짜·진행자·원문·요약본) → 화자 줄 → 판 제목 → 여는 문단 → 차례 → 절
화자 줄       팟캐스트라 누가 말하는지가 먼저다. 요약본 frontmatter people 에 「진행 … / 발표 …」.
              말한 사람만 — 진행자가 인용한 기사(SemiAnalysis)는 화자가 아니다.
              전사에 없는 소속·직함은 안 적는다
차례          절 제목만 한 칸으로, 앵커. 눌렀을 때 절 머리 위에 22px 여백(scroll-margin-top)
절 제목       번호와 제목만. 방법 이름 없음
글자          본문 15px / 1.8, 폭 720, 문단 사이 20px. 17px 은 너무 컸다
줄 번호       (L97) 은 화면에서 걷는다. 원본 파일에만 남는다
모바일        640px 아래에서 표는 행 블록으로. 390px 에서 옆으로 밀리면 생성기가 멈춘다
```

검사 — `check_ui()`(접힘·타일·차례·화자 메타), `check_scroll.js`(390px 가로 스크롤),
`shot_toc.js`(차례 링크마다 눌러 절 머리 y 를 찍는다), 도해 값·배치는 생성 때.
