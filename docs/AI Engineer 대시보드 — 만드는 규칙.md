# AI Engineer 대시보드 — 만드는 규칙

컨퍼런스 발표 한 편이 카드 한 장이다. 규칙이 `scratchpad/gen_aie_dashboard.py` 머리말에만
있어서 눈에 안 띄었다. 여기로 옮기고 **구조화 절을 더한다** — 절을 늘어놓기만 하면 발표가
목록이 되고, 그러면 이 장이 다른 요약 사이트와 구별되지 않는다.

**본보기는 `content/understanding/AI Engineer/2026-07-26-LLM에게-운전대를-주지-마라.md` 다.**
아래 규칙은 대부분 그 카드에서 되읽은 것이다.

**이 문서는 이 장의 형식과 검증을 맡는다.** 글을 세우는 법(물음·축·목차·비교표·한계)은
`doc-structure` 가 정본이고 여기 다시 적지 않는다 — 두 곳에 적히면 한쪽이 낡는다.

앞선 문서를 전제로 한다.
- `doc-structure` 스킬 — 앞머리 셋·절=물음·비교표·한계
- `insight-figure` 스킬 — 없는 값 금지·좌표 계산·판 위 글자 금지·검사기

---

## 1. 형식이 둘이다

```
format: report   68편. 지금 쓰는 꼴. 절 제목(## )·문단·그림 부름([[fig:이름]])이 섞여 흐른다
번호글            13편. 옛 꼴. 한 생각에 번호 하나를 매겨 죽 늘어놓는다
```

새 카드는 `report` 로 쓴다. 발표는 논지가 앞에서 뒤로 굴러가는 글이라 「핵심 포인트 ·
주요 숫자 · 인용」으로 쪼개면 「앞의 것이 뒤에 어떻게 걸리나」가 사라진다. 번호글도 같은
이유로 만든 꼴이지만, 절 제목을 물음으로 쓸 수 있는 `report` 가 축을 더 잘 세운다.

카드 목록을 생성기에 적지 않는다. `content/understanding/AI Engineer/*.md` 한 편이 카드
한 장이고, 어느 섹션에 설지·주제칩·`gain` 까지 전부 프런트매터에 있다.

```
title date source speaker org channel dur section topic format gain
section 은 생성기 SEC 의 열쇠말 하나다. 없는 열쇠말을 적으면 생성이 멈춘다
```

## 2. 구조화 — 절을 늘어놓지 않는다

`doc-structure` 를 이 장의 꼴로 내린 것이다.

### 앞머리 — 한줄 코멘트가 그 자리다

본문 첫 문단(`한줄 코멘트.` 로 시작)이 앞머리다. 셋을 담는다.

```
남는 것   발표에서 가장 오래 남는 대목 하나. 요약이 아니라 고른 것이다
왜 그런가  그것이 왜 그렇게 되는지 한 겹 더. 여기가 빠지면 인상만 남는다
조건      언제·무엇을 전제로 한 이야기인가. 그대로 옮기면 안 되는 자리를 밝힌다
```

본보기가 셋을 다 갖췄다 — 하이쿠 4.5로도 됐다는 대목(남는 것), 모델이 작아서가 아니라
하네스가 판단을 가져가 모델 몫이 줄었기 때문(왜 그런가), 하네스 없이 모델만 바꾸면
신뢰성이 오히려 떨어진다(조건).

**한줄 코멘트에 별표를 남기지 않는다.** 용어 표시를 안 거치는 자리라 생성이 멈춘다.

### 절 제목이 축이다

`## N. 제목` 이 축 노릇을 한다. **제목이 물음 하나를 답해야 한다.** 본보기의 여섯이 그렇다.

```
1. 무엇이 문제였나        2. 무엇을 바꿨나        3. 한 단계가 어떻게 도나
4. 그래서 작은 모델로 내려갔다   5. 언제 이 방법을 쓰나   6. 발표가 밝히지 않은 것
```

앞의 셋이 진단·처방·작동이고, 4는 결과, 5는 적용 조건, 6은 한계다. **발표 순서를 그대로
옮긴 것이 아니라 물음으로 다시 세운 것이다.**

```
나쁘다   ## 3. 여러 가지 팁      물음이 아니라 서랍이다
나쁘다   ## 7. 평가와 배포       「A와 B」다. 두 절로 나눈다
```

절이 여덟을 넘으면 발표가 아니라 목록을 옮긴 것이다. 묶어서 줄인다.

### 견주는 것이 둘 이상이면 표로

방법 둘을 견주거나 모델 여럿을 재면 산문으로 늘어놓지 말고 표를 세운다(`표:` 로 시작하는
문단이나 파이프 표를 파서가 읽는다). 열은 모두에게 같은 물음이어야 한다.

**표에는 「언제 것 · 성격」을 단다.** 발표장 숫자는 셋이 섞여 있다.

```
사내 실험    발표자가 재서 보여 준 값       2026-07 · 사내 실험
공개 값      누구나 확인할 수 있는 값       2026-07 · 공개
발표자 주장   근거 없이 말로만 한 것         — · 주장
```

이 구분이 없으면 무대에서 한 말이 측정치처럼 굳는다. 이 장에서 가장 자주 나는 사고다.

### 마지막 절은 한계

본보기의 「6. 발표가 밝히지 않은 것」이 그 자리다. 발표는 파는 자리라 실패가 잘 안 나온다 —
**안 나왔다는 사실 자체를 적는다.** 본보기는 각 단계가 안에서 무엇을 하는지 발표가 대지
않았다는 것을 본문에서 그대로 밝힌다.

### 용어

`용어` 로 시작하는 문단에 적으면 본문의 `*이름` 이 그 뜻으로 짚인다. 용어를 본문에서
풀어 쓰지 말고 이 자리에 모은다.

## 3. 도해

```
report 꼴   본문 줄 하나에 [[fig:이름]] — aie_figs.RFIGS[영상ID][이름] 에서 꺼낸다
            이름이 사전에 없으면 생성이 멈춘다
번호글 꼴    figs = [(anchor, 제목, svg, 캡션)] · anchor 는 그 그림이 푸는 번호 바로 앞
```

**없는 값을 그리지 않는다.** 발표 슬라이드에 있던 수라도 우리 변환본에 없으면 그리지
않는다. 막대 높이·아이콘 개수도 값으로 읽힌다. 항목이 셋을 넘으면 좌우가 아니라 위아래로
쌓고, 칸 폭은 `w_of()` 가 글자에 맞춰 잰다. 배치는 `scratchpad/check_fig.py` 가 본다.

## 5. 흔한 사고

| 증상 | 원인 | 처방 |
|---|---|---|
| 「그냥 요약 같다」 | 절을 늘어놓고 축이 없다 | 절 제목을 물음으로 |
| 「이게 실험이야 주장이야」 | 표에 성격이 없다 | 「언제 것 · 성격」 |
| 「지금도 맞는 얘기야?」 | 조건을 안 밝혔다 | 한줄 코멘트의 조건 |
| 「그림이 발표보다 세게 말한다」 | 변환본에 없는 값을 그렸다 | insight-figure 규칙 1 |
| 「절이 두 말을 한다」 | 제목이 「A와 B」다 | 절을 둘로 |
| 생성이 멈춘다 | 한줄 코멘트에 별표가 남았거나 그림 이름이 사전에 없다 | 용어 문단으로 옮기고 이름을 맞춘다 |
