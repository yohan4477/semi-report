# AI Engineer 대시보드 — 만드는 규칙

컨퍼런스 발표 한 편이 카드 한 장이다. 규칙이 `scratchpad/gen_aie_dashboard.py` 머리말에만
있어서 눈에 안 띄었다. 여기로 옮기고 **구조화 절을 더한다** — 번호를 늘어놓기만 하면
발표가 목록이 되고, 그러면 이 장이 다른 요약 사이트와 구별되지 않는다.

앞선 문서를 전제로 한다.
- `doc-structure` 스킬 — 앞머리 셋·절=물음·비교표·한계
- `insight-figure` 스킬 — 없는 값 금지·좌표 계산·판 위 글자 금지·검사기
- `docs/도해 유형 — 무엇을 언제 그리나.md` — 유형 다섯

---

## 1. 이 장이 다른 장과 다른 점

카드를 「핵심 포인트 · 주요 숫자 · 인용」으로 쪼개 쓰지 않는다. 메르 장처럼 **한 생각에
번호 하나**를 매겨 죽 늘어놓는다. 발표는 논지가 앞에서 뒤로 굴러가는 글이라, 조각으로
쪼개면 「앞의 것이 뒤에 어떻게 걸리나」가 사라진다.

카드 목록을 생성기에 적지 않는다. `content/understanding/AI Engineer/*.md` 한 편이
카드 한 장이고, 어느 섹션에 설지·주제칩·`gain` 까지 전부 그 글의 프런트매터에 있다.
글을 넣고 생성기를 다시 돌리면 카드가 는다.

```
title date source speaker org channel dur section topic format gain
section 은 생성기 SEC 의 열쇠말 하나다. 없는 열쇠말을 적으면 생성이 멈춘다
```

## 2. 구조화 — 번호를 늘어놓지 않는다

`doc-structure` 의 규칙을 이 장의 꼴로 옮긴 것이다. 번호글이라는 형식은 그대로 두고,
그 안에 축을 세운다.

### 앞머리 — 한줄 코멘트가 그 자리다

카드 맨 위 한 문단이 앞머리다. 셋을 담는다.

```
물음   이 발표가 답하는 물음 하나
남는 것 발표에서 가장 오래 남는 대목 하나 — 요약이 아니라 고른 것
때 조건 언제 기준의 이야기인가. 모델 판이 바뀌면 못 쓰는 요령이면 여기서 밝힌다
```

실물이 이미 그렇게 돼 있다 — 「적어 놓은 추론이 실제로 밟은 길과 다를 수 있다는 대목이
가장 오래 남는다 … 다만 두 판 앞의 모델을 두고 한 이야기라 지금 판에서 다시 재고 옮겨야
한다」. 이 꼴을 규칙으로 굳힌다.

### 소제목이 축이다

번호마다 붙는 `## N. 제목` 이 축 노릇을 한다. **제목이 물음 하나를 답해야 한다.**

```
좋다   ## 2. 왜 어려운가          — 물음이다
좋다   ## 5. 물음을 어디에 두나     — 물음이다
나쁘다  ## 3. 여러 가지 팁         — 물음이 아니라 서랍이다
나쁘다  ## 7. 평가와 배포          — 「A와 B」다. 둘로 나눈다
```

번호가 열을 넘으면 **세 묶음 안으로 접힌다**. 발표는 대개 「무엇이 문제인가 · 어떻게 했나 ·
무엇이 남았나」로 접힌다. 접히지 않으면 발표가 아니라 목록을 옮긴 것이다.

### 견주는 것이 둘 이상이면 표로

발표가 방법 둘을 견주거나 모델 여럿을 재면 산문으로 늘어놓지 말고 표를 세운다.
열은 모두에게 같은 물음이어야 한다.

**표에는 「언제 것 · 성격」을 단다.** 발표장 숫자는 셋이 섞여 있다.

```
사내 실험 결과   발표자가 재서 보여 준 값        2024-08 · 사내 실험
공개 벤치마크    누구나 확인할 수 있는 값        2024-08 · 공개
발표자 주장      근거 없이 말로만 한 것          — · 주장
```

이 구분이 없으면 청중 앞에서 한 말이 측정치처럼 굳는다. 카드 안에서 가장 자주 나는 사고다.

### 한계는 카드 안에

`gain` 에 적는 것과 별개로, 본문 끝에 「이 발표가 안 다룬 것」을 한 문단 둔다. 발표는
파는 자리라 실패한 것이 잘 안 나온다 — 안 나왔다는 사실 자체를 적는다.

## 3. 도해

`scratchpad/aie_figs.py` 에 영상 ID를 열쇠로 넣는다. 값은 `card_lib` 의 figs 그대로다.

```
[(anchor, 제목, svg, 캡션)]
anchor 는 그 그림이 푸는 번호 바로 앞이다 — 7~19번을 푸는 그림이면 6
```

**없는 값을 그리지 않는다.** 발표 슬라이드에 있던 수라도 우리 변환본에 없으면 그리지
않는다. 막대 높이·아이콘 개수도 값으로 읽힌다. 배치는 `scratchpad/check_fig.py` 가 본다.

## 4. 검사

```bash
PYTHONIOENCODING=utf-8 python scratchpad/gen_aie_dashboard.py
PYTHONIOENCODING=utf-8 python insights/check_prose.py    # P19 번역투 포함
PYTHONIOENCODING=utf-8 python insights/check_read.py
PYTHONIOENCODING=utf-8 python scratchpad/check_fig.py
```

대시보드 HTML을 손으로 고치지 않는다. 고칠 것은 원문 md 와 생성기다.

## 5. 흔한 사고

| 증상 | 원인 | 처방 |
|---|---|---|
| 「그냥 요약 같다」 | 번호만 늘어놓고 축이 없다 | 소제목을 물음으로, 세 묶음으로 접는다 |
| 「이게 실험이야 주장이야」 | 표에 성격이 없다 | 「언제 것 · 성격」 |
| 「지금도 맞는 얘기야?」 | 모델 판 조건을 안 밝혔다 | 앞머리의 때 조건 |
| 「그림이 발표보다 세게 말한다」 | 변환본에 없는 값을 그렸다 | insight-figure 규칙 1 |
| 「절이 두 말을 한다」 | 소제목이 「A와 B」다 | 절을 둘로 |
