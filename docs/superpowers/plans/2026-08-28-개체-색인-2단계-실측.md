## 눈으로 보고 고친 것

**전망 줄 열 개를 읽었다.** 어긋난 것은 하나였다 — 「부모가 준 전세금, 20년 뒤 국세청에 털립니다」라는 **영상 제목**이 출처 줄에 인용돼 있어 2046년 전망으로 잡혔다. 제목 인용은 그 문서의 주장이 아니다. 「2000년 닷컴·2007년 서브프라임 … 2027」처럼 지난 일과 앞날이 한 줄에 있어 최대 연도로 전망이 된 줄은 설계대로다.

**계산 줄 열두 개를 읽었더니 오탐이 둘이었고, 규칙 버그였다.**

```
「MS 와 20년 전력공급 계약」   → 20년 전 으로 읽어 2006년
「IT 인프라가 10~20년 뒤처짐」 → 20년 뒤 로 읽어 2046년
```

둘 다 기간을 시점으로 읽은 것이다. 「전」이 「력」과, 「뒤」가 「처」와 붙어 다른 낱말이 됐는데 규칙이 그 자리를 안 막았다. 시점을 가리키는 「N년 전/뒤/후」는 조사나 공백이 뒤따르므로, 뒤에 다른 한글 음절이 붙으면 버리도록 `times.OFFSET`을 고쳤다. 계산 줄이 215에서 208로 줄었다.

고친 뒤 표본 열두 줄을 다시 읽었고 **오탐 0**이었다. 가장 먼 2066년도 확인했다 — 「40년 뒤 재건축에서 개발이익을 누가 갖느냐」로, 토지임대부 아파트의 진짜 시점 언급이다.

## 증분 색인 — 글이 들어올 때마다 전수를 다시 훑지 않는다

2단계를 끝낸 뒤 재빌드 값을 재니 `gen_index`가 **37.4초**였다. 글 한 편을 붙일 때마다 478편을 통째로 다시 훑고, 2.5MB짜리 `index.json`이 매번 통째로 다시 커밋된다.

`_meta.files_stat`에 파일별 `[해시, 줄 수]`를 적어 두고 해시가 바뀐 파일만 다시 훑도록 고쳤다.

| | |
|---|---|
| 전수 (`--full`) | 37.4초 |
| 증분 · 바뀐 것 없음 | 0.36초 |
| 증분 · 새 글 한 편 | 0.36초 |

100배다. 새 글 한 편을 넣었을 때 hit이 20,034에서 20,036으로 늘어 두 줄을 제대로 잡았고, 파일을 지우니 원래 색인으로 정확히 돌아왔다. 전수 결과와 증분 결과가 같은지는 실제 코퍼스에서 대조해 확인했고, 편집·추가·삭제 세 경우는 단위 테스트가 전수와 증분을 직접 비교한다.

**전수로 되돌아가는 경우가 하나 있다.** 사전(`entities.json`)이 바뀌었을 때다. 별칭 하나가 늘면 모든 줄의 판정이 달라져 옛 주소를 하나도 못 믿는다. `_meta.entities_hash`를 같이 적어 두고 다르면 전부 다시 훑는다.

`_meta.fingerprint`의 값은 안 바뀌었다 — 전에도 파일별 sha1을 이어 붙여 만들었고 지금은 그 재료를 `files_stat`과 나눠 쓸 뿐이다. 그래서 X1 검사와 `times.json`의 `index_fingerprint`가 그대로 맞는다. `index.json`은 2.5MB에서 2.6MB로 늘었다.
