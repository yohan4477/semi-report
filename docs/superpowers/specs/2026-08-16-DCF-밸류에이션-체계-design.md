# DCF 밸류에이션 체계 — 남의 평가를 내 근거로 감사한다

작성 2026-08-16.

## 왜 만드나

네이버 프리미엄 채널 `busymoon/kicpakpmg`의 필자 **엘곰**은 DCF 방법론 글과 기업별
평가 글을 함께 쓴다. 방법론은 견고하다 — 3단계 fade 성장, D&A와 CAPEX의 시차,
CAPM으로 뽑은 WACC까지 전개가 서 있다. 그런데 **거기 들어가는 숫자가 검증되지
않는다.**

같은 필자가 삼성전자를 다섯 달 사이 세 번 평가했는데 서로 어긋난다.

| 날짜 | 방법 | 2026년 영업이익 가정 | 결과 | 그때 시장가 |
|---|---|---|---|---|
| 2026-02-26 | 역산(reverse) | 61조 (시나리오 B) | 적정시총 1,250~1,400조 | 218,000원 |
| 2026-05-03 | 외부 인용 | — (FCF 197.2조) | 주당 577,263원 | 220,500원 |
| 2026-07-16 | 정방향 8년 DCF | **383조** | 주당 361,000원 | 255,250원 |

2026년 영업이익 가정이 61조에서 383조로 여섯 배 뛰었다. 07-16 글의 표는 매출
732조(전년비 +119.5%), 영업이익률 52.3%를 깔고 있다. 삼성전자 2025년 매출은
300조대이고 역대 최고 영업이익률은 2018년 24%쯤이다. 02-26 글이 인용한 증권사
추정 상단(180조)의 두 배다.

표 파싱 오류가 아니다. FCF 233.8조 → EV 1,993.6조 → 순현금 119.2조 가산 →
주주지분 2,112.9조 ÷ 58.46억주 = 361,410원으로 내부가 맞물린다. 필자가 실제로
그 숫자를 썼다.

05-03 글도 같은 성격이다. FCF가 TTM 23.2조에서 2026년 197.2조로 8.5배 뛰는
Simply Wall St 전망을 검증 없이 인용했다.

**그 숫자들 — 메모리 가격, HBM4 물량, 하이퍼스케일러 CAPEX, 파운드리 수율 — 은
이 저장소의 노트가 이미 다루는 것이다.** 방법론은 그의 것을 쓰고, 숫자는 내
근거로 판정한다. 그게 이 체계다.

두 개다.

## 밸류에이션 네 종류

필자의 글은 네 종류로 갈린다. `method` 필드가 이를 구분한다.

| method | 무엇 | 입력 | 출력 |
|---|---|---|---|
| `statements` | 재무제표 분석. 앞단계 | 과거 3~5년 재무제표 | NOPAT·D&A·CAPEX·NWC 정상비율 |
| `simple` | 한 덩어리 FCF에 성장률·할인율 하나씩 | 정상 FCF, g, r | 주당가치 1개 |
| `dcf` | 3단계 fade, 연도별 추정 | 단계별 g·마진·CAPEX | 주당가치 + 연도별 표 |
| `reverse` | 현재가를 정답으로 놓고 역산 | 시장가, r, g | 시장이 깔고 있는 성장률 |
| `cited` | 외부 기관 값을 그대로 인용 | — | 그 기관의 값 |

**`reverse`가 이 판에 제일 잘 맞는다.** 정방향은 "내 가정이 옳나"를 다투게 되는데
그건 증명하기 어렵다. 역방향은 "시장은 삼성전자 2026년 영업이익 70~90조를 깔고
있다"를 뽑아주고, 그 70~90조가 말이 되는지는 내 노트가 판정할 수 있다.

## 룰북

`docs/valuation-rulebook.md`. 룰마다 번호를 매기고 세 칸으로 나눈다.

| 칸 | 내용 |
|---|---|
| 필자가 정한 것 | R1 FCFF 공식, R7 3단계 구분, R9 마지막해 성장률≈g … |
| 필자가 비워둔 것 | 아직 글이 없는 영역. `simple`·`reverse`의 룰이 여기 |
| 내가 어긴 것 | 회사별 이탈. 평가 JSON이 룰 번호로 가리킨다 |

원문 전문은 옮기지 않는다. 내 말로 압축하고 요약본 줄 포인터만 단다.

현재 확보된 방법론 글에서 나온 것:

**FCF 편 (2026-04-25 ①②)**

```
FCFF = NOPAT + D&A − CAPEX − △NWC
NOPAT = EBIT × (1−t)
NWC   = 매출채권 + 재고 + 선급금 − 매입채무 − 선수금
```

- EBIT 정제 다섯: 일회성 구조조정·자산처분손익·지분법손익·금융수익·R&D 자본화
- PPA 무형자산 상각은 일반 D&A와 분리한다. add back 하면 FCF가 과대해진다
- CAPEX/매출 산업 평균: 반도체·장치 20~40%, 바이오 10~20%, SaaS 3~8%, 서비스 2~5%
- 장기에는 D&A = CAPEX로 수렴한다고 본다. 따라서 장기 FCF ≈ NOPAT
- Normalized FCF: 과거 3~5년 비율 분해 → 이상치 제거 → 정상비율 × 매출
- 성장의 역설: 성장률이 높을수록 FCF는 오히려 낮다

**성장률 편 (2025-03-05·03-07)**

- 3단계: 초고속 3~5년 → 전환 5~10년(10~30%) → 안정 영구
- 마지막 예측연도 성장률이 영구성장률에 근접해야 한다. 크게 벌어지면 예측기간을 늘린다
- 한국 관행(5년 성장 후 6년차 급락)은 빅테크에 부적합하다고 명시적으로 반박한다
- Terminal Value가 전체 가치의 절반 이상을 먹는다

**할인율 (2026-07-16 삼성전자 편에서 전개)**

```
Rf 4.20% (한국 10년 국고채) + β 1.18 (52주) × MRP 5.50% (Damodaran 한국)
= Ke 10.69%
Kd(세후) 2.80%,  D/(D+E) 4.44%   →   WACC 10.34%
```

## 평가 파일

평가 한 번이 파일 한 장이다. 한 파일에 판(revision) 배열을 몰지 않는다 — git
diff가 죽고, 새 평가가 들어온 사실이 커밋에 안 보인다.

```
insights/valuation/005930-삼성전자/
  meta.json                      종목코드·발행주식수·회사 고정값
  2026-02-26-엘곰-역산.json       method: reverse
  2026-05-03-엘곰-인용.json       method: cited
  2026-07-16-엘곰-정방향.json     method: dcf
  2026-08-16-내감사.json          basis: 2026-07-16-엘곰-정방향
```

**가정은 고정 필드가 아니라 리스트다.** 시점마다 항목 자체가 생기기 때문이다 —
07-16 글에서 "D&A = 직전 4개년 CAPEX 평균"이라는 가정이 처음 등장했는데, 02-26
글에는 그 개념이 아예 없다. 고정 스키마였다면 담을 자리가 없다.

```json
{
  "as_of": "2026-08-16",
  "method": "audit",
  "basis": "2026-07-16-엘곰-정방향",
  "source": "content/understanding/회계사/[2026-07-16] ....md",
  "price": {"value": 255250, "as_of": "2026-07-16", "note": "필자 기재 장중가"},
  "assumptions": [
    {"key": "rev_2026", "label": "2026년 매출", "rule": "R11",
     "theirs": 732.5, "mine": null, "unit": "조원",
     "verdict": "확인필요",
     "why": "필자 본인 02-26 글은 2026년 영업이익을 61조로 봤다. 같은 필자가 …",
     "cite": "삼성전자 DCF 밸류에이션 L48"}
  ],
  "output": {"per_share": 361000, "ev": 1993.6, "tv_share": 0.33}
}
```

**판정은 넷이다.** `유지` / `수정` / `보류` / `확인필요`.

- `수정`하려면 `cite`가 필수다. 근거 없이 숫자를 바꾸지 않는다
- `보류`는 내 코퍼스에 근거가 없다는 뜻이다. 필자의 값을 그대로 쓴다
- `확인필요`는 그 값이 다른 자료와 어긋나는데 아직 어느 쪽이 맞는지 못 정한 상태다

**근거는 `insights/notes/`만 쓴다.** 교차 인사이트(`synth/`)와 브리핑은 노트의
파생물이라 근거로 삼으면 이중계산이 된다.

## 판 사이 diff

`gen_valuation.py`가 인접한 두 판을 자동으로 대조해 「이번에 달라진 것」을 뽑는다.
손으로 쓰지 않는다.

```
2026-02-26 → 2026-07-16   필자가 바꾼 것
  2026 영업이익  61조 → 383조  (+528%)   근거 제시 없음
  방법          역산 → 정방향
  WACC          9.0% → 10.34%            CAPM으로 교체
```

## 계산기

`insights/dcf.py`. 순수 함수. 룰북이 정의한 계산만 넣는다.

- FCFF + WACC가 기본. FCFE도 지원한다(필자가 NVDA에 쓴 방식)
- 3단계 fade는 선형 보간
- 감도표는 WACC × 영구성장률 격자
- 역산: 목표 시가총액을 넣으면 필요 성장률 또는 내재 할인율을 되돌린다

**재현 테스트가 관문이다.** `insights/test_dcf.py`에 필자의 결과를 박는다.

| 사례 | 기대값 |
|---|---|
| 삼성전자 2026-07-16 | 주당 361,000원 (±1%), 감도표 25칸 |
| NVDA 2025-03-07 | 주당 $127.19 (±1%) |

못 맞추면 내 계산기가 틀린 것이다. 맞춘 뒤에야 가정을 놓고 다툴 수 있다.

## 화면

**회계사 대시보드** — `gen_site.py` PAGES에 `locked=True`, `gen_hub.py` TOPICS에

최신 판이 펼쳐지고 이전 판은 접힌다(롤업 리포트가 쓰는 부품).

## 순서

```
1. 요약본 7편 → 노트 7장          (Sonnet 위임)
2. 룰북 R번호 확정                 (메인)
3. dcf.py + test_dcf.py           (Sonnet 위임, 재현 테스트로 검증)
4. 회계사 대시보드 + 등록          (Sonnet / Haiku 위임)
5. 삼성전자 평가 JSON 넉 장         (메인 — 판정은 위임하지 않는다)
6. gen_valuation.py + 통합 인사이트 섹션  (Sonnet 위임)
```

3번을 통과하지 못하면 5번으로 넘어가지 않는다.

- 종목 추천, 목표주가, 매매 판단
