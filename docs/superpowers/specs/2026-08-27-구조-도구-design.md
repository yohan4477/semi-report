# 구조 도구 — 물음을 쪼개서 답까지 가는 길을 찾는다

물음 하나를 받아 쪼갬 후보를 세우고, 가지마다 근거를 붙이고, 어디를 더 파야 하는지 가리킨다. MBB 케이스 인터뷰에서 structure 를 짜는 그 일이다.

만들어 놓고 보는 그림이 아니다. **답까지 가는 탐색 절차**다.

## 왜 MECE 인가 — 소거를 정당하게 만들려고

MECE 자체가 목적이 아니다. 원인을 빨리 찾는다는 것은 매번 탐색 공간을 지운다는 뜻이고, 그 지우기가 유효하려면 두 조건이 필요하다.

```
겹치면   가지 하나를 지워도 원인이 아직 거기 있을 수 있다   → 못 지운다
빠지면   다 뒤졌는데 답은 안 센 자리에 있다              → 헛수고
```

그래서 겹침과 빠짐을 본다. **완벽할 필요는 없다** — 다만 얼마나 겹치고 얼마나 비었는지를 알아야 지운 가지를 믿을 수 있다.

같은 이유로 겹침은 몫을 못 믿게 만든다. 가지끼리 겹치면 「이게 80%」를 말할 수 없다. 같은 값을 두 가지가 나눠 세기 때문이다. **몫을 못 믿으면 어디를 팔지 못 정한다.**

## 쏠림은 성적이 아니라 방향이다

가지에 몫을 붙이고 나면 대개 한쪽으로 쏠린다. 그것은 컷이 좋다는 뜻도 나쁘다는 뜻도 아니다.

```
쏠린 가지     거기가 답이 사는 데다      →  더 쪼갠다
안 쏠린 가지  건드릴 값이 없다          →  거기서 멈춘다
```

「비용의 80%가 칩이다」는 컷을 칭찬하는 말이 아니라 **칩을 더 쪼개라**는 지시다.

## 뎁스는 노드마다 다르다

그래서 트리가 고르게 깊으면 안 된다. **고르게 깊은 트리는 우선순위를 안 매겼다는 표시다.**

```
회수
├ 드는 돈 ─ 칩 ─ 메모리 ─ HBM 계약 ─ 선불 조건    4단
├ 드는 돈 ─ 인건                                1단에서 멈춤
└ 버는 돈 ─ 단가 ─ 계약 형태                     2단
```

인건비가 전체의 3%면 거기를 네 단까지 파는 것은 낭비다. 균형을 맞추려 들면 그 낭비를 하게 된다.

## 나쁜 컷은 셋뿐이다

쏠림으로는 컷을 못 가른다. 못 쓰는 컷은 이렇다.

```
못 채운다    가지에 붙일 근거가 없다
겹친다      몫을 귀속시킬 수가 없다
안 갈린다    고르게 나뉘는데 아래로 더 내려가도 여전히 고르다
```

셋째가 미묘하다. 고르게 나뉘는 것 자체는 문제가 아니다 — 덜 쪼개면 된다. 문제는 **더 내려가도 안 갈리는** 경우다. 그 컷이 이 물음에서 아무것도 구별 못 한다는 뜻이라, 그 노드에서 다른 컷으로 갈아탄다.

## 형은 노드마다 정해지고 섞여 든다

구조 전체가 트리이거나 프로세스인 것이 아니다. **노드마다 그 자리에서 제일 잘 쪼개지는 방식을 고른다.**

```
회수되는가
└ 수식      회수 = 버는 돈 − 드는 돈
  ├ 드는 돈
  │ └ 구성   칩 · 설비 · 전력 · 인건
  │   └ 전력
  │     └ 프로세스  조달 → 송전 → 배전 → 냉각
  │       └ 배전
  │         └ 인과   변압기 리드타임 → 가동 지연 → 회수 지연
  └ 버는 돈
    └ 수식    공급량 × 단가 × 가동률
```

수식 안에 구성이 들고 그 안에 프로세스가 들고 그 안에 인과가 든다. 순수 트리도 아니다 — 프로세스의 「가동」이 수식의 「공급량」으로 흘러든다. **가로지르는 선이 있다.**

## 한 노드가 쪼갬을 여럿 갖는다

같은 노드를 여러 방식으로 열 수 있어야 한다. 물음은 하나인데 접근이 셋이다.

```
[A] 수식     회수 = 매출 − 비용            어느 항이 큰가
[B] 프로세스  조달 → 설비 → 가동 → 매출 → 재조달   어디서 끊기나 (고리다)
[C] 행위자    칩 · 클라우드 · 모델 · 전력      누가 남기고 누가 뒤집어쓰나
```

셋이 경쟁하지 하나가 맞는 것이 아니다. **하나로 안 좁혀도 된다.** A 가 「칩이 비용을 지배」라 하고 C 가 「마진은 전력회사가 가져감」이라 하면 둘 다 참이고, 그 불일치가 곧 답이다. 억지로 고르면 정보를 버린다.

## 쪼개는 갈래 — 목록이지 메뉴가 아니다

| 갈래 | 꼴 | 강점 |
|---|---|---|
| 이분법 | A / A 아닌 것 | 공짜로 MECE다. 통찰은 약해도 구멍이 없다 |
| 수식 | 매출 = 단가 × 수량 | 몫이 계산으로 나온다 |
| 구성 | 비용 = 재료 + 인건 + 물류 | 합이 전체가 된다 |
| 프로세스 | 유입 → 전환 → 유지 → 이탈 | 어디서 새나 |
| 공급/수요 | 공급 측 / 수요 측 | 값과 양이 걸린 물음 |
| 행위자 | 공급자·고객·경쟁자·규제자 | 누가 먹고 누가 뒤집어쓰나 |
| 안/밖 | 우리 탓 / 바깥 변화 | 통제 가능한 것을 가른다 |
| 시간 | 전 / 후, 언제부터 | 방아쇠가 언제 당겨졌나 |
| 대립 | 살까 만들까 | 진단이 아니라 결정용 |
| 구간 | 상위 20% / 나머지 | 쏠린 데를 바로 집는다 |

원인을 찾을 때와 해결책을 찾을 때 첫 컷이 다르다. 원인은 안/밖 → 시간 → 프로세스 → 수식 순으로 지우는 힘이 세고, 해결책은 행위자·대립·구성 쪽이다.

**이 표는 제안을 돕는 힌트다.** 물음에서 갈래로 가는 매핑이 아니다.

## 목록이 메뉴로 굳는 것을 막는 장치

힌트라고 적어 두는 것은 약속이지 장치가 아니다. 읽으면 결국 거기서 고른다. 그래서 셋을 건다.

**코드가 갈래 이름을 모른다.** 검사기는 `'수식'`·`'프로세스'` 같은 문자열로 분기하지 않는다. 전개가 **스스로 주장하는 성질**을 읽고 그에 맞는 검사만 돌린다.

```
전개 = {
  자식: [...],
  주장: {
    exhaustive  자식이 부모를 다 덮는다고 주장하나
    exclusive   서로 안 겹친다고 주장하나
    additive    자식의 합이 부모와 같다
    ordered     순서가 있다
    cyclic      마지막이 처음으로 돌아온다
  }
}
```

「수식」은 `additive+exclusive+exhaustive`를 켠 프리셋일 뿐이고, 그 프리셋은 스킬 산문에 산다. **검사기는 프리셋을 안 본다.** 갈래를 새로 지어내도 성질만 밝히면 똑같이 검사된다.

이것이 유일하게 검증 가능한 장치다. 위 표를 통째로 지워도 검사기 테스트가 전부 통과해야 한다. 안 통과하면 어딘가 의존이 생긴 것이다.

나머지 둘은 절차다. **짓고 나서 대조한다** — 재료를 보고 먼저 컷을 지어낸 뒤 표와 맞춰 빠뜨린 것을 확인한다. 그리고 **매번 표에 없는 후보를 하나 요구한다** — 못 지어내면 생각한 것이 아니라 고른 것이다.

## 전처리 없이는 숫자가 거짓말한다

가지에 근거를 붙이려면 코퍼스를 훑어야 하는데, 지금 그대로 세면 이런 값이 나온다.

```
자금 조달 구조   253편   ← 「부채」·「금리」가 아무 글에나 나와 부푼 값
시간당 단가       14편
```

18배가 실제 차이인지 낱말이 흔한 정도 차이인지 구분이 안 된다.

**시간을 붙인다.** 줄마다 쓴 날과 가리키는 때를 갖는다. 파일 날짜는 이미 있고 가리키는 때가 없다. 메르 클리핑을 재면 글 하나에 서로 다른 연도가 중앙값 셋, 최대 열여섯이다. 파일 날짜 하나로 뭉개면 63년치가 한 점에 찍힌다. 회수 논증에서 2023년 GPU 가격은 근거가 아니라 소음이다.

가리키는 때를 쓴 날과 견주면 회고·현재·전망으로 갈린다. **회고는 안 낡고 전망은 낡는다.** 신선도를 회고에 먹이면 1965년 회고가 「60년 낡음」으로 걸러진다.

**원천으로 접는다.** 코퍼스가 층으로 쌓여 있다 — 원문에서 노트로, 카드로, 보고서로. 같은 주장이 여러 층에 있고 **배수가 주장마다 다르다.** 어떤 주장은 한 번, 어떤 주장은 다섯 번 복제된다.

고정 배수면 비교에서 상쇄되는데 들쭉날쭉하면 안 된다. 그러면 가지 두께가 근거의 양이 아니라 **네가 그 얘기를 몇 번 썼는지**를 재게 된다.

```
많이 쓴 주제  →  층마다 복제  →  가지가 두껍다  →  "여긴 잘 덮었네"
안 쓴 주제    →  원문 한 줄   →  가지가 얇다    →  "여긴 구멍이네"
```

그럴듯한데 뒤집으면 **이미 아는 것을 확인해 줄 뿐이다.** 트리의 목적이 안 본 데를 찾는 것인데 지표가 많이 본 데에 보상을 준다. 순환이다.

그래서 문서를 세지 않고 **원천을 센다.** 노트가 원문을 `(파일이름 L123)`으로 인용하고 `cites.json`이 그 줄을 잡고 있으며 카드도 원문 링크를 갖는다. 되짚는 길이 이미 깔려 있으니 새로 만들 것이 아니라 쓰면 된다.

접고 나면 반대가 보일 수 있다 — 제일 두꺼워 보이던 가지가 원문 하나를 다섯 번 우려낸 것일 수 있다. 그것이 나오면 진짜 발견이다.

**순서.** 시간과 원천 접기가 최소선이다. 그 둘 없이 트리에 숫자를 붙이면 그럴듯하게 틀린다. 개체 정규화는 행위자 컷을 세우는 순간 필요해지고, 수량 파싱은 `additive` 를 켠 전개를 검사할 때 필요하다. 주장 단위 분할은 비싸므로 나중이다.

## 어디까지가 기계이고 어디부터가 판단인가

```
컷 후보를 세운다              판단    메인 세션
겹치나 — 이 둘이 같은 것인가   판단    도메인 지식이 든다
가지에 근거를 붙인다           기계    전처리가 받쳐야 한다
몫을 세고 쏠림을 잰다          기계
자식 합이 부모와 같나          기계    additive 를 켠 전개만. 산수다
빠진 가지가 있나              섞임    다른 문서가 더 센 것은 기계, 세상에 더 있나는 판단
어디를 팔지 정한다             기계    몫 순으로 세운다
멈출 때인가                   판단    잎이 관찰·결정에 닿았나
```

기계는 **못 쓸 후보를 걸러 내고 쓸만한 후보에 숫자를 붙이는 데까지**다. 고르는 것은 사람이다.

## 산출물

```
skills/구조-짜기/SKILL.md    절차와 갈래 힌트. 판단이 사는 곳
scripts/structure.py         전개의 주장을 검사한다. 갈래 이름을 모른다
scripts/evidence.py          가지에 근거를 붙인다. 전처리 위에 선다
insights/times.json          생성물. 줄 주소 → 가리키는 때·확실도
insights/origins.json        생성물. 파생 주소 → 원천 주소
```

트리를 저장소에 쌓지 않는다. 물음마다 새로 세우고 보고서만 남긴다. 대신 **보고서가 재현 가능해야 한다** — 무슨 컷을 썼고 어느 가지에 무엇이 붙었고 코퍼스가 어느 시점이었는지를 함께 적는다. 저장된 트리가 없으니 그것을 안 적으면 같은 보고서를 다시 만들 수 없다.

## 안 하는 것

- **트리를 저장소에 쌓지 않는다.** 축 대장을 두면 굳는다. 굳은 구조를 없애려고 만드는 도구다
- **물음에서 갈래로 가는 매핑을 코드에 두지 않는다.** 표에 없는 물음이 막힌다
- **검사기가 갈래 이름으로 분기하지 않는다.** 전개가 밝힌 성질만 읽는다
- **MECE를 강제하지 않는다.** 겹침과 빠짐을 숫자로 낼 뿐 막지 않는다
- **트리를 균형 잡지 않는다.** 뎁스가 제각각인 것이 정상이다
- **컷을 하나로 좁히지 않는다.** 여럿의 불일치가 정보다
- **전처리 없이 숫자를 붙이지 않는다.** 시간과 원천 접기 전에는 세지 않는다
- **카드를 분류하지 않는다.** 서류 정리는 이 도구의 일이 아니다
- **글을 고치지 않는다.** 구멍을 짚기만 한다. 집필은 판단이고 `insight-review` 의 몫이다
