# 청약 공고를 쉽게 보는 화면 — 스펙

대상: `대시보드/포트폴리오 워치.html` 「청약 — 조건」 절 축약 + 새 페이지 `대시보드/watch/청약 공고.html`.
조립은 `scratchpad/gen_watch_page.py`. 색·간격·글꼴은 그 파일 `CSS` 상수의 기존 토큰만 쓴다(새 토큰 없음).

## 1. 물음 다섯이 답해지는 자리

| 물음 | 어디서 | 몇 초 | 어떻게 |
|---|---|---|---|
| ① 지금 접수 중인 게 있나 | 본 장 「청약」 절 첫 줄(요약 문장) · 새 페이지 h1 아래 `.verdict` | 1초 | 문장으로 박는다. 없으면 「지금 접수 중인 공고가 없습니다」 |
| ② 이번 달·다음 달 접수 예정 | 본 장 「청약」 절 목록 최대 3건 · 새 페이지 §접수 예정 | 3초 | 접수 시작 가까운 순. 상태 칩이 「접수 예정」 |
| ③ 최근 발표된 건 경쟁률 | 새 페이지 §발표됨, 한 건의 셋째 줄 | 5초 | 발표 최근 순. 「1순위 경쟁률 2.8~81.17:1」 |
| ④ 어느 구·몇 세대·상한제·입주 | 한 건의 둘째 줄(모든 절 공통) | 같은 5초 | 첫 줄에 구, 둘째 줄에 세대수·분양가상한제·입주 예정 |
| ⑤ 어디서 신청하나 | 한 건의 셋째 줄 오른쪽 | 1초 | 「청약홈에서 보기 →」(단지명도 같은 링크) |

구별 필터는 두지 않는다 — 지도 「청약 공고」 층이 이미 구로 고르는 자리다. 페이지에는 「구」를 값으로만 적는다.

## 2. 상태 규칙 (기계가 정한다)

입력: `today`(만드는 날), `apply`=접수 시작(RCEPT_BGNDE), `end`=접수 종료(RCEPT_ENDDE, **지금은 없음**), `announce`=당첨자 발표(PRZWNER_PRESNATN_DE). 전부 `YYYY-MM-DD` 문자열 비교로 판정한다.

```
apply 가 없으면                                   → "일정 미정"
today <  apply                                    → "접수 예정"
end 가 있고  apply <= today <= end                → "접수 중"
end 가 없고  today == apply                       → "접수 중"        ← 대체 규칙
announce 가 있고 today <  announce  (위에 안 걸림) → "접수 마감·발표 대기"
announce 가 있고 today >= announce                → "발표됨"
announce 가 없고 today >  apply                   → "접수 마감·발표 대기"
```

**종료일이 없을 때의 대체 규칙**: 종료일을 추정해 만들지 않는다(「값은 원문에 있는 것만」). 접수 시작 당일만 「접수 중」으로 보고 다음 날부터는 「접수 마감·발표 대기」다. 기간 표기도 `2026-09-07~`로 끝을 비운 채 낸다. 어댑터가 `end`를 받아 오면 이 규칙은 자동으로 안 쓰인다.

상태는 **만드는 시점에 계산해 HTML에 박는다**(JS는 계산하지 않는다 — 이 장의 기존 규약). 그래서 두 화면 모두 캡션에 「상태는 화면 만든 날(YYYY-MM-DD) 기준입니다」를 적는다.

정렬: 접수 예정·접수 중은 `apply` **오름차순**(가까운 것 먼저), 발표 대기·발표됨은 `announce` **내림차순**(최근 것 먼저). 일정 미정은 맨 끝.

## 4. 새 페이지 `대시보드/watch/청약 공고.html`


## 5. 지도 구 패널 변경

`gu_panel()`의 단지 줄(`gp-sub-item`)에 칩을 **줄 끝**에 붙인다. 값 줄이 좁아 칩이 커지면 안 되므로 그 자리에서만 작게 줄인다.

```html
<p class="gp-row gp-sub-item">브라운스톤 월곡 센트럴 · 접수 09-07
  <span class="tag t-near gp-chip">접수 예정</span></p>
```

```css
.gp-chip{font-size:11px;padding:1px 6px;margin-left:6px;vertical-align:1px}
```

「최근 공고 n건」 줄은 그대로 두고 그 오른쪽에 「지금 접수 중 1건」을 잔글씨로 덧붙인다(0이면 안 붙인다). 패널 맨 아래 `gp-more` 위에 한 줄 더: `<a class="gp-more" href="watch/청약 공고.html">이 구 공고 전부 보기 →</a>` — 페이지에 구 필터가 없으므로 앵커 없이 페이지 전체로 간다(구별 필터를 안 두기로 한 결정과 어긋나지 않게 문구는 「공고 전부 보기 →」로 통일해도 된다).

## 6. 어댑터가 더 받을 필드 · 없을 때

`subscription.py`의 `it` dict에 아래를 더한다. **없으면 그 조각을 통째로 빼고 가운뎃점도 같이 뺀다 — `—`를 찍지 않는다.**

| 열쇠 | API 필드 | 화면 자리 | 없으면 |
|---|---|---|---|
| `end` | `RCEPT_ENDDE` | 둘째 줄 「접수 2026-08-24~08-26」 | 「접수 2026-08-24~」 + 상태 대체 규칙 |
| `total` | `TOT_SUPLY_HSHLDCO` | 둘째 줄 「468세대」 | 조각 삭제 |
| `movein` | `MVN_PREARNGE_YM` | 둘째 줄 「입주 2029-03」 | 조각 삭제 |
| `sp_apply` | `SPSPLY_RCEPT_BGNDE` | 둘째 줄 끝 「특별공급 2026-08-23」 | 조각 삭제 |
| `pblanc_de` | `RCRIT_PBLANC_DE` | 정렬 보조·「자료 기준」 계산 | 지금대로 `apply`로 정렬 |
| `builder` | `CNSTRCT_ENTRPS_NM` | 첫 줄 단지명 아래 잔글씨 | 조각 삭제 |
| `hmpg` | `HMPG_ADRES` | 셋째 줄 「분양 홈페이지 →」 | 청약홈 링크만 |

`end`가 들어오면 상태 규칙의 대체 경로가 저절로 안 쓰이고, 기간 표기가 `~08-26`으로 닫힌다. 나머지 필드는 하나도 안 와도 화면이 그대로 선다(둘째 줄이 「접수·발표·분양가상한제」 셋으로 줄 뿐).

## 7. 하지 말 것 셋

1. **개인 판정 금지.** 「당신은 1순위입니다」·「넣어 볼 만합니다」·「경쟁률이 낮으니 유리」를 쓰지 않는다. 상태 칩은 날짜 사실이고 조건 표는 규칙이다 — 그 둘을 이어 붙여 결론을 내는 문장은 화면이 아니라 독자 몫이다.
2. **없는 값을 만들지 않는다.** 접수 종료일을 「시작 +2일」로 추정하지 않고, 빈 자리에 `—`나 「미정」 자리표시를 찍지 않는다(조각째 뺀다). 경쟁률이 없는 건에는 셋째 줄 왼쪽을 비운다.
3. **경쟁률에 방향 색(`--up`/`--down`)을 쓰지 않고, 이 장에서 접지 않는다.** 경쟁률 240:1은 오름도 내림도 아니다(`--ink-2` 고정). `is-fold`·`uc-caret`·`class="stile`은 `check_ui`가 막는다 — 새 페이지도 같은 규약으로 검사에 넣는다(`check_detail_ui`가 `watches` 슬러그만 돌므로 `청약 공고.html`을 명시로 더한다).
