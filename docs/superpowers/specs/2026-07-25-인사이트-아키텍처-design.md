# 인사이트 합성 아키텍처 — 성장하는 코퍼스 위 통합 인사이트

작성일: 2026-07-25

## 1. 목적 / 문제

SemiAnalysis(뉴스레터 코퍼스)와 언더스탠딩(제3자 해설)에서 통합 인사이트를 뽑아 여러 대시보드(임팩트 타임라인, 언더스탠딩, 인텔리전스, 미래의 지도)가 보여준다. 소스가 계속 늘어나는데, 현재는 인사이트가 각 대시보드에 애드혹으로 박혀 있어 다음 문제가 있다:

- 새 소스가 생기면 **전체 코퍼스를 다시 뒤져야** 하나?
- append만 하면 **코퍼스 전체에서만 보이는 새 인사이트(emergent)**를 놓친다.
- semi·understanding가 따로 놀아 **최종 통합**이 안 된다.

이 스펙은 인사이트를 **데이터 계층**으로 분리해, 증분 갱신(싸게)과 주기적 전체 재합성(놓침 방지)을 함께 지원하고, 여러 소비자(대시보드·지도)가 읽는 단일 진실을 만든다.

## 2. 요구사항 (확정)

- 새 소스 추가 시 **영향받는 클러스터만** 재합성(전체 재스캔 금지).
- 어느 클러스터에도 안 걸린 **uncovered 소스를 표면화**(emergent 후보).
- **주기적 전체 재합성**(`--full`)으로 새 인사이트 발굴.
- 인사이트는 **corpus-agnostic** — semi/und/both. 테스트기엔 코퍼스별, 최종엔 통합.
- 소스·이벤트에 **선택적 `geo`** — 미래 지도 소비자 대응(지도 자체는 이 스펙 아님).
- 소비자(UI 렌더)는 별도 스펙(B). 이 스펙은 데이터 계층 + 툴링 + 기존 인사이트 이관까지.

**비목표(YAGNI)**: UI 렌더 변경, 지도 구현, semi 전 코퍼스 합성 저술(지속 작업), 자동 LLM 클러스터링.

## 3. 데이터 모델 (3계층)

**소스 id**: `<corpus>:<category>:<slug>` (안정 불변). 예 `semi:compute:250214-데이터센터-해부학-part2`, `und:oil:하르그섬`.

### Layer 1 — 매니페스트 `insights/manifest.json` (자동 생성)
```json
{ "generated": "2026-07-25", "sources": [
  {"id":"semi:cooling:250214-…", "corpus":"semianalysis", "category":"cooling",
   "date":"2025-02-14", "path":"content/newsletter/ai_infra/cooling/[250214]….md",
   "hash":"ab12cd34ef56",
   "geo":[{"place":"대만 가오슝","lat":22.63,"lng":120.30,"role":"팹"}]}
]}
```
- `content/newsletter/**` + `content/understanding/**` 스캔. `corpus`=경로 최상위(newsletter→semianalysis, understanding→und). `category`=하위 폴더. `date`=파일명 `[YYMMDD]` 또는 frontmatter `published`/`updated`. `hash`=본문 sha1 앞 12자. `geo`=선택(없으면 생략).
- 손편집 금지 — 항상 스크립트 재생성.

### Layer 2 — 인사이트 클러스터 `insights/clusters/<id>.md`
```yaml
---
cluster_id: A-이란전쟁
title: "이란 전쟁과 원유 수급 충격"
subtitle: "…"
corpus_scope: und           # semi | und | both
categories: [oil]           # 라우팅 키 — 이 카테고리 신규 소스가 소관
sources: ["und:oil:밥엘만데브", "und:oil:하르그섬", …]
source_hashes: {"und:oil:밥엘만데브":"ab12…", …}
covered_through: "2026-07-25"
---
## 통합 논지
## 공통 진단
## 연결·인과
## 상충·이견
## 함의·다음 확인 포인트
```
`sources`+`source_hashes`가 "무엇을, 어느 버전까지 반영했나"를 박제 → Layer 3의 stale 판정 근거.

### Layer 3 — 커버리지·갭 (`insights/coverage.py`)
manifest ↔ clusters diff → `insights/coverage_report.md` + 종료코드.

## 4. 커버리지·stale 알고리즘

**라우팅**: 클러스터 `categories`로 신규 소스를 내용 안 읽고 매칭.

**클러스터가 stale** ⇔ 아래 중 하나:
- (a) `sources` 중 manifest hash ≠ `source_hashes` (내용 변경)
- (b) `sources` 중 manifest에 없는 id (삭제/이동)
- (c) `categories`에 속하는 manifest 소스가 `sources`에 없음 (반영할 신규)

**소스가 uncovered** ⇔ 어느 클러스터 `sources`에도 없고 어느 클러스터 `categories`에도 안 걸림 → 새 클러스터 후보.

**출력**:
```
STALE: A-이란전쟁 (신규 2: 하르그·미군이란 / 변경 1)
UNCOVERED: semi:robotics:unitree … (N건) → 새 클러스터 검토
OK: B-원유의존 …
```
- `--full`: 기존 클러스터 무시, 전 소스를 검토 대상으로 덤프 → 모델 전체 재합성.
- `uncovered ≥ K`(기본 5) → "새 클러스터/전체 재합성 권장" 배너.

## 5. 스크립트 / 워크플로

**스크립트 (`insights/`, stdlib만, `PYTHONUTF8=1 py`)**
- `gen_manifest.py` — 스캔 → manifest.json. 결정적·멱등.
- `coverage.py [--full]` — diff → coverage_report.md + 종료코드.
- `validate_insights.py` — 클러스터 frontmatter 유효성 + `sources` id의 manifest 존재 확인(끊긴 provenance 검출).
- 합성 저술 = 모델 작업(스크립트 아님).

**워크플로**
1. 새 소스 파일 추가(기존 파이프라인) → `gen_manifest.py` → `coverage.py`.
2. 리포트의 **stale 클러스터만** 모델이 재합성(그 소스만 재독 → 5블록 갱신 → sources/hashes/covered_through 갱신).
3. uncovered → 새 클러스터 검토(임계 배너).
4. 주기적 `--full` → emergent 발굴·재편.

**소비자(별도 스펙 B)**: 대시보드·지도가 manifest+clusters 읽어 렌더.

## 6. 마이그레이션

- 기존 `content/understanding/통합/*.md` 4편 → `insights/clusters/`(corpus_scope: und, categories/sources/hashes 부여). 근거 카드 제목 → 소스 id 매핑.
- SemiAnalysis: 임팩트 타임라인 `THESES` 5테마 / `통합 리포트/` → corpus_scope: semi 클러스터로 provenance 작성.
- **최종(별도)**: `--full` 병합 패스로 corpus_scope: both 크로스-코퍼스 클러스터.

## 7. 에러 / 엣지

- manifest 소스 date 파싱 실패 → `date:null`, 경고(중단 X).
- 클러스터 `sources` id가 manifest에 없음 → validate가 ERROR로 보고(끊긴 provenance).
- clusters 디렉터리 비어있음 → coverage는 전 소스 uncovered로 보고.
- geo 없는 소스 → 필드 생략(정상).
- 같은 slug 충돌 → 카테고리로 네임스페이스됨(`corpus:category:slug` 전체가 id).

## 8. 검증 / 테스트

- `gen_manifest.py`: 픽스처 스캔 → id·category·hash 정확; 내용 변경 시 hash 변경; 재실행 멱등.
- `coverage.py`: 픽스처로 stale(a/b/c)·uncovered·ok 정확 분류; `--full` 전량.
- `validate_insights.py`: 존재 안 하는 소스 id·깨진 frontmatter 검출.
- 롤아웃 검증: 언더스탠딩 4클러스터 이관 후 coverage에서 그 소스 OK; validate 0 깨짐; manifest 멱등.

## 9. 산출물 경계

- **포함**: 스키마 + 툴링 3종(TDD) + 언더스탠딩 4클러스터 이관 + semi 초기 클러스터 provenance + coverage 베이스라인.
- **제외**: UI 렌더(스펙 B), 지도(미래), semi 전 코퍼스 합성 저술, LLM 자동 클러스터링.
