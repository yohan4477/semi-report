# 포트폴리오 워치에 청약을 더한다 — 기획 메모

2026-09-03. 화면은 「서울에서 집 구하는 사람이 한 달에 한 번 열어 2분 안에 본다」는
자리다. 청약은 전세·매매와 나란한 **세 번째 선택지**로 들어간다.

**개인 판정을 하지 않는다.** 통장 가입 기간이나 부양가족 수를 입력받아 「넣을 수 있다」를
답하지 않는다 — 조건을 표로 세워 놓고 독자가 자기 상황을 대 보게 한다. 판정을 하면
틀렸을 때 책임이 화면에 오고, 규칙이 바뀌면 판정 로직이 조용히 낡는다.

## 자동으로 받을 수 있는 것 / 사람이 확인해야 하는 것

**자동** — ⑴ 「주택공급에 관한 규칙」 시행일자(법령 API, 오늘 2026-06-15 확인). 판이
바뀌었는지가 이 한 값으로 갈린다. ⑵ 세 권역의 모집공고 목록·경쟁률(청약홈 API, 열쇠 필요).

**수동** — ⑴ 순위 요건·가점제 비율·특별공급 비율 같은 **조문 안의 수**. 별표는 표라서
글로 받아도 판형이 바뀌면 읽는 방식이 깨진다(대출 규제 줄에서 같은 판단을 이미 했다).
⑵ 분양가상한제 지역 지정·해제. 공고가 PDF로만 나와 자동으로 못 받는다. ⑶ 단지별 분양가와
납부 일정. 공고문마다 다르고 API 가 안 준다.

## 화면에 새로 서는 것 셋

1. **지도 구 패널에 줄 둘** — 「분양가상한제」(강남·서초·송파·용산만 적용)와 「최근 공고
   n건」. 앞의 것이 규제지역 셋과 처음으로 **값이 갈리는 층**이다. 서울이 전역
   투기과열지구가 된 뒤 지도 세 층이 모두 25구 같은 값이라 지도가 아무것도 안 갈랐다.
2. **본 장 「청약」 절** — 조건 표와 뽑는 방법 표 둘. 워치 줄
   `insights/watch/policy/청약 제도.md` 가 재료다.
3. **상세 페이지** — 권역별 공고 목록(단지명·공급위치·접수일·당첨자발표일·분양가상한제
   적용 여부)과 1순위 해당지역 경쟁률. 어댑터가 열쇠를 받은 뒤에 선다.

## 열쇠 발급

data.go.kr 에서 두 서비스를 활용신청한다 — 15098547(청약홈 분양정보 조회),
15098905(청약접수 경쟁률 및 특별공급 신청현황 조회). 개발단계는 자동승인, 운영단계는
심의승인이라고 두 페이지에 적혀 있다(며칠 걸리는지는 안 적혀 있다). 받은 일반 인증키를
환경변수 `DATA_GO_KR_KEY` 에 넣는다. 게이트웨이는 `api.odcloud.kr` 이다.

## 아직 못 정한 것

- **구 단위 필터가 API 에 있는지 확인 못 했다.** 지역 파라미터가 시·도까지만 내려가는
  것으로 보여, 어댑터는 서울로 받아 공급위치 주소 문자열로 구를 다시 거른다. 주소 표기가
  단지마다 흔들리면 놓치는 공고가 생긴다.
- **경쟁률을 권역 한 수로 접을지.** API 는 주택형×순위×거주코드마다 한 행을 준다.
  평균을 내면 우리가 만든 수가 되므로, 지금은 공고별 1순위 해당지역 값만 그대로 늘어놓는다.
- **예정 공고(입주자모집공고 전 단계)를 어디서 받을지.** 이 API 는 이미 난 공고를 준다.
