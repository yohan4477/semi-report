# 원문 기반 노트 체계 — 원자를 걷어내고 문서 노트로 간다

- 작성 2026-08-09
- 상태: 설계 승인됨, 구현 계획 대기
- 대체 대상: `docs/superpowers/specs/2026-07-30-원자-뷰-인사이트-design.md`

## 왜 바꾸나

원자 체계는 2026-07-30에 「클러스터 9개로 문서 65편을 요약하니 요약의 요약이 됐다」는 문제를 풀려고 만들었다. 문서 원문의 한 줄에서 조건이 붙은 최소 사실 단위를 뽑아 좌표에 매다는 방식이다. 6주 돌려 본 결과는 이렇다.

**얻은 것.** 인사이트 29건과 thesis 3건이 근거를 되짚을 수 있는 상태로 남았다. 문서를 가로지르는 대조로 두 건을 잡았다 — 「60%」가 두 문서에서 서로 다른 것을 센다는 것(check_atoms C9), 그리고 스페이스X가 전력장비 병목을 우회하는 각본이 T-01 판단을 깎는다는 것(crosscheck).

**못 얻은 것.** 6주에 문서 24편, 전체의 29%다. 나머지 71%는 체계 밖에 있다. 그리고 부분 커버리지가 거짓말을 한다 — 2026-08-09에 만든 머스크 추적판이 xAI를 「원자 221일째 공백」으로 표시했는데, 실제로는 xAI 콜로서스 2 전용 클리핑(xAI 언급 107회, 26.9KB)이 원자화 안 된 채 있었을 뿐이다. 회색으로 칠한 것이 현실이 아니라 파이프라인 구멍이었다.

**결정적인 실측.** 같은 날 원문 5편(249KB)을 서브에이전트 한 콜에 통째로 넣어 서술을 쓰게 했더니, 원자 층에 하나도 없던 것이 쏟아졌다 — 솔라리스 합작법인(xAI가 수주잔고 1,700MW의 67% 차지), 사우디 PIF 400억 달러 라운드, 테라팹(월 100만 장 = TSMC 전체의 68%), 우주 데이터센터 실효비용이 지상의 4배, 그리고 발전 용량과 컴퓨트 용량은 다른 숫자라는 것. 원자 27개를 조립한 판보다 압도적으로 읽혔다.

원자 설계의 전제는 「한 콜에 다 못 넣으니 미리 압축해야 한다」였다. 250KB 한 콜이 잘 돌아가면서 그 전제가 무너졌다.

**사용자 실사용.** 원자가 떠받치던 것 중 실제로 여는 것은 ⚛️ 인사이트와 근거 한 장뿐이다. 🏭 제약과 회사(회사 84곳), 검증 대장(55건), 구조 뷰는 만들어 놓고 안 본다.

## 무엇을 만드나 — 3층

```
① 원문      input/clippings/*.md (69편) · content/newsletter/**/*.md (47편)
                                                          116편 · 약 278만 토큰
                    │  문서 1편 = 1콜, 논지를 보존한 채 8:1로 줄인다
                    ▼
② 문서 노트  insights/notes/<yymmdd>-<슬러그>.md
                                                          116장 · 약 15만 토큰
                    │  전부 한 콜에 들어간다 → 교차 작업은 여기서
                    ▼
③ 서술      insights/synth/*.md   판단 노트 (구 인사이트 29건 + thesis 3건)
             insights/tracks/*.md  추적 노트 (주체·기술별 현황)
                    │
                    ▼
             ⚛️ 인사이트와 근거 · 🚀 추적판
```

②가 원자를 대신한다. 원자와 다른 점 셋:

1. **문장을 쪼개지 않는다.** 논증이 살아 있어 「왜 그렇게 말했나」가 남는다. 원자는 조건은 지켰지만 논지를 버렸다.
2. **문서 하나에 노트 하나.** 압축을 두 번 하지 않는다. 2026-07 실패는 65편을 9개 주제로 눌러 담은 것이었고, 이번 노트는 언제나 문서 하나를 가리킨다.
3. **전부 한 콜에 들어간다.** 원자 521줄도 훑을 수는 있었지만 조건만 있고 논지가 없어 어긋남이 잘 안 보였다.

## 문서 노트 형식

`insights/notes/<yymmdd>-<슬러그>.md` — 파일명 규칙은 기존 `insights/atoms/`와 같게 한다.

```markdown
---
source: "input/clippings/....md"
title: 원문 제목
date: 2026-08-07
corpus: semi          # semi | und
lang: en              # en | ko
actors: [스페이스X, 마이크로소프트, APR에너지]
topics: [전력, 데이터센터, 계약]
---

## 이 문서가 주장하는 것
(3~5문장. 문서의 논지. 요약이 아니라 주장이다)

## 수치
- 값 · 조건 · 귀속 (L123)
  … 5~15개. 조건 없는 수치는 적지 않는다

## 저자가 추정이라고 밝힌 것
- … (L456)

## 이 문서가 반박하거나 뒤집는 것
- (있으면. 다른 문서를 명시적으로 반박할 때만)
```

**분량 상한 3KB.** 넘으면 문서를 통째로 다시 읽는 편이 낫다는 신호다.

`actors`·`topics`는 얇은 색인이다. 원자의 `view.actor`처럼 상업적 해석을 담지 않는다 — 이름만 적는다. 나중에 「이 회사를 다룬 문서」를 고를 때 쓴다.

## 인용

서술과 노트 모두 `(라벨 L123)` 형식으로 원문 줄을 가리킨다. 라벨은 frontmatter의 `source`(노트) 또는 `sources` 목록(서술)으로 해석한다.

렌더할 때 GitHub blob의 `#L123`으로 링크한다. 이미 `insights/gen_entity_board.py`에 구현돼 있고 머스크 판에서 62곳이 동작한다.

**라벨 매칭은 부분 일치로 한다.** 사람이 「온사이트 가스 딥다이브」라고 줄여 쓰는데 파일명은 `[251231] AI 랩들은 어떻게…`로 시작한다. 앞머리 일치만 보면 놓친다(머스크 판에서 실제로 7건 놓쳤다).

### 인용 잠금 — `insights/cites.json`

```json
{"input/clippings/foo.md#L123": {"sha1": "ab12…", "seen": "2026-08-09"}}
```

검사기가 처음 볼 때 그 줄의 해시를 기록하고, 이후 실행에서 달라지면 WARN을 낸다. 원문이 갱신되면 그 줄을 인용한 서술을 다시 봐야 한다는 뜻이다. 원자 체계의 C16·C17을 대체하며, 실제로 인용한 줄만 검사하므로 더 싸다.

## 검사기 — `insights/check_notes.py`

| | 규칙 | 등급 |
|---|---|---|
| N1 | frontmatter의 `source`/`sources` 파일이 실재한다 | FAIL |
| N2 | 모든 인용 라벨이 그중 하나로 해석된다 | FAIL |
| N3 | 인용한 줄 번호가 파일 범위 안이다 | FAIL |
| N4 | 인용한 줄의 해시가 `cites.json`과 같다 | WARN |
| N5 | 노트가 3KB를 넘지 않는다 | WARN |
| N6 | 「수치」 절의 항목에 조건과 인용이 둘 다 있다 | FAIL |
| N7 | 서술 문단 중 숫자가 있는데 인용이 없는 것이 없다 | WARN |

`insights/check_prose.py`(P1~P7)는 그대로 쓴다. 긴 문장·번역투·용어 풀이·절 순서 검사는 원자와 무관하고, 문체 게이트는 유지 가치가 있다.

## 교차 인사이트 — 세 방식

노트 층이 서면 원자가 하던 일이 여기로 옮겨온다.

**① 훑기 (수시).** 노트 116장을 한 콜에 넣고 묻는다 — 무엇이 서로 어긋나나, 같은 단위를 다르게 세는 곳이 어디냐, 아무도 안 다룬 구멍이 어디냐. 원자로는 6주에 두 건 나왔던 것이 한 번 돌릴 때마다 목록으로 나온다.

**② 신규 대조 (문서가 들어올 때마다).** 새 노트 + 기존 노트 전부를 한 콜에 넣어 「이게 기존 판단 중 무엇을 깎나」를 받는다. `crosscheck.py`의 STALE 탐지를 대체한다.

**③ 파고들기 (질문 주도).** ①·②에서 걸린 것만 원문 5~10편을 통째로 읽고 서술을 쓴다. 2026-08-09 머스크 추적 노트가 이 단계의 실물이다.

얕게 전부 → 걸린 데만 깊게. 원자는 이 둘을 한 층으로 하려다 둘 다 놓쳤다.

## 마이그레이션

**1. 서술의 참조 치환 (자동, 100%).** 인사이트 29건과 thesis 3건의 `(A-260807b-01)`을 `(파일 L줄)`로 바꾼다. 원자 JSON에 `_path`와 `line`이 있으므로 기계가 전부 변환한다. 사람이 쓴 산문은 한 글자도 안 건드린다.

**2. 원자 → 노트 물려받기.** 원자화된 24편은 「수치」 절을 원자에서 그대로 접어 넣을 수 있다. 다만 「이 문서가 주장하는 것」은 원자에 없으므로 읽기 한 번은 필요하다. 24편은 나머지보다 싸다는 뜻이지 공짜는 아니다.

**3. 노트 생성.** 116편. 서브에이전트 1편당 1콜, 병렬 가능.

**4. 삭제.** 위 셋이 끝나고 검사기가 통과한 뒤에만.

### 단계적 적용

전부를 한 번에 하지 않는다. 순서는 쓸 일이 많은 것부터.

- 1단계 — AI·인프라 변환본 47편 (⚛️와 추적판이 바로 쓴다)
- 2단계 — 클리핑 중 미변환 45편 (xAI 콜로서스 2처럼 체계 밖에 있던 것들)
- 3단계 — 나머지

1단계가 끝나면 ①·② 교차를 돌릴 수 있다. 2단계까지 가면 커버리지 100%다.

## 죽는 것

삭제는 마이그레이션 검증 뒤에 한다. git 이력에는 남는다.

| | 규모 | 사유 |
|---|---|---|
| `insights/atoms/` | 521개 · 24편 | 노트로 대체 |
| `check_atoms.py` | C1~C21 | `check_notes.py`로 대체 |
| `crosscheck.py`·`test_crosscheck.py` | STALE 탐지 | 교차 ②로 대체 |
| `structures.py`·`views/structures.json` | 구조 뷰 | 안 본다 |
| `views/process.json` | 프로세스 7단계 | 좌표 축이 사라진다 |
| `views/actors.json`·`actor_map.json` | 주체 84곳 | `actors:` 태그로 축소 |
| `gen_actormap.py` · 🏭 제약과 회사 | 회사 84곳 | 안 본다 |
| `verify.json` | 검증 대장 55건 | 판정을 원자로만 하게 돼 있었다(C21) |
| `gen_atomview.py`의 ③ 근거 지도 | 스택 10칸·프로세스 7단계 | 안 본다 |

**⚛️의 계층 SVG도 같이 간다.** 2026-08-09 오전에 그린 포함관계 그림이다. 계층을 설명하는 그림 자체는 문서 안에서 계속 쓸 수 있지만, 「어느 칸에 근거가 비었나」라는 커버리지 장치로서는 없어진다.

`gen_atomview.py`는 `gen_insightview.py`로 이름을 바꾸고 ①만 남긴다 — 인사이트 본문 + 인용 링크. ②의 근거 펼침은 문장 옆 각주로 바뀐다.

## 안 하는 것

- **노트에 상업적 해석을 넣지 않는다.** 티커·수혜/피해 판단은 서술에서 한다. 노트는 문서가 말한 것만 담는다.
- **노트를 자동 갱신하지 않는다.** 원문이 바뀌면 N4가 WARN을 내고 사람이 다시 본다.
- **좌표 축을 다시 만들지 않는다.** 스택·프로세스 뷰는 되살리지 않는다. 필요해지면 그때 별도로 설계한다.
- **검증 대장을 노트 기반으로 재건하지 않는다.** 판정 0건이었다. 다시 필요해지면 그때.

## 미결

- **노트 116장을 한 콜에 넣는 게 실제로 되는지 미검증.** 15만 토큰 추정은 문서당 3KB 가정이다. 1단계 47편(약 6만 토큰) 끝난 시점에 실측한다.
- **제3자 코퍼스(`content/understanding/` 46편)를 노트 대상에 넣을지.** 지금은 뺐다. 코퍼스 혼합 금지 규칙(구 C18)을 노트 층에서 어떻게 지킬지 정해야 한다 — `corpus:` 필드는 넣어 뒀다.
- **🏭 제약과 회사를 되살릴지.** 안 본다고 했지만 84곳 매핑은 노동이 들어간 자산이다. 삭제 전에 `views/actor_map.json`만 남겨 둘지 정한다.
