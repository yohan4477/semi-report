# AI Engineer — 주장 흐름 (시간순 한 줄기)

2026-09-08 확정. 산출물은 `대시보드/ai-engineer/주장 흐름.html` 한 장과
그 재료 `insights/views/aie_thread.json`, 조립기 `scratchpad/gen_aie_thread.py`.

## 1. 무엇을 답하는 장인가

AI Engineer 발표 81편은 카드 81장으로 이미 서 있다. 카드는 한 편을 잘 읽게 하지만
**「이 사람이 3개월 전 저 사람 말을 뒤집었다」는 카드 사이에 있어서 어느 카드에도 안
적힌다.** 이 장이 그 자리다.

한 물음만 답한다 — **에이전트를 어떻게 지어야 하는가에 대해, 2025-04부터 지금까지
무슨 말이 나왔고 뒤에 온 사람이 앞사람 말을 밀었나 엇갈렸나 새 물음을 열었나.**

쟁점을 미리 잡아 두지 않는다. 한 번 접었던 설계다 — 쟁점 이름(autonomy·tools·memory…)
을 먼저 세우면 그 서랍에 안 들어가는 발표를 억지로 밀어 넣거나 버리게 된다. 서랍은
우리 것이지 발표자들 것이 아니다. 시간순 한 줄기에 주장을 놓고 걸리는 것만 잇는다.

## 2. 관계는 셋뿐이다

```
동조    앞의 주장을 같은 방향으로 한 걸음 더 밀었다
엇갈림  같은 물음에 반대로 답했다
신규    앞에 없던 물음을 열었다 — rel 이 비었다는 뜻, 따로 안 적는다
```

**「반박」이 아니라 「엇갈림」이다.** 발표자들이 서로 이름을 대고 받아치는 일은 거의
없다. 실제로 있는 것은 같은 물음에 반대로 답한 두 발표뿐이고, 「반박」은 그 자리에
없던 의도를 붙인다. 「보강」처럼 동조와 신규 사이의 중간 이름은 만들지 않는다 —
애매하면 신규다.

## 3. 재료 — `insights/views/aie_thread.json`

한 줄이 주장 하나다. 한 발표가 주장 둘을 내면 줄이 둘이다.

```json
{
  "id": "2026-07-26-microsoft-운전대",
  "talk": "2026-07-26-LLM에게-운전대를-주지-마라",
  "date": "2026-07-26",
  "org": "Microsoft",
  "speaker": "Ornella Bahidika & Joel Allou",
  "claim": "<변환본에 있는 발표자 말 한 줄>",
  "line": 47,
  "rel": [{"to": "2025-08-26-aws-판단은모델에", "kind": "엇갈림"}]
}
```

- `claim` 은 요약이 아니라 `content/aie/<talk>.md` 의 그 줄이다. 우리 말로 다시
  쓰지 않는다 — 다시 쓰는 순간 두 주장이 맞선다는 판정의 근거가 우리 문장이 된다.
- `line` 은 그 md 의 줄 번호. `scripts/check_jsoncite.py` 가 실재하는 줄을
  가리키는지 문다.
- `id` 는 `<date>-<org소문자>-<열쇠말>`. `rel.to` 는 반드시 **자기보다 앞선 날짜**의
  `id` 여야 한다 — 조립기가 검사한다.
- 주장을 못 뽑은 편은 줄을 안 만든다. 「81편이 다 나와야 한다」가 아니다.

## 4. 뽑는 절차 — 두 판

```
1판  발표 한 편 = 주장 1~2줄 (claim·line 만, rel 없음)
     81편 병렬, sonnet 위임. 원문 덩어리로 메인 컨텍스트를 안 채운다
2판  날짜순으로 훑으며 각 주장을 앞선 주장 목록과 맞대 동조·엇갈림·신규 판정
     앞의 것을 다 봐야 하므로 병렬 불가. 판정이 산출물이라 메인이 한다
```

2판의 판정마다 **두 인용을 나란히 남긴다.** 근거 줄 없이 「엇갈림」을 붙이지 않는다.

범위는 81편 전부다. `section` 이 `agent` 가 아닌 편(평가·코딩·검색·인프라)에도 에이전트를
어떻게 지어야 하는가에 답한 대목이 있다 — 섹션으로 미리 자르지 않고 1판이 주장을
찾은 편만 남는다.

## 5. 화면 — `대시보드/ai-engineer/주장 흐름.html`

아카이브 부품(`dash_common`)을 안 쓴다. 카드가 쌓이는 장이 아니라 한 줄기를 위에서
아래로 읽는 장이다. 워치 장과 같은 이유이고, 같은 이유로 **규약을 조립기 안
`check_ui()` 에 적는다** — 규약 없는 장이 되면 다음 사람이 같은 자리를 다시 판다.

```
위 → 아래   2025-04 → 2026-08. 한 줄이 주장 하나
줄 왼쪽     ● 신규  ↑ 동조  ✕ 엇갈림
줄 본문     날짜 · 조직 · 화자 · 주장 한 줄(원문 그대로)
잇기        동조·엇갈림은 대상 줄로 잇는 선. 펴면 두 인용이 나란히
거르기      「신규만」 「엇갈림만」. 조직을 고르면 그 조직 줄만 진하게, 나머지는 옅게
클릭        AI Engineer 대시보드의 그 카드로
```

- **입장을 좌표나 색으로 매기지 않는다.** 두 진영으로 위아래를 가르지도 않는다.
  가름은 우리가 만든 값이다. 대립은 이어 붙은 두 인용을 읽어서 보이게 한다.
- 색은 회색만. 관계 셋은 색이 아니라 기호와 선꼴로 가른다(신규는 선이 없고,
  동조는 실선, 엇갈림은 점선).
- **고립 주장이 많으면 이 장은 목록이 된다.** 걸린 줄은 선과 함께 진하게, 아무 데도
  안 걸린 줄은 옅게 낸다. 옅은 줄이 절반을 넘으면 2판 판정이 게을렀다는 신호다 —
  조립기가 그 비율을 찍는다.
- 2025-08 에 21편이 몰려 있다. 세로 간격은 날짜에 비례시키지 않고 줄 수로 균등하게
  둔다. 날짜는 줄마다 적히므로 뭉침이 정보를 지우지 않는다.

## 6. 조립과 검사

```bash
PYTHONIOENCODING=utf-8 python scratchpad/gen_aie_thread.py
PYTHONIOENCODING=utf-8 python scripts/check_jsoncite.py   # claim 이 그 줄에 있나
PYTHONIOENCODING=utf-8 python insights/check_prose.py     # 대시보드 HTML 산문
PYTHONIOENCODING=utf-8 python scratchpad/check_fig.py     # 배치
```

조립기가 생성 때 스스로 검사하는 것(`check_ui()`):

```
rel.to 가 자기보다 뒤 날짜를 가리키면      FAIL
rel.to 가 없는 id 를 가리키면              FAIL
kind 가 동조·엇갈림 밖이면                 FAIL
claim 이 원문 줄과 다르면                  FAIL (check_jsoncite 와 겹치는 그물)
아무 데도 안 걸린 줄 비율                  찍는다 (FAIL 은 아니다)
```

AI Engineer 대시보드 머리에 이 장 링크 한 줄을 단다. HTML 은 생성물이라 손으로
고치지 않는다.

## 7. 안 하는 것

- 쟁점 서랍(자율·도구·기억…)을 세우지 않는다. §1 의 이유.
- 주장에 점수·좌표·진영을 매기지 않는다.
- 발표 요약을 다시 쓰지 않는다. 요약은 카드가 이미 한다. 이 장은 카드 사이만 본다.
- 81편을 다 채우려 하지 않는다. 주장이 없으면 안 나온다.
