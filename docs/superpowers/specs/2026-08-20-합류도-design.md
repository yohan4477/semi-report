# 합류도 — 주제 하나가 어디로 모이는지를 지도로 세운다

- 작성 2026-08-20
- 상태: 설계 승인됨, 구현 계획 대기
- 대상 파일: `insights/merges.py`(신규) · `insights/gen_insightview.py` · `insights/check_merge.py`(신규) · `scripts/build_all.py`
- 원형: `scratchpad/gen_leesunyeop_dashboard.py`의 `MERGE_SVG`

## 무엇을 만드나

통합 인사이트에 **합류도** 한 겹을 더한다. 한 주제를 두고 「바깥에서 오는 것 → 값을 정하는 곳 → 합류하는 곳」 세 열로 칸을 세운 그림이고, **칸을 누르면 그 칸에 배정된 카드만 펼쳐진다.**

첫 주제는 **AI 자본조달 순환**이고 합류점은 **「컴퓨트 한 단위가 돈을 버나」**다.

```
바깥에서 오는 것        값을 정하는 곳         합류하는 곳
[채권 · 리스 조달]      [배수의 기준선]        ┐
[순환거래 · 백스톱]     [컴퓨트 단가 · 굿풋]   ├→ [컴퓨트 1단위가
[금리 · 조달비용]                              ┘   버는 돈]
```

## 왜 이 형식인가

이선엽 시황 대시보드에서 자리 잡은 형식이다. 그 페이지의 카드 열셋은 전쟁·금리·수급·반도체 넷으로 흩어져 있는데, `MERGE_SVG` 한 장이 「이것들은 따로 노는 주제가 아니라 전부 반도체 실적 하나로 합류한다」를 먼저 보인다. 카드를 읽기 전에 **그 카드가 어느 칸에 서는지**를 알고 들어가게 만드는 장치다.

통합 인사이트에는 이 장치가 없다. 섹션 타일(칩·전력·모델·AI 사업·에너지·금리)은 카드를 **주제별로 나누는** 도구라, 주제를 **가로질러 하나로 모으는** 일은 못 한다. 「AI 투자 회계」 카드와 「GW당 매출」 카드가 같은 사슬의 앞뒤라는 사실이 화면 어디에도 없다.

## 왜 이 합류점인가

「AI 자본조달 순환」 노트는 거의 다 `corpus: third`다 — 채권발행·순환거래·리스·FCF 계열 15편 전부 회계사·미주사에서 왔다. SemiAnalysis 코퍼스(`semi`)에서 이 축에 서는 건 열 편 남짓이다(엔비디아 GPU 백스톱 260706, 메타 컴퓨트 260702, 앤트로픽 3분기 흑자 260708, AWS 베드락 마진 260528, 인텔 유상증자 260611, 스페이스X 10GW 260807, 용량 취소설 반박 260619).

그래서 합류점을 「빅테크 잉여현금흐름」으로 잡으면 **회계사 대시보드의 복제**가 된다. 같은 코퍼스로 같은 결론을 두 장에 쓰는 꼴이다.

SemiAnalysis 코퍼스가 남들과 다른 것은 돈이 실제로 도는 컴퓨트가 됐는지를 **GW·굿풋·토큰 단가**라는 물리·운영 숫자로 잰다는 점이다. 그래서 합류점을 「컴퓨트 한 단위가 돈을 버나」로 둔다. 바깥 칸은 third 코퍼스가 채우고, 합류 칸은 semi 코퍼스가 채운다 — 두 코퍼스가 한 사슬의 앞뒤로 붙는다.

## 재료 — 새로 쓸 산문은 없다

칸에 설 카드가 이미 있다.

| 지도 칸 | 배정할 글의 headline |
|---|---|
| 바깥 — 채권·리스 조달 | 빅테크는 쓴 돈만큼 장부에 담지 않는다 · 같은 보증 계약을 한쪽은 다리로, 한쪽은 부풀림으로 센다 |
| 바깥 — 순환거래·백스톱 | 같은 날 메타는 코어위브의 고객이자 경쟁자가 됐다 |
| 바깥 — 금리·조달비용 | 금리와 환율을 국내 수급으로 설명하는 방식이 깨졌다 |
| 값 — 배수의 기준선 | 같은 칩을 두고 2배와 100배가 같이 나온다 · 앤트로픽은 흑자, 오픈AI는 매출만큼 적자 |
| 값 — 컴퓨트 단가·굿풋 | AI 값은 내려가는데 파는 쪽 마진은 오른다 · 수혜 엔비디아·AMD, 위기 세레브라스·Groq: 소프트웨어가 1.9배 |
| 합류 — 컴퓨트 1단위가 버는 돈 | 같은 1GW인데 매출이 열 배 다르다 · 사 오는 과제가 병목이라더니 산 GPU가 74% 놀았다 |

배정은 headline 문자열로 가리킨다. 카드 본문·frontmatter는 한 글자도 안 고친다.

## 왜 읽기 층인가 — 접근 셋 중 하나

**A. 읽기 층(채택).** 지도 정의를 `insights/merges.py` 한 파일에 두고, `gen_insightview.py`가 그것을 읽어 SVG를 그린다. 카드 풀 위에 얹힌 뷰다.

**B. frontmatter 확장(기각).** 각 cross/brief에 `merge:` 필드를 넣으면 단일 출처가 되지만 글 41편을 전부 손대야 한다. 그리고 한 카드가 여러 지도에 서면 다중값이 필요해져 frontmatter가 지저분해진다.

**C. 합류도 전용 카드 신규 집필(기각).** 기존 카드와 내용이 겹친다. `insight-review`가 막을 종류의 중복이다.

A를 고른 결정적 이유는 **통합 비용**이다. 주제를 더하는 일이 dict 하나를 더 쓰는 일로 끝난다. 카드는 여러 지도에 겹쳐 서도 된다 — 「메모리」 지도와 「자본조달」 지도가 `배수의 기준선`을 공유하는 것이 자연스럽다. 겹침 금지는 **한 지도 안에서만** 건다.

## 자료구조

```python
# insights/merges.py
# 주제 하나 = dict 하나. 칸은 headline 문자열로 글을 가리킨다.
MERGES = [{
  'id': 'capital',
  'title': 'AI 자본조달 순환',
  'lede': '조달한 돈이 실제로 도는 컴퓨트가 됐는지를 GW·굿풋·토큰 단가로 되짚는다',
  'outer': [('채권 · 리스 조달',
             ['빅테크는 쓴 돈만큼 장부에 담지 않는다',
              '같은 보증 계약을 한쪽은 다리로, 한쪽은 부풀림으로 센다']),
            ('순환거래 · 백스톱',
             ['같은 날 메타는 코어위브의 고객이자 경쟁자가 됐다']),
            ('금리 · 조달비용',
             ['금리와 환율을 국내 수급으로 설명하는 방식이 깨졌다'])],
  'price': [('배수의 기준선',
             ['같은 칩을 두고 2배와 100배가 같이 나온다',
              '앤트로픽은 흑자, 오픈AI는 매출만큼 적자']),
            ('컴퓨트 단가 · 굿풋',
             ['AI 값은 내려가는데 파는 쪽 마진은 오른다',
              '수혜 엔비디아·AMD, 위기 세레브라스·Groq: 소프트웨어가 1.9배'])],
  'merge':  ('컴퓨트 1단위가 버는 돈',
             ['같은 1GW인데 매출이 열 배 다르다',
              '사 오는 과제가 병목이라더니 산 GPU가 74% 놀았다']),
}]
```

열은 셋으로 고정한다(`outer` · `price` · `merge`). 네 번째 열을 열면 그림이 지도가 아니라 조직도가 된다 — 이선엽판이 세 열로 버틴 이유가 그것이다.

`merge`는 칸 하나뿐이다. 합류점이 둘이면 그것은 주제가 둘이라는 뜻이므로 dict를 나눈다.

## 화면

`course()` 아래, 섹션 타일 **위**에 접힌 `<details class="mrg">` 한 겹을 세운다. 열면 주제 탭(지금은 하나)과 SVG가 나온다.

- **접힌 상태가 기본이다.** 첫 화면은 여전히 섹션 타일이다 — 대시보드 UI 규약(`CLAUDE.md`)을 깨지 않는다.
- SVG 칸을 누르면 타일이 숨고 그 칸에 배정된 카드만 남는다. 복귀는 기존 「← 주제 다시 고르기」 버튼(`.sback`)을 그대로 쓴다.
- 칸 클릭 필터는 섹션 타일 필터와 **같은 자리를 쓴다.** 둘이 동시에 걸리면 나중 것이 앞의 것을 푼다.

SVG는 `MERGE_SVG`처럼 문자열을 손으로 적지 않고 `MERGES` dict에서 칸 개수에 맞춰 좌표를 계산해 그린다. 주제를 더할 때 좌표를 다시 재는 일이 없어야 한다.

## 이선엽판에서 안 가져오는 것

**카드별 시간 흐름(`flow_svg`)은 뺀다.** 저쪽은 매일 쓰는 시황이라 「언제 무슨 말을 했나」가 본체이고, 그래서 카드마다 정거장 다섯 개짜리 가로선이 맨 앞에 선다. 통합 인사이트의 카드는 문서를 가로지른 판단이라 날짜 축이 약하다. 이미 `period()`가 인용한 원문의 발행일 범위를 카드 겉면에 박고 있다.

없는 시계열을 억지로 찍으면 카드가 실제보다 시간 순서를 가진 것처럼 읽힌다.

## 검사

`insights/check_merge.py`를 새로 만들고 `build_all.py`의 `CHECK`에 등록한다(생성기가 아니라 검사기다).

1. 칸에 적힌 headline이 실제 글에 있나 — `all_headlines()` 대조. 못 가리키면 FAIL
2. 한 지도 안에서 같은 글이 두 칸에 배정됐나 — FAIL
3. `merge` 칸이 비었나 — FAIL
4. `outer`·`price` 칸이 하나도 없나 — FAIL

`gen_insightview.py` 쪽에서도 생성 중에 1번을 assert로 다시 막는다. 이선엽판 `_attach_flows()`가 조각 하나가 카드 하나를 못 가리키면 생성을 멈추는 것과 같은 방식이다 — 검사기를 안 돌리고 푸시하는 경로를 남기지 않는다.

## 나중 통합

`MERGES`에 dict를 더하면 주제 탭이 는다. 다음 후보는 이 순서다.

1. **메모리** — 바깥(HBM 수요·수출통제·금리) → 값(고정가·설비투자 규율) → 합류(SK하이닉스·삼성전자 실적)
2. **데이터센터 전력** — 바깥(용량시장·가스터빈 리드타임·용수) → 값(전력 단가·계통 접속 대기) → 합류(준공 속도)
3. **추론 경제성** — 합류점이 회사 하나로 안 모이고 칩 여럿으로 갈라진다. 이 형식에 안 맞을 수 있어 마지막에 검토한다

## 범위 밖

- SemiAnalysis 대시보드(`대시보드/SemiAnalysis 대시보드.html`)는 손편집 페이지다. 여기에 합류도를 끼우지 않는다 — 생성물과 손편집이 섞인다
- 이선엽 시황 대시보드의 `MERGE_SVG`는 그대로 둔다. 공용 부품으로 뽑는 일은 지도가 셋 이상 생긴 뒤에 판단한다
- 카드 본문·frontmatter 수정 없음
