# 축 검토기 — 이미 만든 카드를 다른 기준으로 다시 세워 본다

대시보드 열두 장에 카드 368장이 서 있다. 각 카드가 어느 자리에 서는지는 `section` 하나로 정해져 있고, 그 배치는 손으로 유지한다. 이 문서는 **같은 카드를 다른 기준으로 다시 나눠 보고 그때 무엇이 겹치고 무엇이 비는지 짚는 도구**를 설계한다.

읽기 전용이다. 카드를 고치지 않는다.

## 무엇을 만드나

물음 하나를 받아 축을 세우고, 카드 368장을 그 축의 칸에 배치한 뒤, 겹침과 빈칸과 쏠림을 숫자로 보고한다. 축은 저장하지 않는다 — 매번 새로 세우고 보고서만 남긴다.

```
$ python scripts/axis_review.py 부동산 --cut 지역
부동산 대시보드 · 카드 22장
  축 [지역] 나무 — 서울 / 경기 / 인천 / 지방
    겹침 2 · 빈칸 1 · 잔여 5장(23%)
    빈칸  인천 — 수도권 셋 중 하나가 비었다
    잔여  「기타」 5장이 어느 칸에도 안 들어갔다
```

## 왜 지금인가

**섹션이 이미 축이고, 그 축은 고정돼 있다.** `dash_common.sections()`가 카드를 `section`으로 묶는다. 그것이 화면 배치이자 유일한 분해다. 대시보드마다 손으로 정하고, 한번 정하면 카드가 거기 묶인다. 다른 기준으로 보려면 사람이 머리로 다시 세워야 한다.

**카드는 이미 자료다.** `CARDS` 리스트에 dict으로 산다. HTML을 파싱할 필요가 없다.

```
회계사 120 · 미주사 61 · 수도리무브 35 · 산업/시장 32 · 계보 30 · 부동산 22
건강 20 · 언더프리미엄 14 · 이선엽 13 · 모델 가이드 10 · Epoch 10 · 용어 1
```

**구조 점검이 이미 둘 있는데 둘 다 규약만 본다.** `check_labels()`는 카드 라벨이 원문에 없는 회사를 달았는지 보고, `check_ui()`는 화면 규약을 본다. 배치가 **분해로서 성립하는지**는 아무도 안 본다.

**손 라벨링은 이미 한 번 실패했다.** 노트 349장 중 `cell:`을 단 것이 0장이고, `topics` 1,023종 중 799종이 한 번만 쓰였다. 그러니 이 도구는 라벨을 요구하지 않는다.

## 원시 단위는 형이 아니라 축이다

```
축(cut)   항목을 서로 다른 칸으로 보내는 함수. 기준 하나
형(shape) 그 칸들 사이의 관계
```

**형은 고르는 것이 아니라 칸에서 읽힌다.** 축을 정하면 형이 따라 나온다.

| 칸들이 가진 관계 | 형 |
|---|---|
| 없음 | 목록 |
| 순서값(날짜·단계) | 선 |
| 포함 | 나무 |
| A의 출력이 B의 입력 | 사슬 |
| 연산자 | 수식 |
| 마지막에서 처음으로 되먹임 | 고리 |

「시간 흐름을 보여 달라」는 축을 날짜로 잡는다. 칸이 순서값을 가지니 형은 선이다. 「밸류체인을 보여 달라」는 축을 공정 단계로 잡는다. 칸 사이가 출력에서 입력으로 이어지니 형은 사슬이다. **매핑을 새로 더하지 않고 떨어진다.**

물음에 형을 매핑한 표를 두지 않는다. 그 표를 두는 순간 표에 없는 물음이 막힌다.

## 하네스는 축을 갖지 않는다

축 목록을 저장소가 가지면 굳는다. `insights/axes.py`의 `AXES = [...]` 상수 리스트가 그 형태다.

```
축은 매번 물음에서 새로 제안된다     ← 판단. 메인 세션이 쓴다
하네스는 제안된 축을 검사만 한다      ← 결정적. 겹침·빈칸·잔여·불균형을 센다
```

자유는 제안 쪽에, 규율은 검사 쪽에 둔다. 아무 축이나 지어낼 수 있지만 나쁜 축은 검사기가 숫자로 깐다.

컨설턴트가 쓰는 축 갈래(시간·구성·공정·행위자·연산·대립·정도)는 제안을 돕는 힌트이지 스키마가 아니다. 저장소 코드가 그 목록에 의존하지 않는다.

## 축은 파일로 저장하지 않는다

카드가 자기 칸을 선언하면 그 카드가 그 분해에 묶인다. 둘째 축을 세우려면 선언을 하나 더 달아야 하고, 열째 축이면 열 개다. 그래서 아무도 안 단다 — `cell:` 0장이 그 증거다.

```
지금  카드 ──선언 section──> 배치           축이 늘면 카드를 다시 라벨링한다
바꿈  카드 ──이미 가진 사실──> [축 함수] ──> 배치   축이 늘어도 카드는 그대로다
```

카드가 이미 가진 것으로 배치를 계산한다 — `title`·`oneliner`·`points`·`post`·`links`·`meta`. 축 하나는 **칸 이름과 그 칸을 알아보는 낱말**로 정의되고, 그 정의는 명령줄이나 작은 JSON 한 장으로 그때그때 준다. 저장소에 축 대장을 두지 않는다.

## 겹침의 뜻을 바로잡는다

`c['also']`는 한 카드가 여러 섹션에 서는 것을 **일부러 허용한다.** 마이크론과 SK하이닉스를 같이 다룬 글은 두 회사 어느 쪽을 눌러도 나와야 한다.

그러니 「한 카드가 두 칸에 섰다」를 그대로 위반으로 세면 `also`가 전부 걸린다. 갈라야 한다.

| | 뜻 | 판정 |
|---|---|---|
| 선언된 다중 배치 | `also`로 밝힌 것 | 위반 아님 |
| 계산된 다중 배치 | 축 함수가 한 카드를 두 칸으로 보냄 | **겹침** |

겹침은 축이 배타적이지 않다는 신호다 — 칸 이름이 서로를 포함하거나(「재건축」과 「규제」), 낱말이 겹친다.

## 무엇을 세는가

```
겹침    한 카드가 계산으로 두 칸 이상에 들어갔다
빈칸    축이 세운 칸인데 카드가 하나도 안 들어갔다
잔여    어느 칸에도 안 들어간 카드. 전체의 20%를 넘으면 축이 잘못 잡힌 것이다
불균형  가장 큰 칸이 가장 작은 칸의 다섯 배를 넘는다
```

**완벽한 MECE를 강제하지 않는다.** 넷 다 개수로 보고만 하고 막지 않는다. 읽기 전용이라 막을 것도 없다. 숫자를 줄일지는 사람이 정한다.

빈칸이 제일 값어치 있다. 「이 셋을 다뤘으면 넷째가 있어야 한다」가 거기서 나온다. 다만 기계는 빈칸이 **아직 안 쓴 것인지 원래 없는 것인지** 모른다. 그 판단은 사람 몫이라고 보고서에 적는다.

## 보고서에 배치를 함께 적는다

축을 저장하지 않으니 배치도 저장되지 않는다. 그래서 배치를 안 적으면 **같은 보고서를 다시 만들 수 없다.**

```
축 정의   칸 이름과 낱말, 그대로
배치      카드 제목 → 들어간 칸. 368장 전부
못 넣은 것 잔여로 빠진 카드 제목
잰 때      대시보드 생성기 파일의 해시
```

마지막 줄이 있어야 「이 보고서는 카드 22장일 때 것이다」가 드러난다.

## 자료구조

```
scripts/axis_lib.py       카드 적재와 배치 계산. 순수 함수
scripts/axis_review.py    CLI. 읽기 전용
insights/test_axis_lib.py 테스트
```

카드 적재는 생성기 모듈을 import해 `CARDS`를 읽는다. HTML을 파싱하지 않는다 — 생성물을 되읽으면 원본이 바뀔 때 어긋난다.

축 정의 한 장:

```json
{
  "name": "지역",
  "shape": "나무",
  "cells": [
    {"id": "서울", "words": ["서울", "강남", "송파", "마포"]},
    {"id": "경기", "words": ["경기", "성남", "분당", "수원"]},
    {"id": "인천", "words": ["인천", "송도"]},
    {"id": "지방", "words": ["부산", "대구", "광주", "대전"]}
  ]
}
```

`shape`는 사람이 적지 않는다 — 칸 사이 관계에서 읽어 낸다. 위 예의 `shape`는 도구가 채운 값이다.

## 안 하는 것

- **카드를 고치지 않는다.** 구멍을 짚기만 하고 빠진 카드를 새로 쓰지 않는다. 본문 집필은 판단이고 `insight-review` 스킬의 몫이다
- **축을 저장소에 쌓지 않는다.** 축 대장을 두면 굳는다
- **물음에 형을 매핑한 표를 두지 않는다.** 표에 없는 물음이 막힌다
- **완벽한 MECE를 강제하지 않는다.** 넷 다 보고만 한다
- **`also`를 겹침으로 세지 않는다.** 그건 선언된 다중 배치다
- **HTML을 파싱하지 않는다.** 카드는 `CARDS` dict에서 읽는다
- **`CARDS`를 안 쓰는 생성기 셋(aie·mer·undreport)은 이번 범위가 아니다.** 꼴이 달라 따로 본다
- **`check_labels`·`check_ui`가 보는 것을 다시 안 본다.** 라벨 규칙과 화면 규약은 이미 그 둘이 막는다
- **개체 색인에 기대지 않는다.** 축 검토기는 카드 368장을 읽지 원문 129,490줄을 읽지 않는다. 색인은 나중에 이 도구를 낫게 하지 전제 조건이 아니다
