# 포트폴리오 워치 대시보드 — 설계

- 날짜: 2026-08-31
- 상태: 1~5단계 구현됨 (스키마 · 화면 · 검사기 · 어댑터 둘 · 실행기). 에이전트는 아직

## 만들다 바뀐 것

화면을 먼저 세운 덕에 설계의 결함 셋이 구현 중에 드러났다. 아래 본문은 **고친 뒤**의 것이고,
무엇이 어떻게 바뀌었는지만 여기 남긴다.

| 무엇 | 설계 | 실물 | 왜 |
|---|---|---|---|
| 트리거 갈래 | 「값이 조건을 넘는다」 하나 | `값` · `사건` 둘 | 삼성전자 HBM 공급 계약 공표는 값이 아니라 사건이다. 어댑터는 값 줄만 채운다 |
| W1 사전 | `actor_alias.json` 정본 | 종목은 `actor_alias`, 권역은 새 `watch/_areas.json` | `actor_alias` 는 회사 사전이라 권역이 들어갈 자리가 없다 |
| W6 | 트리거 `src` 가 실재하나 | 절 넷이 서 있나 (+ W7 경로 실재) | 트리거 표를 네 열로 줄이며 `src` 를 뺐다. 출처는 metric JSON 이 들고 온다 |
| 트리거 위치 | frontmatter | 본문 마크다운 표 | `notes_lib.parse_front` 가 평평한 key:value 만 읽는다. 파일이 카드와 같은 꼴로 읽히는 이점도 있다 |
| 어댑터 계약 | 한 시점 값만 | `series`·`unit` 을 더함 | 트렌드는 시계열이라 한 점으로는 선을 못 긋는다. 같은 metric 안에 둬 「지금 값」이 시계열의 마지막 점이 되게 했다 |
| 도해 재료 | (설계에 없음) | 줄이 `context` 로 밝힌 것만 | 처음엔 metric 전부를 내줬더니 같은 대상을 다른 물음으로 보는 줄들이 전부 같은 그림을 그렸다 |
| 조건 | 사람이 읽는 문장 | 기계가 읽는 꼴을 정함 | 「지금 걸렸나」가 카드 산문에 손으로 적혀 값이 바뀌어도 안 바뀌었다. 못 읽는 꼴은 「사람 판정」으로 남긴다 |
| 실행기 | (설계에 없음) | `insights/watch_fetch.py` | `_metrics` 를 다시 만드는 방법이 코드에 없고 사람 기억에만 있었다 |
| 종목 원천 | `facts.json` 하나 | 꼴이 둘 | 삼성전자는 `fundamentals.json`(분기·억원)이고 미국 6종목은 `facts.json`(연·SEC)이다 |
| W3 열쇠 꼴 | `[a-z][a-z0-9_]*` | 한글을 연다 | 구마다 값을 따로 받는 설계라 열쇠에 구 이름이 들어간다(`sale_idx_강남구`) |

W2 는 세우자마자 **내가 쓴 조건 셋을 물었다** — 「기존 밴드 하단 이탈」·「전분기 대비 하향」·
「정상 구간 복귀」에 잴 수 있는 수가 없었다. 자기 이력 대비 상대값으로 고쳤다.
- 산출물: `대시보드/포트폴리오 워치.html` (공개 슬러그 `watch`)

## 물음

부동산과 주식을 한 화면에서 「무엇을 왜 보고 있고, 무엇이 일어나면 판단이 바뀌나」로
관리한다. 보유 자산이 아니다 — 손익·비중·현금흐름은 이 장이 다루지 않는다.

## 각도

- 무엇을 담나 — 워치리스트(보유 아님, 예측 대장 아님)
- 대상 단위 — 부동산 권역 · 주식 티커
- 굴리는 힘 — 수치 자동 · 판단 수동
- 쪼개는 축 — 역할(뼈대) × 자산군(어댑터)

## 1. 데이터 모델

### ① 워치 줄은 무엇으로 되어 있나

`insights/watch/<kind>/<슬러그>.md`. 기존 노트와 같은 frontmatter 결이다.

```yaml
kind: realestate            # realestate | equity
target: 강남 3구            # insights/actor_alias.json 정본
opened: 2026-08-31          # 언제부터 보나
why: 공급 절벽이 2027 에 풀리는지가 이 권역 가격의 유일한 변수다
triggers:
  - watch: 입주물량
    cond: 2027년 입주 1.5만호 초과
    src: insights/notes/260812-수도권-공급.md
metrics: [jeonse_ratio, supply_2027]
checked: 2026-08-31         # 마지막 사람 확인
```

본문은 「왜 보나」 산문 몇 줄과 근거 노트 링크.

### ② 왜 수치를 딴 파일에 두나

`insights/watch/_metrics/<kind>/<슬러그>.json` 은 어댑터가 통째로 덮어쓴다.
사람은 안 건드린다. 한 파일에 섞으면 둘 중 하나가 벌어진다 —
스크립트가 사람 글을 날리거나, 사람이 수치를 손으로 고쳐 원천과 어긋난다.
「수치 자동 + 판단 수동」은 파일이 갈려야만 성립한다.

## 2. 어댑터

### ③ 부동산과 주식이 실제로 갈리는 데는 어디인가

| | 공유 | 자산군마다 |
|---|---|---|
| 스키마 | 워치 줄·카드 부품 `card_lib` | — |
| 조립 | `dash_common.render()` | — |
| 검사 | 검사기 열넷 + `check_watch` | — |
| 문체·구조 | CLAUDE.md 규칙 | — |
| 집필 | 메인 세션 | — |
| 수치 원천 | — | 주식 `facts.json`·`_multiples.json` / 부동산 실거래가·입주물량 |
| 적정한가 재는 법 | — | 멀티플 / 전세가율·공급 |
| 대상 사전 | — | 티커 / 권역명 |

갈리는 자리가 아래 세 줄뿐이라, 에이전트를 자산군으로 가르지 않고 **어댑터 파일 두 개**로만 가른다.

```
insights/watch/adapters/equity.py
insights/watch/adapters/realestate.py
```

계약:

```python
fetch(target) -> {metric_key: {"value": ..., "as_of": "2026-08",
                               "kind": "공표|추정", "src": ...}}
```

`as_of`·`kind` 를 계약에 박는다. 값에 「언제 것 · 성격」을 붙이는 것은 이 저장소의 필수
규칙인데, 표를 만들 때 붙이면 늦는다. 어댑터가 안 주면 표를 못 만들게 한다.

## 3. 화면

### ④ 카드 한 장에 무엇이 어느 자리에 서나

- 파일: `대시보드/포트폴리오 워치.html`
- 생성기: `scratchpad/gen_watch_dashboard.py` — `dash_common.render()` 를 반드시 거친다
- `scripts/gen_site.py` 의 `PAGES` 에 슬러그 `watch` 로 등록, 잠그지 않는다
- 첫 화면은 섹션 타일 둘 — 🏠 권역 · 📈 종목 (UI 규약, 관문 버튼 금지)

카드는 `card_lib` 스키마를 그대로 쓴다. 자리만 정한다.

| 자리 | 내용 |
|---|---|
| `verdict` | 지금 판단 한 문장 |
| `lead_table` | 트리거 표 — 무엇 · 지금 값 · 조건 · 언제 것 · 성격 |
| `points` | 왜 보나 |
| `clash` | 반대 근거 |
| `figs` | 도해 (새 카드 필수 규칙) |

트리거 표가 `lead_table` 로 맨 위에 서는 이유 — 워치리스트에서 먼저 알아야 할 것은
근거가 아니라 「지금 조건에 걸렸나」다.

## 4. 에이전트 계약

### ⑤ 무엇을 위임하고 무엇을 메인이 쓰나

| 에이전트 | 모델 | 하는 일 | 금지 |
|---|---|---|---|
| `watch-fetch` | haiku | 어댑터 돌려 `_metrics/` 갱신 | 산문·판단 |
| `watch-digest` | sonnet | 원문 1편 읽고 「어느 워치 줄의 어느 트리거를 건드리나」만 뱉는다 | 카드 본문 집필 |
| 메인 세션 | — | `why`·트리거 조건·판단 집필 | 위임 |

`watch-digest` 의 존재 이유는 토큰이 아니라 **메인 컨텍스트에 원문 덩어리를 안 들이는 것**이다.

## 5. 검사기

### ⑥ 무엇이 새어 나갈 수 있나

`insights/check_watch.py` 를 새로 세운다.

| 규칙 | 무는 것 | 등급 |
|---|---|---|
| W1 | 종목은 `actor_alias.json` 정본인가·`ticker` 가 있나 / 권역은 `watch/_areas.json` 에 있나 | FAIL |
| W2 | 값 트리거 `cond` 에 잴 수 있는 수가 있나 (「오르면」만 있으면 걸린다). 사건 트리거는 면제 | FAIL |
| W3 | 값 트리거에 metric 키가 있나 · 사건 트리거에 키가 안 붙었나 | FAIL |
| W4 | metric 마다 `as_of`·`kind` 가 있나 | FAIL |
| W5 | `checked` 가 90일 넘었나 | WARN |
| W6 | 절 넷(지금 판단·트리거·왜 보나·반대 근거)이 서 있나 | FAIL |
| W7 | 본문이 가리키는 경로가 실재하나 | FAIL |
| W8 | 이 조건이 이력에서 몇 번 걸렸나 | 늘 걸림·닿을 수 없는 문턱은 FAIL, 나머지는 WARN |
| W9 | 값 트리거의 열쇠를 어댑터가 실제로 내나 | FAIL |
| W10 | 지금 값이 series 마지막 점과 같나 · 때가 순서대로인가 · as_of 가 갈렸나 | FAIL / WARN |
| W11 | (갈래·대상·관점)이 유일한가 | FAIL |

기존 게이트도 그대로 탄다 — `check_prose` 가 `대시보드/*.html` 을 보므로 문체 규칙이 걸린다.

규칙을 세울 때는 결함을 일부러 넣어 무는지 먼저 본다. `check_watch.py --selftest` 가 그
자리다 — 규칙마다 걸려야 할 줄과 걸리면 안 되는 줄을 넣고 실제로 그렇게 되는지 센다.
지금 여섯 가지를 물고 전부 통과한다.

## 6. 만드는 순서

### ⑦ 어느 것부터 만드나

화면을 먼저 보고 고치자는 판단이 들어와 4번을 앞으로 당겼다.

| | | 상태 |
|---|---|---|
| 1 | `gen_watch_dashboard.py` + `gen_site.py` PAGES 등록 | 됨 |
| 2 | 스키마 확정 + 손으로 쓴 워치 줄 셋 (주식 2 · 부동산 1) | 됨 |
| 3 | `check_watch.py` — 그 셋을 물게 | 됨 (W1~W7 · selftest 6) |
| 4 | `adapters/equity.py` — 기존 밸류에이션 자료 재활용이라 키가 필요 없다 | 됨 (원천 꼴 둘) |
| 5 | `adapters/realestate.py` — 값 원천을 새로 뚫어야 한다. 여기가 제일 무겁다 | 됨 (지수·전세가율·수급·중위가) |
| 6 | `watch_fetch.py` — 다시 받는 방법을 코드로 | 됨 |
| 7 | W8~W11 — 문턱이 신호인지를 이력으로 잰다 | 됨 |
| 8 | 에이전트 둘 (`watch-fetch`·`watch-digest`) | **안 만들기로 했다** (아래) |

### 에이전트를 안 만든 이유

2026-09-01 에 세 관점(부동산 전문가·서비스 기획자·엔지니어)으로 한 번 비평해 보고 정했다.
검사기 열넷이 전부 FAIL 0 인 상태에서 55건이 나왔는데, 그중 상시 역할이라야 잡히는 것이
하나도 없었다 — 기계가 잴 수 있는 것은 규칙(W8~W11)으로, 매번 물어야 하는 것은 스킬로,
나머지는 그냥 고치면 되는 것이었다.

일회성 3관점 리뷰는 남긴다. 큰 것을 세운 뒤 한 번 도는 것은 값이 있었다.

각 단계가 의미 단위다 — 끝날 때마다 커밋·푸시한다.

## 7. 한계

### ⑧ 이 설계가 정하지 않은 것

- ~~부동산 수치 원천 미정~~ → 정해졌다. 한국부동산원 R-ONE Open API 의 월간 매매·전세
  가격지수(아파트)를 쓴다. 서울은 구 단위 코드가 있어 권역을 구로 쪼개 받는다.
  인증키는 reb.or.kr 에서 로그인 후 즉시 발급되고 환경변수 `REB_API_KEY` 로 읽는다
- **전세가율과 입주물량은 아직 못 채운다.** 전세가율은 전세지수를 매매지수로 나눈 것이
  아니다 — 둘 다 기준시점 100 인 지수라 나눈 값에 뜻이 없다. 별도 통계를 찾아야 한다.
  입주물량은 API 가 없어 정보공개청구(open.go.kr) 아니면 수기다
- **실거래가는 안 붙였다.** 개별 거래를 권역으로 집계하려면 면적·층 보정이 필요하고,
  집계하는 순간 성격이 공표치에서 추정치로 바뀐다. 지수와 같은 표에 세우지 않는다
- **트리거가 걸렸을 때 알리는 길이 없다.** 사람이 열어 봐야 안다. 알림·cron 은 다음 판
- 보유·손익·비중은 이 장이 안 다룬다. 나중에 붙이려면 워치 줄에 보유 칸을 더하는 것이
  아니라 층을 하나 더 세운다 (워치 → 보유 → 채점)
- ~~`facts.json` 키 목록 미확인~~ → 확인했다. 지어 둔 이름(`dc_rev_yoy` 등)은 전부 걷고
  실재하는 것으로 바꿨다(`revenue_yoy`·`gross_margin`·`op_margin`)
- **종목은 주가 이력이 없다.** 두 원천 다 그 시점 스냅숏이라 주가·선행배수에 시계열이
  없다. 그래서 선행배수는 값이 아니라 사건으로 걸었다
- **문턱이 아직 자리표시다.** W8 이 재 준 잦기를 보고 사람이 정할 자리다. 구마다
  변동폭이 크게 달라 한 꼴을 다 걸 수 없다
- **트리거 조건의 문턱값은 사람이 정할 것이다.** 지금 적힌 「최근 3년 중앙값 대비 20% 하회」
  같은 수는 W2 를 통과시키려고 세운 자리표시이지 투자 판단이 아니다
