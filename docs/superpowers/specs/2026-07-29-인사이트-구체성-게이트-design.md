# 인사이트 구체성 게이트 — 설계

작성일: 2026-07-29

## 문제

통합 인사이트 문장이 일반론에 머문다. 근거는 충분한데 결과물에 안 실린다.

측정(2026-07-29, `insights/clusters/*.md` 본문의 불릿·문단 기준):

| 클러스터 | 문장 | 숫자 포함 | 날짜 앵커 |
|---|---|---|---|
| 컴퓨트 | 12 | 91% | 8% |
| P-전력 | 11 | 90% | 0% |
| A-이란전쟁 | 13 | 76% | 0% |
| 메모리 | 10 | 60% | 0% |
| AI모델 | 11 | 54% | 0% |
| B-원유의존 | 13 | 53% | 0% |
| D-AI전력 | 13 | 46% | 0% |
| C-재생비용 | 14 | 28% | 0% |
| 냉각 | 8 | 25% | 0% |

원인:

1. **검사 대상이 아니다.** `insights/validate_insights.py`(28줄)는 provenance ID 존재만 확인한다. 문장 품질 규칙은 0개.
2. **압축비 13:1에 생존 규칙이 없다.** 코퍼스 사실 1,424행(`insights/facts.py` 산출) → 인사이트 105문장. 규칙이 없으면 요약은 추상 쪽으로 수렴한다. 추상 문장은 개별 소스로 반박당하지 않아 "안전"하고, 구체 문장은 틀릴 위험이 있어 깎여나간다.
3. **사실 표가 산문 옆에 있고 안에 없다.** 대시보드 헤드라인은 여전히 산문이고 숫자는 접힌 표 안이다.
4. **앵커가 없어 반증이 불가능하다.** "언제 시점, 어느 문서의 주장인가"가 문장에 없으면 일반론과 구별할 방법이 없다.

## 근거 계층 — 무엇을 "코퍼스"로 볼 것인가

측정(2026-07-29, 근거 문서 65편):

| 층 | 분량 | 정체 |
|---|---|---|
| 대장 (`대장/숫자 대장.md`) | 548행 | 사람이 표준화한 지표. 36/65편만 등재 |
| `insights/facts.py` | 1,424행 | 문서의 `📌 핵심` 블록 + 언더스탠딩 `## 주요 숫자` |
| 코퍼스 본문 | 4,213줄 | 단위 붙은 수치가 실제로 있는 줄(표 199행 포함) |

`facts.py`는 코퍼스 수치의 **34%**만 본다. 나머지 2,789줄은 본문 산문·TCO 표·mermaid 안에 있다. 게다가 `📌 핵심`은 문서 저자가 이미 한 번 추상화한 층이라, 그것만 근거로 삼으면 "요약의 요약" 실패를 한 단계 아래에서 반복한다 — 지금 클러스터가 일반론이 된 경로와 같다.

따라서 근거의 기준은 **코퍼스 본문**이고, `facts.py`는 그 색인으로만 쓴다.

## 목표

- 9개 클러스터 본문 전체를 규칙에 맞게 재작성
- 규칙을 검사기로 고정해 이후 신규·수정 클러스터에도 자동 적용
- 목표 지표: **숫자 포함 ≥80%**, **앵커 100%**, **클러스터당 미검증 항목 ≥1**

비목표: 대시보드·지도 레이아웃 변경, 클러스터 분류 체계 변경, 신규 클러스터 생성.

## 문장 규칙

`insights/clusters/*.md` 본문 불릿·논지에 적용한다.

| # | 규칙 | 판정 |
|---|---|---|
| R1 | 진단·이견·미지 블록의 각 불릿에 수치 1개 이상 | 정규식 `\d` 매치 |
| R2 | 각 불릿에 앵커 1개 이상. 형식 `(문서약칭 YY-MM-DD)` | 정규식 `\(\S[^)]*\d{2}-\d{2}-\d{2}\)` |
| R3 | 클러스터마다 `## 아직 모르는 것` 블록에 1개 이상 항목 | 섹션 존재 + 불릿 수 |
| R4 | `## 통합 논지`는 2문장 이하, 수치 2개 이상 | 문장 분리 후 카운트 |
| R5 | 금지 표현이 **같은 불릿에 수치 없이** 등장하면 실패 | 아래 목록 |
| R6 | 불릿의 수치가 그 클러스터 근거 문서 원문에 문자열로 존재 | 원문 grep. **WARN**(발행은 막지 않음) |

R5 금지 표현: `가속`, `확대`, `강화`, `진화하고 있다`, `흐름은 일관`, `확신도 중간`, `중요하다`, `주목된다`, `전망이다`.
수치가 있으면 통과시킨다 — "수요가 +21GW→+84GW로 가속"은 일반론이 아니다.

R6은 왜 WARN인가: 원문이 "3.5배"로 쓴 걸 클러스터가 "35PFLOPS(GB200 대비 3.5배)"로 풀어 쓰면 문자열이 어긋난다. 정상적인 서술 변형까지 막으면 문장이 딱딱해진다. 대신 WARN 목록을 메인 세션이 눈으로 훑어 조작 여부만 가른다.

앵커 약칭 규칙: 문서 제목에서 `[YYMMDD]` 제거 후 첫 명사구 12자 이내. 예 `(메모리 마니아 26-02-07)`.
같은 불릿에 근거가 여럿이면 앵커도 여럿 허용한다.

## 클러스터 구조 (6블록)

기존 5블록 + 신규 1블록. 순서 고정.

```
## 통합 논지        R4
## 공통 진단        R1 R2 R5
## 연결·인과        R2 R5
## 상충·이견        R1 R2 R5
## 아직 모르는 것    R1 R2 R3 (신규)
## 함의·다음 확인 포인트   R2 R5
```

`## 아직 모르는 것`에 담는 것: 원문이 공개하지 않은 수치, 독립 검증 전 주장, 상반 근거가 없어 판정 불가한 항목. 각 항목은 "무엇을 모르는가 + 언제·무엇이 나오면 풀리는가" 두 부분으로 쓴다.

기존 `상충·이견`과의 경계: 상충은 **근거가 둘 이상 있고 서로 어긋나는 것**, 미지는 **근거 자체가 없는 것**.

## 구현

### 1. 검사기 (`insights/validate_insights.py` 확장)

기존 provenance 검사는 유지하고 규칙 검사를 추가한다.

```
python insights/validate_insights.py
→ FAIL insights/clusters/냉각.md:19 [R1] 수치 없음: "방향은 일관되나 아직 시제품 …"
→ FAIL insights/clusters/냉각.md:19 [R2] 앵커 없음
→ 요약: 9클러스터 / 불릿 105 / 실패 61 / 숫자 포함 58% / 앵커 3%
```

- 종료 코드: 실패 1건 이상이면 1
- 요약 지표를 항상 출력해 재작성 진척을 추적한다
- `--fix` 같은 자동 수정은 넣지 않는다. 문장은 사람(또는 에이전트)이 쓴다.

### 2. 재작성 (서브에이전트 9개)

클러스터당 sonnet 서브에이전트 1개. 메인 세션은 규칙 전달과 검수만 한다 — 사실 1,424행을 메인에서 다 읽으면 컨텍스트가 소모된다.

각 에이전트에 주는 것:
- 대상 클러스터 파일 경로 1개
- 그 클러스터 근거 문서의 **경로 목록**과, 색인용 사실 행(`insights/facts.py`의 `rows(path)`)
- 이 스펙의 "문장 규칙" 절 전문
- 종료 조건: `python insights/validate_insights.py` 가 해당 파일에 대해 실패 0

작업 순서(에이전트):
1. 사실 색인을 훑어 쓸 문장 8~14개의 뼈대를 정한다
2. **문장마다 해당 근거 문서를 열어 확인한다** — 수치가 맞는지, 그리고 색인(`📌 핵심`)에 없던 더 날카로운 숫자가 본문 산문·표에 있는지. 코퍼스 수치의 66%는 색인 밖에 있다
3. 확인한 수치로 문장을 쓰고 앵커를 붙인다

각 에이전트가 지켜야 할 것:
- frontmatter(sources·source_hashes·as_of 등)는 **수정 금지**
- **원문에서 눈으로 확인하지 않은 수치는 쓰지 않는다.** 색인 행을 그대로 옮기는 것도 확인 없이는 금지
- 원문에 없는 계산·환산(비율, 합계)을 새로 만들지 않는다
- 블록 순서·제목 문자열은 스펙대로 고정

### 3. 재생성·발행

재작성 후: `gen_dashboard.py` → `gen_map.py` 순으로 재실행, 두 아티팩트를 기존 URL로 재발행.

생성기 수정은 필요 없다. 대시보드의 `md_body()`는 `##` 섹션을 순서대로 전부 렌더하므로 신규 블록이 자동으로 실린다. 지도는 `공통 진단`·`상충·이견`·`함의` 3개만 골라 쓰므로 그대로 두고, 신규 블록은 대시보드에서만 보이게 한다.

## 검증

1. `python insights/validate_insights.py` 실패 0
2. 지표: 숫자 포함 ≥80%, 앵커 100%, 클러스터별 미지 항목 ≥1
3. `python -m pytest insights/test_insights.py` 통과 (기존 배관 회귀 없음)
4. 규칙 자체의 테스트: 통과/실패 샘플 문장으로 R1~R5 각각 단위 테스트

## 실패 모드

- **앵커 강제가 문장을 망가뜨린다.** 불릿마다 괄호가 붙어 읽기 나빠질 수 있다. 완화: 앵커는 불릿 끝 1회로 제한하고, 같은 문서 반복 시 약칭을 짧게 쓴다.
- **수치 채우기용 억지 숫자.** "3사", "2가지" 같은 무의미한 수가 R1을 통과시킬 수 있다. 완화: 검사기는 단위·연도·비율이 붙은 수치(`\d+(%|GW|kW|억|조|배|nm|년|월)` 또는 `20\d\d`)만 인정한다.
- **에이전트가 사실을 지어낸다.** 완화: R6(WARN) 목록 + 메인 세션이 클러스터당 무작위 3문장을 원문 대조.
- **에이전트가 원문을 안 열고 색인만 베낀다.** 그러면 이번 작업의 목적 자체가 무너진다. 완화: R6 WARN 비율이 비정상적으로 낮으면(= 색인 문구를 그대로 옮긴 흔적) 해당 클러스터를 재작업시킨다. 시범 1개(냉각)에서 색인 밖 수치가 실제로 새로 들어왔는지 먼저 확인한다.

## 작업 순서

1. 검사기 규칙 구현 + 단위 테스트 → 현재 상태 측정치 기록
2. 냉각(25%) 1개로 시범 재작성 → 규칙이 실제로 읽을 만한 문장을 만드는지 확인
3. 사용자 확인 후 나머지 8개 병렬 재작성
4. 전수 검사 통과 → 재생성 → 재발행 → 커밋
