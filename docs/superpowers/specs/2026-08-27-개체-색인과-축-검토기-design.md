# 개체 색인 — 놓친 원문을 찾는다

원문 920편 129,490줄을 개체 이름으로 훑어 `개체 → 줄 주소` 색인을 만들고, 그 위에 조회를 얹는다. 색인에 본문을 담지 않고 주소만 담는다 — 조회는 주소를 받고 그 줄만 읽는 2단이다.

## 무엇을 만드나

**① 개체 색인** — 코퍼스 920편 129,490줄을 개체 이름으로 훑어 `개체 → 줄 주소`를 적어 둔다. 어휘 매칭은 결정적이고 0.3초에 끝난다. 조회는 2단이다: 주소를 받고, 그 줄만 읽는다.

**② 벡터 검색** — 이름을 모르고 개념만 아는 물음을 위한 셋째 갈래. 순서상 마지막이고, 앞 둘이 세운 주소 체계 위에 얹는다.

## 왜 지금인가

증상 넷이 같은 구멍을 가리킨다.

**원문에 한 번 나온 회사가 안 잡힌다.** 색인 단위가 노트라서다. 노트 349장의 `actors`에 안 적히면 그 회사는 저장소에 없는 것과 같다. 저장소는 이 버그를 이미 한 번 맞았다 — `insights/gen_entity_board.py` 머리말이 xAI를 「221일째 조용」으로 내보낸 사고를 적어 놨고, 원인은 xAI 전용 클리핑이 원자화 안 된 채 있었던 것이었다. 실측하면 xAI는 `content/` 안에서만 176줄 47편에 나온다.

**요약이 지운 세부는 요약에서 복구가 안 된다.** 카드는 원문의 세부를 덜어내고 쓴다. 그러니 검색이 노트 349장이 아니라 원문 129,490줄에 착지해야 한다. 이건 어떤 검색법을 쓰느냐와 무관한 층이다.

**코퍼스를 통째로 컨텍스트에 넣을 수 없다.** 920편 1,084만 자 ≈ 770만 토큰이다. 200K 창에 38배 초과다.

**축 체계가 서 있는데 아무도 안 쓴다.** `insights/axes.py`는 축 셋(`money`·`measure`·`rates`)을 세워 놨고 `check_axes.py`가 MECE를 이미 검사한다 — A2가 겹침(Mutually Exclusive), A3가 빠짐(Collectively Exhaustive)이다. 그런데 축을 그리는 대시보드는 `gen_insightview.py` 하나뿐이고 대시보드는 20장이다. 그리고 **노트 349장 중 `cell:`을 선언한 것은 0장이다.** 라벨링 비용이 빈 필드로 드러났다.

## 구조화는 이 문서에서 떴다

축·형·MECE 검토는 `2026-08-27-축-검토기-design.md` 로 옮겼다. 둘은 별개 산출물이다 — 색인은 원문 129,490줄을 읽고, 축 검토기는 카드 322장을 읽는다. 축 검토기가 색인을 기다릴 이유가 없다.

## 날짜가 하나가 아니라 둘이다

파일 하나가 시간대 하나를 다루지 않는다. 메르 클리핑 368편을 재면 이렇다.

```
연도가 명시된 글                  329 / 368편
글 하나에 나오는 서로 다른 연도    중앙값 3 · 평균 4.3 · 최대 16
연도 여섯 개 이상인 글             100편 (27%)
상대 시간표현이 든 글              123편 (33%)

「7광구 한일 협상이 재개되는 비밀」
  쓴 날 2024-09-27
  본문  1965 1969 1970 1978 1980 1983 1985 1995 2004 2012 2028   폭 63년
```

파일 날짜만 쓰면 저 63년이 한 점에 찍힌다. 연표 축을 세우면 368편이 점 368개로 뭉개지고, 2028년 전망이 과거로 찍힌다.

그래서 hit 하나가 날짜를 둘 갖는다.

```
쓴 날 (utterance)      파일 단위. manifest.json 에 이미 있다
가리키는 때 (referent)  줄 단위. 이것이 빠진 것
```

뽑는 것은 결정적으로 된다.

| 꼴 | 방법 | 실측 |
|---|---|---|
| 명시 연도 「1965년」 | 정규식 | 메르 329/368편 |
| 상대 표현 「작년」「3년 전」 | 쓴 날 기준으로 계산한다 | 123편 |
| 없음 | 쓴 날을 상속한다 | 나머지 |

상대 표현이 공짜인 것이 핵심이다. 쓴 날을 아니까 「작년」은 뺄셈으로 풀린다. 판단이 필요 없다.

확실도를 함께 적는다 — **명시 · 계산 · 상속**. 상속뿐인 줄로 연표를 그리지 않게 표시한다.

## 시제 셋이 유효성을 가른다

가리키는 때를 쓴 날과 견주면 셋으로 갈린다.

```
회고   가리키는 때 < 쓴 날      1965년 한일협정
현재   가리키는 때 ≈ 쓴 날      지금 점유율은 90%다
전망   가리키는 때 > 쓴 날      2028년에는 협정이 만료된다
```

**일괄로 「최근 것만」을 걸면 틀린다.** 낡는 것과 안 낡는 것이 다르기 때문이다.

| | 낡나 | 왜 |
|---|---|---|
| 회고 | 안 낡는다 | 1965년에 일어난 일은 2026년에도 그대로다 |
| 현재 서술 | 낡는다 | 점유율 90%는 분기면 뒤집힌다 |
| 전망 | 낡는다. 그리고 검증 대상이 된다 | 2028년 전망은 2028년에 맞았는지 따진다 |

시제가 판별자다. 그러니 신선도는 `check_fresh.py`의 `STALE_DAYS`(`biz` 120일 · `chip` 180 · `model` 180 · `power` 365)를 그대로 재사용하되 **현재와 전망 줄에만 먹인다.** 회고 줄은 면제다 — 안 그러면 1965년 회고가 「60년 낡음」으로 걸러진다.

덤으로 전망 줄이 자동으로 모인다. 검증 대장이 지금 손으로 모으는 것을 색인이 준다.

조회 결과에 시간대를 박는다.

```
$ python scripts/q.py 7광구
7광구 · 원문 4편
  [1] 회고 1965  (쓴 날 2024-09-27, 명시)   한일협정으로 …
  [2] 회고 2004  (쓴 날 2024-09-27, 명시)   중국이 …
  [3] 전망 2028  (쓴 날 2024-09-27, 명시)   협정이 만료되면 …   미검증
  [4] 현재  —    (쓴 날 2024-09-27, 상속)   시점이 약하다
```

**연표 축은 쓴 날이 아니라 가리키는 때로 세운다.**

## 검색은 세 갈래가 같은 주소로 모인다

물음의 꼴이 넷이고 도구가 셋이다.

| 묻는 꼴 | 도구 |
|---|---|
| 이름을 안다 — 「램리서치」 | 어휘 |
| 표기가 흔들린다 — 「Lam」「램리써치」 | 별칭 사전. 여전히 어휘다 |
| 이름을 모르고 개념만 안다 — 「식각 장비를 독점하는 데」 | 벡터 |
| 관계를 묻는다 — 「HBM과 전력이 같이 나오는 데」 | 그래프 |

```
어휘(별칭) ─┐
그래프     ─┼─→ 후보 줄 주소 ─→ 원문 재검토 ─→ 근거
벡터       ─┘     (합집합·랭킹)     (결정적)
```

셋 다 산출이 `경로#L123`으로 같다. 그래서 갈아 끼울 수 있고, 벡터를 나중에 붙여도 앞단이 안 바뀐다.

**어휘가 첫째인 이유.** 실측으로 548편 전부를 0.3초에 훑고 토큰을 0 쓴다. 램리서치 44줄 9편, xAI 176줄 47편, 엔비디아 2,664줄 222편이 그대로 나온다. 고유명사를 놓치지 않는다.

**임베딩을 첫째로 안 두는 이유.** 한 번만 언급된 고유명사가 임베딩의 최악 조건이다 — 그 이름이 문단 벡터 안에서 희석된다. 지금 증상을 정확히 못 고치는 도구다. 이름을 모를 때만 값이 나온다.

**그래프는 토큰을 먹지 않는다.** 순회는 순수 CPU고 노드가 수백 개면 마이크로초다. 토큰은 컨텍스트에 넣은 것만 먹는다. 그래프는 오히려 토큰을 줄인다 — 엔비디아 2,664줄을 다 넣을 수 없으니 무엇을 자를지 정해야 하고, 그 일을 그래프가 한다.

**벡터의 규모.** 문단 청크 2~3만 개, 작은 다국어 모델로 CPU에서 한 번 빌드하고 이후 새 파일만 증분으로 더한다. 저장은 3만 × 384차원 float32 = 46MB라 커밋하지 않고 로컬 생성물로 둔다. 조회는 쿼리 임베딩 한 번과 3만 번 내적이라 numpy로 밀리초다. **벡터DB도 근사 최근접 라이브러리도 쓰지 않는다** — 이 규모에서는 전수 계산이 더 빠르고 의존성이 0이다.

**비결정을 산출물까지 안 보낸다.** 검사기가 전부 결정적인데 임베딩 모델은 첫 비결정 조각이다. 규칙 하나로 봉한다 — **임베딩은 후보를 찾는 데만 쓰고 근거로는 안 쓴다.** 찾은 뒤에는 원문 줄을 읽고, 인용은 `check_cite`가 그 줄에 그 숫자가 있는지 확인한다.

## 답에 영수증을 붙인다

`2026-08-05-실패한-것은-에이전트가-아니라-하니스다`가 가른 것을 그대로 쓴다 — **기록은 무엇이라고 말했는지를 남기고, 영수증은 실제로 무엇을 했는지를 남긴다.** 조회 결과에 근거를 함께 적는다.

```
색인 판   gen_index.py 가 읽은 manifest 해시와 만든 날
본 줄     답에 실제로 들어간 줄 주소 전부
때 판정   각 줄의 가리키는 때와 그것을 명시·계산·상속 중 무엇으로 정했는지
안 본 것  hit 이 상한을 넘어 잘렸으면 잘린 개수
```

마지막 줄이 있어야 「44줄 중 40줄만 봤다」가 드러난다. 이것이 없으면 잘린 답과 완전한 답이 화면에서 같아 보인다.

## 자료구조

```
insights/entities.json      개체 사전. 사람이 검토하고 커밋한다
insights/gen_index.py       결정적 매칭기
insights/index.json         생성물. 개체 → 줄 주소 목록
insights/times.json         생성물. 줄 주소 → 가리키는 때·확실도
insights/check_index.py     색인 검사기
scripts/q.py                조회 CLI
```

`entities.json` 한 항목:

```json
{
  "canonical": "램리서치",
  "type": "회사",
  "ko": ["램리서치", "램리써치"],
  "en": ["Lam Research", "Lam"]
}
```

타입은 다섯으로 통제한다 — 회사·기술·제품·지표·사람. 이 다섯만 손으로 유지하고 주제 위계는 동시출현에서 파생시킨다. 씨앗은 노트 `actors` 474종과 `actor_alias.json` 40개에서 자동으로 뽑고, 타입 부여는 한 번의 판단으로 붙인다.

`index.json`은 **본문을 담지 않고 주소만 담는다.**

```json
{"램리서치": ["content/newsletter/ai_infra/memory/[230717] 낸드플래시 독점 균열.md#L246"]}
```

`cites.json`이 해시만 갖는 것과 같은 이유다. 스니펫을 넣으면 12MB로 부는데 주소만 두면 4MB 아래로 떨어지고, 본문은 조회할 때 그 줄을 읽으면 된다.

`times.json`은 **희소하게 둔다.** 명시되거나 계산된 줄만 적고 상속은 안 적는다.

```json
{"input/clippings/mer/223407396834.json#L88": {"t": "1965", "how": "명시"}}
```

상속은 조회할 때 `manifest.json`의 파일 날짜로 채운다. 없는 것을 안 적으면 파일이 작고, 「이건 상속이다」가 저절로 구분된다.

  [1] 현재 2023  낸드 독점 균열 L246

## 검사

`check_index.py`가 보는 것. **첫째가 제일 중요하다.**

```
X1  manifest.json 의 파일 해시와 대조해 색인이 낡았다   ← 조용한 실패
X2  entities.json 의 별칭이 둘 이상의 정본에 걸려 있다
X3  index.json 의 주소가 가리키는 파일이 없다
X4  주소의 줄 번호가 파일 범위 밖이다
X5  노트 actors 에 있는 이름이 entities.json 에 없다
X6  times.json 의 가리키는 때가 코퍼스에 있을 수 없는 값이다
```

X1을 첫째로 두는 이유가 있다. 새 원문이 들어왔는데 색인을 안 돌리면 **조회가 에러 없이 그럴듯한 답을 낸다.** 빠진 자료가 있다는 신호가 어디에도 안 뜬다. `2026-08-05-실패한-것은-에이전트가-아니라-하니스다`가 이것을 조용한 성공이라 부른다 — 충돌은 경계를 주지만 조용한 성공은 안 주고, 일관돼 보이는 답이 실은 끊긴 이력 위에 서 있다. 나머지 다섯은 틀린 주소를 잡는 검사고, X1만이 없는 자료를 잡는 검사다.


`CLAUDE.md`의 검사기 목록에 `check_index.py`를 한 줄 더한다. 개수는 이미 제목에서 뺐다(`ee48b4b`).

## 순서

1. `entities.json` 씨앗 — 노트 `actors` 474종과 별칭 40개에서 자동 생성, 타입 부여
2. `gen_index.py`와 `index.json` — `content/` 548편 먼저
3. `q.py` — **여기서 그냥 grep보다 나은지 확인한다. 안 나으면 4로 안 간다**
4. `times.json` — 명시 연도와 상대 표현, 시제 셋
5. `input/clippings` 영문 원본과 메르 클리핑 확장, 영한 이름 매핑
6. 동시출현 그래프와 연표
7. 벡터 갈래

## 안 하는 것

- **주제 택소노미를 손으로 짜지 않는다.** `topics` 1,023종 중 799종이 한 번만 쓰였다. 손 라벨링은 이미 한 번 실패했다. 위계는 동시출현에서 파생시킨다
- **회고 줄에 신선도를 안 먹인다.** 낡는 것은 현재 서술과 전망뿐이다
- **벡터DB를 안 쓴다.** 3만 청크에서는 전수 계산이 더 빠르다
- **임베딩을 근거로 안 쓴다.** 후보 발견 전용이다
- **`gen_entity_board.py` 의 `signal_hits(alias, cap=6)` 을 남겨 두지 않는다.** 색인이 서면 그 함수는 색인을 부르게 갈아탄다. 같은 일을 하는 코드가 둘이면 하나가 낡는다
