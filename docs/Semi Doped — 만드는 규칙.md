# Semi Doped — 만드는 규칙

원문 한 편이 카드 한 장이 된다. 절차는 둘이다 — **원문을 뜯는 일**과 **보고서를 쓰는 일**.
둘을 한 사람이 이어서 하면 원문 덩어리가 머리에 남아 요약을 요약하게 된다. 뜯는 일은
위임하고, 쓰는 일만 직접 한다.

이 문서는 2026-08-29 에 카드 한 장(오픈AI 할라페뇨)을 놓고 하루 종일 결함을 잡아 가며
세웠다. **여기 적힌 것은 전부 그날 실제로 터진 것이다.** 일반론은 넣지 않았다.

## 목차

```
1  원문 분석      1-1 위임한다  ·  1-2 받는 꼴  ·  1-3 성격 여덟  ·  1-4 받고 나서
2  보고서 작성    2-1 마디 찾기  ·  2-2 MECE 점검 셋  ·  2-3 축을 판다
                 2-4 절 쓰기  ·  2-5 값에 이름  ·  2-6 도해  ·  2-7 각도 상자
3  검사           3-1 검사기  ·  3-2 결함을 넣어 본다
```

## 1. 원문 분석

### 1-1 위임한다

원문은 전사본이라 만 자를 넘는다. 그걸 직접 읽으면 머리에 원문 문장이 남고, 카드를 쓸 때
**요약을 다시 요약하게 된다.** 그러면 「누가 무엇을」이 빠지면서 뜻이 뒤집힌다.

sonnet 에 넘긴다. 넘길 때 **요약하지 말고 옮기라고** 못박는다.

### 1-2 받는 꼴

한 줄에 항목 하나. 표가 아니라 줄이다 — 표로 받으면 칸을 맞추느라 값이 잘린다.

```
L<줄번호> | <주체> | <무엇> | <값 그대로> | <성격>
```

- **줄번호**는 그 파일의 실제 줄이다. 나중에 카드에서 인용할 때 원문을 다시 안 연다
- **주체**는 회사·기관 이름이다. 진행자 이름(오스틴·빅)을 주체에 쓰지 않는다 —
  진행자가 남의 것을 읽은 것이면 주체를 그 회사로 두고 「진행자 읽기 —」를 앞에 붙인다
- **값**은 원문 표기 그대로. 환산도 반올림도 하지 않는다

그리고 셋을 더 받는다.

```
소제목 목록        §소제목 (L시작~L끝) 꼴로 전부
저자 논지          이 글이 세운 주장을 5줄 이내 산문으로
원문이 안 밝힌 것   값이 없거나 근거가 진행자 추정인 대목 5개 이내
```

셋째가 카드의 마지막 절이 된다. 이걸 안 받으면 한계 절을 쓸 때 원문을 다시 열어야 한다.

### 1-3 성격 여덟

```
사실 · 계획 · 전망 · 추정 · 가정 · 발언 · 제안 · 개념
```

여덟 밖은 없다. 이 구분이 없으면 합칠 때 추정이 사실로 굳는다. 특히 **진행자가 스스로
「추측」이라고 못박은 것**은 반드시 추정으로 받는다 — 할라페뇨 편의 CPU 종류·공정 노드·
HBM 공급사가 전부 그랬다.

### 1-4 받고 나서

받은 줄을 그대로 카드에 옮기지 않는다. 줄은 재료지 글이 아니다. 여기서 2 로 넘어간다.

## 2. 보고서 작성

### 2-1 마디 찾기 — 미리 정해 두지 않는다

마디는 둘 중 하나다.

```
대상의 마디   다루는 것이 실제로 어떤 부분으로 되어 있는가 (메모리 · 연산 · 연결)
              본문에서 그 말로 이야기하고 있어야 한다
글이 굴러가는 차례   무엇을 노렸고 → 무엇을 했고 → 무엇이 나왔고 → 무엇을 모르나
              대상의 말이 아니므로 목차에 「무엇으로 갈랐는지」를 적는다
```

**차례 이름을 목록으로 두지 않는다.** 한때 「목표·시도·성과·한계」를 닫힌 넷으로 박고
검사기로 강제했다가 되돌렸다 — 그러면 모든 카드가 그 넷으로 굽는다. 이름도 차례도 글이
정한다. 카드는 이렇게 적는다.

```python
('toc', ('글이 굴러가는 차례', [ … ]))     # 차례로 갈랐을 때
('toc', [ … ])                          # 대상의 마디로 갈랐을 때
```

축을 적으면 맨 위에 사슬(`목표 → 시도 → 성과 → 한계`)이 걸린다. 대상의 마디에는 순서가
없으므로 사슬을 안 건다 — 화살표로 이으면 없는 순서를 지어내는 꼴이다.

### 2-2 MECE 점검 셋

마디를 세운 뒤 반드시 묻는다. 셋 다 그날 실제로 깨졌다.

```
겹치나      두 마디가 같은 물음을 답하고 있지 않나
            「설계 기준」과 「벤치마크」가 둘 다 「무엇을 재나」였다
층위가 같나  한 층에 성격이 다른 것이 섞이지 않았나
            목표 · 구조 셋 · 성과 · 공정이 같은 들여쓰기로 섰다
차례가 맞나  차례로 갈랐다면 실제 순서와 같나
            성과가 공정 앞에 서 있었다 — 만들기 전에 재는 셈이다
```

### 2-3 축을 판다 — 깊이를 미리 정하지 않는다

한 마디 아래 절이 셋을 넘으면 그 안에도 축이 있다. 없는 채로 늘어놓으면 층위가 다른 절이
나란히 선다.

```
시도   (설계)
         (칩 내부)  ② (메모리) 어떻게 붙였나
                    ③ (연산) 어떻게 한 칩에 몰았나
         (칩 외부)  ④ (연결) 몇 개가 한 덩어리로 도나
       (기간)       ⑤ (개발) 9개월이 어떻게 나왔나
```

**축 이름을 괄호로 앞세운다.** 「어떻게 붙였나」와 「어떻게 몰았나」를 나란히 두면 무슨
기준으로 갈렸는지 모른다. (메모리)·(연산)이 앞에 서면 제목을 읽기 전에 걸린다.

깊이 제한은 없다. 잎에 아직 여럿이 들어 있으면 한 층 더 파고, 더 쪼개도 뜻이 안 늘면
거기가 잎이다. 한 묶음이 값 하나만 갖게 되면 너무 판 것이니 위 층에 되돌린다.

### 2-4 절 쓰기

```
제목      물음 하나. 「무엇으로 쟀고 무엇이 안 재졌나」는 절이 둘이다
번호      ①②③. 목차의 번호와 절의 번호가 같아야 한다
나열      「셋 남는다」로 열었으면 항목이 셋이고 ①②③ 이 다 붙어야 한다
마지막    한계. 검증 안 한 것, 진행자 추정인 것
```

### 2-5 값에 이름을 붙인다

숫자만 적고 **무엇의 값인지**를 빼면 읽는 사람이 못 알아본다.

```
✕  128칩의 HBM4 를 합치면 초당 약 1페타바이트다
✓  HBM4 가 초당 읽어 내는 양을 칩 128개치 합치면 약 1페타바이트다
```

**지어낸 말을 쓰지 않는다.** 「겹이 둘이다」라고 썼는데 무슨 겹인지 아무 데도 안 적혀
있었다. 「칩을 묶는 단위가 두 단계다」로 적고 작은 묶음·큰 묶음으로 부른다.

전문용어는 남기고 첫 등장에 괄호로 푼다. 쉬운 말로 치환하지 않는다.

### 2-6 도해

```
값        원문에 없는 값을 그리지 않는다. 막대 길이도 아이콘 개수도 수치로 읽힌다
글자      판 위 글자는 그 자체로 읽혀야 한다. 「칩당 초당 600Gb」는 줄임말이다 —
          「칩 하나가 초당 600기가비트로 붙는다」로 편다
줄        한 줄에 한 뜻. 「잣대가 돈에서 / 사람이 겪는 것으로 / 옮겼다」처럼 격조사로
          끊어 세 줄로 자르면 한 줄씩은 아무 뜻이 없다. 두 줄 라벨은 정상이다
자리      상자 사이에 글자를 넣으려면 띠를 32픽셀은 벌린다. 12픽셀에 넣었다가 아래
          상자 테두리에 깔렸다
```

### 2-7 각도 상자 — 접어 둔다

원문이 다룬 마디 중 카드가 절로 안 세운 것을 밝히는 자리다. 감추면 카드가 원문 전부인
것처럼 읽힌다. 다만 **눌러야 펴진다** — 늘 펴 놓으면 본문보다 먼저 눈에 들어와 카드가
목록으로 보인다.

절로 세운 마디는 진하게, 안 세운 마디는 흐리게 남긴다.

## 3. 검사

### 3-1 검사기

`CLAUDE.md` 의 목록을 **전부** 돌린다. 이 장에 직접 걸리는 것은 넷이다.

```bash
PYTHONIOENCODING=utf-8 python insights/check_struct.py   # 앞머리·목차·마디·축·절·나열
PYTHONIOENCODING=utf-8 python scratchpad/check_fig.py    # 도해 배치·줄임말·잘린 줄
PYTHONIOENCODING=utf-8 python insights/check_figval.py   # 도해에 든 값이 원문에 있나
PYTHONIOENCODING=utf-8 python insights/check_prose.py    # 문체·밀도·은유
```

### 3-2 결함을 넣어 본다

**규칙을 세웠으면 무는지 확인한다.** 이게 절차의 일부다.

그날 S12(나열 번호)를 세워 놓고 확인을 안 했으면 그대로 나갈 뻔했다 — 처음 판은 「번호가
하나라도 있으면 통과」였고, ① 만 남기고 ②③ 을 뗀 문단을 지나쳤다. S3 도 목차 상자를 자기
본문으로 세고 있어서 본문에 없는 마디를 통과시켰다. 「물총새」를 넣어 보고 알았다.

넣어 보는 것 넷.

```
마디 이름을 본문에 없는 말로 바꾼다        S3 가 물어야 한다
차례로 갈랐다면서 같은 마디를 두 번 세운다   S9 가 물어야 한다
한 마디 아래 절 넷을 축 없이 늘어놓는다     S11 이 물어야 한다
「셋 남는다」로 열고 ① 만 남긴다           S12 가 물어야 한다
```

## 이 문서가 밝히지 않은 것

- 카드 여러 장을 한 물음으로 꿰는 일은 여기 없다. 그건 `insight-report` 다
- 원문이 팟캐스트가 아닌 갈래(뉴스 묶음·TIL 묶음)를 어떻게 자르는지는 아직 안 세웠다.
  한 편짜리 카드부터 굳히고 그다음에 정한다
