## 이 스킬이 하는 일

물음을 받아 쪼갬 후보를 세우고, 크게 지우는 것부터 펴고, 어디를 더 파야 하는지 가린다.
**만들어 놓고 보는 그림이 아니라 답까지 가는 탐색 절차다.**

안 하는 일 — 카드를 폴더에 넣는 것(서류 정리), 트리를 저장소에 쌓는 것, 글을 고치는 것.

## 왜 MECE 인가

**소거를 정당하게 만들려고** 한다. 목적이 아니다.

```
겹치면   가지 하나를 지워도 원인이 아직 거기 있을 수 있다   → 못 지운다
빠지면   다 뒤졌는데 답은 안 센 자리에 있다              → 헛수고
```

완벽할 필요는 없다. 다만 **얼마나 겹치고 얼마나 비었는지를 알아야** 지운 가지를 믿는다.

## 절차 여섯

### 0. 물음을 벼린다

받은 그대로는 대개 답이 안 나온다. 셋이 없으면 채운다.

```
누구의 것인가      주체가 다르면 답이 다르다
언제까지인가       시계가 없으면 판정이 안 된다
무엇으로 재나       성공의 기준
```

**이 단계를 건너뛰면 아래가 전부 헛돈다.** 벼린 물음을 한 줄로 적고 시작한다.

### 1. 컷 후보를 둘셋 세운다

각 후보가 **무엇을 답하는지** 같이 적는다. 「이 컷은 크기를 잰다」 「이 컷은 어디서 끊기는지를 본다」.

순서가 중요하다. **먼저 지어내고 나중에 아래 표와 대조한다.** 표를 훑고 고르면 표가 메뉴가 된다.
그리고 **매번 표에 없는 후보를 하나 이상 만든다.** 못 만들면 생각한 것이 아니라 고른 것이다.

| 갈래 | 꼴 | 강점 |
|---|---|---|
| 이분법 | A / A 아닌 것 | 공짜로 MECE. 통찰은 약해도 구멍이 없다 |
| 수식 | 매출 = 단가 × 수량 | 몫이 계산으로 나온다 |
| 구성 | 비용 = 재료 + 인건 + 물류 | 합이 전체가 된다 |
| 프로세스 | 유입 → 전환 → 유지 → 이탈 | 어디서 새나 |
| 공급/수요 | 공급 측 / 수요 측 | 값과 양이 걸린 물음 |
| 행위자 | 공급자·고객·경쟁자·규제자 | 누가 움직이나. 시장 구조 |
| 이해관계자 | 이득 보는 쪽 / 손실 보는 쪽 / 위험 지는 쪽 / 결정하는 쪽 | 누구에게 걸려 있나. 이해가 어긋나는 자리 |
| 안/밖 | 우리 탓 / 바깥 변화 | 통제 가능한 것을 가른다 |
| 시간 | 전 / 후, 언제부터 | 방아쇠가 언제 당겨졌나 |
| 대립 | 살까 만들까 | 진단이 아니라 결정용 |
| 구간 | 상위 20% / 나머지 | 쏠린 데를 바로 집는다 |

**행위자와 이해관계자는 다른 컷이다.** 행위자는 「누가 움직이나」로 시장을 나누고,
이해관계자는 「누구에게 걸려 있나」로 나눈다. 이해관계자 컷에서는 **같은 회사가 여러 자리에
선다** — 어떤 물음에서는 빌리는 쪽이고 다른 물음에서는 빌려주는 쪽이다.

이해관계자 컷이 특히 세지는 자리 둘.

```
답이 자리마다 다를 때     「회수되는가」의 답이 칩회사·네오클라우드·전력회사마다 다르면
                        물음을 통으로 물으면 안 된다는 뜻이다. 컷이 물음을 고쳐 준다
이해가 어긋날 때         한쪽의 이득이 다른 쪽의 손실이면 「최선의 답」이 하나가 아니다.
                        누구 입장에서의 최선인지를 먼저 정해야 한다
```

그리고 이해관계자로 자른 뒤 각 자리 안을 또 다른 방식으로 자른다 — 한 자리는 수식으로,
다른 자리는 프로세스로. 자리마다 걸려 있는 것이 다르니 쪼개지는 방식도 다르다.

원인을 찾을 때는 안/밖 → 시간 → 프로세스 → 수식 순으로 지우는 힘이 세고, 해결책을 찾을 때는 행위자·대립·구성 쪽이다. **힌트다. 매핑이 아니다.**

### 2. 크게 지우는 컷부터 편다

후보 중 **소거가 제일 많이 되는 것**을 먼저 편다. 자료가 많은 컷이 아니다.

주체마다 답이 다르면 행위자 컷을 먼저 편다 — 다르면 **물음 자체가 틀린 것**이라
아래를 파기 전에 그것부터 알아야 한다.

한 단 펴고 나면 **잘라 낸 가지와 그 이유를 적는다.** 나중에 그 소거가 유효했는지 되짚어야 한다.

### 3. 노드마다 형을 갈아 끼운다

구조 전체가 트리이거나 프로세스인 것이 아니다. **노드마다 그 자리에서 제일 잘 쪼개지는 방식을 고른다.**
수식 안에 구성이 들고 그 안에 프로세스가 들고 그 안에 인과가 든다.

가지끼리 가로지르는 선이 있어도 된다 — 프로세스의 「가동」이 수식의 「공급량」으로 흘러드는 식.

**한 노드를 여러 방식으로 열어도 된다.** 하나로 안 좁힌다. 두 컷이 서로 다른 말을 하면
그 불일치가 곧 답이다.

### 4. 뎁스를 일부러 어긋나게 둔다

**고르게 깊은 트리는 우선순위를 안 매겼다는 표시다.** 몫이 3%인 가지를 네 단까지 파는 것은 낭비다.

멈추는 조건 둘 — 그 가지가 무시해도 될 만큼 작거나, 잎이 **관찰·결정할 수 있는 것**에 닿았거나.
「거시 환경」으로 끝나면 잎이 아니다.

### 5. 팔 데를 임팩트 × 불확실성으로 고른다

**자료가 얼마나 있나로 정하지 않는다.**

```
임팩트 큼 + 이미 확실함   답을 안다. 팔 것이 없다
임팩트 큼 + 불확실함      ★ 여기를 판다
임팩트 작음               잘라 낸다
```

가지마다 임팩트와 불확실성을 표로 적고 ★를 고른다. 고른 이유가 「틀리면 결론이 뒤집혀서」여야지
「자료가 많아서」면 안 된다.

### 6. 어긋난 데를 밝힌다

보고서 끝에 반드시 둘을 적는다.

```
MECE 가 안 맞는 자리   어느 가지끼리 겹치나. 그러면 그 소거가 온전하지 않다
가설이지 확인이 아닌 것  무엇을 세운 것이고 무엇을 아는 것인가
```

이것을 안 적으면 세운 구조가 이미 답인 것처럼 읽힌다.

## 자료를 붙일 때

`scripts/evidence.py` 가 가지에 코퍼스 근거를 붙인다.

```python
import evidence as ev
docs = ev.corpus(ROOT)                       # content/**/*.md
ev.weigh(docs, {'label': '전력', 'terms': ['PPA', '변압기'], 'deny': ['리스크']})
```

**돌려주는 문서 수는 순위가 아니다.** 「이 가지를 평가할 자료가 있나」이지 「이 가지가 답의
얼마를 먹나」가 아니다. 정렬에 쓰지 않는다.

`deny` 를 반드시 채운다. 한국어는 조사 때문에 부분 문자열로 잡아야 하고, 그러면 짧은 말이
긴 말 안에 걸린다 — 「리스」가 「애널리스트」·「리스크」에 걸려 한 가지를 253편으로 부풀린 적이 있다.

`widest_share` 가 높고 `widest_idf` 가 낮으면 그 가지의 근거가 **흔한 낱말 하나에 업혀 있다.**
그 개수를 믿지 않는다.

## 무엇을 남기나

트리를 저장소에 쌓지 않는다. 물음마다 새로 세운다. 대신 **보고서가 재현 가능해야 한다.**

```
벼린 물음          한 줄
컷 후보와 고른 이유   왜 이것부터 폈나
잘라 낸 가지와 이유
★ 로 고른 가지      임팩트·불확실성 표
어긋난 데           겹친 자리 · 가설인 것
```

## 기계와 판단의 경계

```
컷 후보를 세운다              판단
겹치나 — 이 둘이 같은 것인가   판단. 도메인 지식이 든다
가지에 자료를 붙인다           기계  evidence.py
자식 합이 부모와 같나          기계  수식 노드만. 산수다
임팩트·불확실성을 매긴다        판단
어디를 팔지 정한다             판단
멈출 때인가                   판단
```

기계는 **자료가 있는지 알려 주는 데까지**다. 고르는 것은 사람이다.

## 흔한 함정

| 함정 | 왜 틀렸나 |
|---|---|
| 자료가 많은 가지부터 판다 | 이미 판 데로 또 간다. 맹점이 꼴찌로 간다 |
| 트리를 고르게 채운다 | 우선순위를 안 매긴 것이다 |
| 컷을 하나로 좁힌다 | 불일치가 정보인데 버린다 |
| 표에서 컷을 고른다 | 표가 메뉴가 된다. 먼저 지어내고 나중에 대조한다 |
| 물음을 안 벼리고 시작한다 | 아래가 전부 헛돈다 |
| 쏠림을 컷의 성적으로 읽는다 | 쏠림은 다음에 팔 데를 가리키는 방향이다 |
