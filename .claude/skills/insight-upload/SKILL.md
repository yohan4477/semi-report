# 인사이트 업로드

새 해설 한 편을 주제 대시보드에 카드로 올리는 절차. **형식은 부동산 인사이트 한 벌로 통일한다.**

## 대상이 아닌 것

- **SemiAnalysis 대시보드는 예외다.** 카드 단위가 아니라 소셜 신호·뉴스레터·클러스터 판단으로 짜인
  다른 구조이고, 지금 형태를 그대로 둔다. 뉴스레터는 `semianalysis-newsletter` 스킬이 처리한다.
- LinkedIn·YouTube 신호 추가는 `linkedin-update` 스킬이다.

## 어느 대시보드인가

**채널이 아니라 주제로 고른다.** 같은 채널이라도 주제가 다르면 다른 페이지로 간다.

| 주제 | 페이지 | 생성기 |
|---|---|---|
| 공급·세제·전세·건설·토지 | `대시보드/부동산 대시보드.html` | `scratchpad/gen_realestate_dashboard.py` |
| 금리·국채·환율 | `대시보드/금융 대시보드.html` | `scratchpad/gen_finance_dashboard.py` |
| AI·데이터센터·전력·에너지·원유 | `대시보드/언더스탠딩 대시보드.html` | 없음 → `scripts/add_card.py` |
| 미국 증시 강의(네이버 프리미엄 카레라) | `대시보드/미국주식 사관학교 대시보드.html` | `scratchpad/gen_usa_dashboard.py` |
| 회계·재무제표·기업 평가 | `대시보드/회계사 대시보드.html` | `scratchpad/gen_accountant_dashboard.py` |
| 몸·질병·수면·대사 | `대시보드/건강 대시보드.html` | **`health-insight` 스킬로 간다** — 카드 단위가 영상이 아니라 주제다 |

생성기를 새로 만들거나 고칠 때는 `scratchpad/dash_common.py` 머리의 UI 규약을 먼저 읽는다.
첫 화면은 어느 장이든 섹션 타일이고, 조립은 `render()`만 거친다.
새 대시보드를 만들면 `scripts/build_all.py`의 `BUILD` 목록에 반드시 넣는다.

파일명이 옛 이름(`언더스탠딩 대시보드.html`)인 페이지의 표시 이름은 **AI · 인프라 · 에너지 인사이트**다.
`scratchpad/dash_common.py`가 이 파일의 `<style>`을 CSS 원본으로 읽으므로 파일명을 바꾸지 않는다.

## 카드 형식 — 부동산 기준

스키마와 마크업은 `scripts/card_lib.py` 한 벌뿐이다. 필수 키는 그 파일 머리말에 있고,
아래는 **내용을 어떻게 쓰는가**에 대한 규칙이다.

- **gain** — 이 편을 열면 무엇을 알게 되는지. 접힌 채로 고르는 기준이라 반드시 쓴다.
  옛 언더스탠딩 카드에 이게 없어서 제목만 보고 골라야 했다.
- **points** — 각 항목은 `<b>소제목.</b>`으로 연다. 숫자와 고유명사를 남긴다.
  일반론("중요하다", "주목된다")은 쓰지 않는다.
- **clash** — 반론·충돌은 **필수**다. 한 편만 읽고 결론 내리지 않게, 같은 대시보드의 다른 편이나
  SemiAnalysis 코퍼스와 어긋나는 지점을 박아 둔다. 수익 사례가 전면에 나오는 편일수록 길게 붙인다.
- **stats** — 본문에 실제로 나온 숫자만. 추정치를 만들지 않는다.
- **quote** — 원문에서 그대로. 다듬지 않는다.
- **table** — 비교 대상이 둘 이상일 때만. 탭으로 나누지 말고 한 화면에 나란히 둔다.
- **scope** — 국내·해외 탭이 있는 페이지에서만 `kr`/`intl`.

문체는 `korean-readability` 스킬을 따른다. 전문용어는 바꾸지 말고 **첫 등장에 괄호로 푼다**
(예: 용적률(대지면적 대비 지을 수 있는 총 바닥면적의 비율)).

## 화면에 나가는 형식 — 슬림

카드는 **접힌 채로 고르고 펼쳐서 읽는다.**

- **접힘**: 주제칩 · 제목 · `gain` · 화자와 날짜. 부동산 인사이트에서 쓰던 그대로다.
- **펼침**: 한 줄 요약 → 핵심 포인트 → 주요 숫자 → 인용. **AI · 인프라 · 에너지 카드와 같은 구성**이다.
  그 뒤에 **반론·충돌을 원본 그대로** 붙이고 유보 메모로 닫는다. 표는 화면에 내지 않는다.

이 형식으로 내려면 카드에 `slim_*` 필드를 쓴다(`scripts/card_lib.py`의 `slim_html`).

| 필드 | 분량 | 규칙 |
|---|---|---|
| `slim_oneliner` | 두세 문장 | 이 편이 무엇을 말하는지 |
| `slim_points` | 6~8개 | 각 한두 문장. `<b>소제목.</b>`으로 연다 |
| `slim_stats` | 4개 | 본문에 나온 숫자만 |

`points` · `table` · `stats` · `clash` · `note` 원본은 카드에 **그대로 남긴다.** 슬림은 렌더링 선택이라
`slim_*`만 지우면 지금까지의 형식으로 되돌아간다.

**슬림 포인트는 자막 전문에서 직접 뽑는다.** 카드에 이미 쓴 문장이나 요약 md를 다시 줄이지 않는다.
요약을 또 요약하면 "누가 무엇을"이 빠지면서 뜻이 뒤집힌다(용인 편에서 실제로 그랬다).
따옴표는 화자가 한 말로 읽히므로 **자막에 있는 말만** 넣는다. 우리가 만든 표현이면 따옴표를 떼고 서술한다.

## 검사 — 통과 못 하면 푸시하지 않는다

```bash
py -3.13 scratchpad/ytsub.py <영상ID>     # 자막 전문 받기 → scratchpad/yt_subs/<ID>.txt
py -3.13 scratchpad/check_slim.py         # 슬림 텍스트를 자막과 대조
```

`check_slim.py`가 보는 것 셋이다.

- **FAIL** — 따옴표 인용이 자막에 없다(유사도 0.55 미만). 자동 자막은 오인식이 많아 완전 일치가 아니라 유사도로 본다.
- **경고** — 숫자를 자막에서 못 찾았다. 3.4억 ↔ 3억 4천 같은 표기 차이일 수 있으니 사람이 확인한다.
- **경고** — 전문용어에 괄호 설명이 없다(`GLOSS_TERMS`). 새 용어를 쓰면 그 목록에 추가한다.

## 절차

### 1. 원문 확보
- 유튜브는 **자막 전문**을 받는다. 설명란 요약으로 때우지 않는다.
- 네이버 프리미엄 유료 텍스트는 CDP 크롬으로 파싱한다. 원문은 로컬에만 두고 공개엔 요약만 싣는다.
- 요약 원본은 `content/understanding/<주제 또는 화자>/` 에 마크다운으로 남긴다.

### 2. 카드 작성

생성기가 있는 페이지는 그 파일의 `CARDS` 목록에 dict를 추가하고 다시 만든다.

```bash
python scratchpad/gen_realestate_dashboard.py
```

섹션 순서는 각 생성기의 `SEC_ORDER`가 정한다. 섹션 번호는 생성기가 다시 매기므로 손대지 않는다.

생성기가 없는 AI · 인프라 · 에너지 페이지는 카드 dict를 파일 하나에 담아 끼워 넣는다.

```bash
python scripts/add_card.py scratchpad/card_new.py --section sec-ai
```

옛 형식 카드 26장은 **아직 소급 변환하지 않는다**. 새 카드만 표준 형식으로 올라가고
한동안 두 형식이 섞인다. 소급은 별도 지시가 있을 때 한다.

### 3. 주간·월간 리포트 갱신 — 빠뜨리지 않는다

카드를 올렸으면 그 페이지의 롤업도 같이 손본다. 새 편이 리포트 기간 안에 들어가는데
리포트가 그대로면 카드 수와 리포트 내용이 어긋난다.

- 산문은 사람이 쓴다(판단이라 자동 생성 금지). 파일은 페이지별로 나뉜다:
  `data/rollup_notes.json`(SemiAnalysis) · `_finance` · `_realestate` · `_usa`
- 각 리포트에 **`desc`(접힌 채로 읽는 한 줄)** 를 반드시 넣는다. 제목만으로는 안에 뭐가 들었는지 모른다.
- 기간 기준은 **매체 업로드일**이지 우리가 처리한 날이 아니다.
- 새 편이 기존 리포트의 판단을 뒤집으면 `items`를 고친다. 덧붙이기만 하지 않는다.
- SemiAnalysis 쪽 롤업은 `python scripts/gen_rollup.py`로 두 페이지에 다시 깐다.
  나머지는 해당 대시보드 생성기를 다시 돌리면 반영된다.

### 4. 대장·사이트 갱신

```bash
python scripts/update_card_ledger.py   # 새 카드의 "사이트에 올라온 날" 기록 → NEW 배지 기준
python scripts/gen_site.py             # insight-dashboard.com 빌드 산출물
```

`update_card_ledger.py`를 건너뛰면 NEW 배지가 안 붙는다. 배지 기준은 영상 업로드일이 아니라
**카드가 사이트에 처음 올라온 날**이고, 그 날짜는 대장에만 있다.

허브(`대시보드/Yomianalysis.html`)에 페이지를 새로 세운 경우에만 `python scripts/gen_hub.py`.
**리포트 한 편 때문에 페이지를 새로 만들지 않는다** — 주제 대시보드의 섹션으로 넣는다.

### 5. 커밋·푸시

의미 단위로 나눠 바로 푸시한다. 몰아서 하지 않는다.
`main`에 푸시하면 Cloudflare Pages가 `scripts/gen_site.py`를 돌려 자동 배포한다.

## 마치기 전 점검

- [ ] `check_slim.py`가 FAIL 0인가 (따옴표는 자막에 있는 말만)

- [ ] `gain`·`clash`가 들어갔나 (옛 형식에서 가장 자주 빠지던 둘)
- [ ] 숫자가 전부 원문에 있는 것인가
- [ ] 첫 등장 전문용어에 괄호 설명이 붙었나
- [ ] **주간·월간 리포트를 갱신했나**
- [ ] `update_card_ledger.py`를 돌렸나
- [ ] 종목이 언급됐다면 추천이 아니라는 전제가 유지되는가 (가격·타이밍은 이 체계에 없다)
