# 통합 보고서 쓰기

`대시보드/통합 보고서.html` 은 카드 장이 아니다. **카드 여러 장을 한 물음으로 꿴 글 한 편**이다.
카드가 원문 한 편씩을 답한다면 보고서는 그 답들을 이어 붙인다.

생성기는 `scratchpad/gen_report_dashboard.py` 하나. 그림은 **원본 대시보드 생성기에서 import 해서 쓴다** —
여기서 다시 그리면 한쪽만 고쳐지는 사고가 난다.

## 카드 규칙과 다른 점 넷

| | 카드 (insight-upload) | 보고서 (여기) |
|---|---|---|
| 재료 | 원문 한 편 | 카드 서른 장 + 그 카드가 링크한 변환본 |
| 단위 | 영상·글 하나 | 절 하나 = 물음 하나 |
| 검증 | 인용 `(라벨 L12)` | 숫자 전수 대조 (`check_report.py`) |
| 반론 | `clash` 필수 | 절 안에 유보를 문장으로 |

**보고서는 카드로 쪼개지 않는다.** 절을 카드로 만들면 접히고, 접히면 이어 읽히지 않는다.
층 하나(`top=`)에 `<h3>` 절과 문단으로 쓴다. 2026-08-24에 카드 열한 장으로 쪼갰다가 되돌렸다.

**이 문서는 검증을 맡는다.** 글을 어떻게 세울지는 `doc-structure` 가 정본이다. 앞머리 셋(물음·바탕·축)·목차·비교표·
한계 절은 거기 규칙이고, 여기서는 통합 보고서에만 걸리는 것(전수 대조·숫자 대조·층 등록)을 본다.

## 재료가 원문일 때 — 기본 경로

**새 층은 원문에서 바로 세운다.** 카드를 먼저 만들 필요가 없다. 2026-09-05 에 세운 선단
패키징 층(`sec-pkg`)이 이 경로로 나온 실물이고, 원본은 `insights/reports/pkg-2026-09-05.md`,
배선은 `scratchpad/_pkg_part1.py` 다.

```
0  주제 낱말로 재료 후보를 뽑는다                       scripts/find_materials.py
1  원문을 두세 편씩 나눠 sonnet 에 읽혀 사실표를 받는다   scratchpad/<슬러그>_facts_*.md
2  사실표를 메인이 읽고 절을 세운다                     어긋남·시차·빠진 것이 여기서 보인다
3  초안을 쓴다                                       insights/reports/<슬러그>.md
4  haiku 둘에게 원문 대조를 시킨다                      결과를 frontmatter fixed: 에
5  도해를 그린다(메인)                                 scratchpad/<슬러그>_fig.py
6  생성기에 층을 붙이고 검사기를 전부 돌린다              check_report 에 층 id 등록
7  커밋·푸시                                         깨끗한 체크아웃 빌드로 라이브 확인
```

위임문 둘(사실표·대조)은 `references/위임문.md` 에 그대로 있다. 재료 이름만 갈아 끼운다.

**0번을 건너뛰지 않는다.** 제목으로 훑으면 재료를 놓친다 — 「전력」으로 재 보니 상위 열여덟 편
가운데 열셋이 제목에 그 말이 없었다. `check_cover` 는 이 구멍을 못 막는다. 선언한 재료를 다
썼나만 묻지 찾아야 할 것을 다 찾았나는 안 묻기 때문이다.

```bash
PYTHONIOENCODING=utf-8 python scripts/find_materials.py 패키징 인터포저 CoWoS EMIB packaging
```

나온 목록은 **후보이고 재료가 아니다.** 넘치는 쪽으로 틀리게 만들어 두었으니 사람이 자른다 —
넘치는 것은 자르면 되고 놓친 것은 아무도 모른다. 자른 뒤 남은 것을 frontmatter `labels:` 에
적으면 그때부터 `check_cover` 가 전수를 센다.

**절을 세우는 2번만 메인이 한다.** 절 열셋은 사실표 다섯을 읽고 어긋남을 찾아 나왔다 —
병목이 편마다 뒤집힌 것, 같은 원문이 매출을 두 값으로 적은 것, 저자가 회사 셈법 자체를
깨는 것. 이건 검사기가 봐 주는 자리가 아니다.

**대조 대상은 사실표가 아니라 원문이다.** 사실표를 거쳐 온 값이 원문에 없으면 사실표가
틀린 것이므로, 검사기가 사실표를 믿게 두면 안 된다. `check_report` 의 재료 폴더에
사실표를 넣지 않는다.

**각도 체계는 걷혔다**(2026-08-28, 커밋 `9e36cbd4`). `insights/angles/`·`check_angles.py`·
`structure` 의 원문-각도 레인이 그때 함께 지워졌다. 각도로 층을 세우라는 지시는 낡은 것이다.

## 전수는 기계가 센다

```bash
PYTHONIOENCODING=utf-8 python insights/check_cover.py
```

frontmatter `labels:` 에 적은 재료가 본문에 `(라벨 L12)` 로 한 번이라도 나오나 센다.
**층 등록이 필요 없다** — 새 층이 `labels:` 만 적으면 그날부터 세어진다.

```
C1 FAIL  선언했는데 한 번도 안 쓴 재료      빠뜨린 것이지 덜 중요한 것이 아니다
C2 FAIL  labels 에 없는 라벨로 인용         오타이거나 labels 가 낡았다
C3 WARN  인용이 한 번뿐인 재료              이름만 스치고 근거로 안 썼을 수 있다
```

**FAIL 이 뜨면 절을 늘리지 말고 기존 절에 접어 넣는다.** 2026-09-05 에 선단 패키징 층의
`CPU영문` 이 이 검사에 걸렸고, 영문 원문에만 있던 두 대목을 7절과 13절에 접어 넣어 풀었다.

## 반드시 지킬 것

### 1. 전수인지 먼저 센다

위 「전수는 기계가 센다」를 돌린다. 같은 규칙을 두 곳에 안 적는다.

**카드가 재료인 옛 층**(로봇·수도리무브)은 `labels:` 가 없어 `check_cover` 가 SKIP 한다.
그때는 카드 제목의 낱말이 본문에 나오나 성기게 센다 — 이름이 겹치면 나온 것으로 치므로,
빠짐이 뜨면 그 카드를 열어 무엇이 안 실렸는지 사람이 본다. 새 층은 이 길로 가지 말고
`labels:` 를 적는다.

### 2. 숫자는 기계로 대조한다

```bash
PYTHONIOENCODING=utf-8 python insights/check_report.py
```

본문 글자에 든 수를 전부 뽑아 원문(`content/understanding/**`)과 회사 조사 파일
(`scratchpad/company_facts_*.md`)에 있는지 센다. 회사 사실은 유튜브 원문이 아니라 회사 사이트에서 오므로
조사 파일이 그 값의 출처다. **확인 필요가 0이 아니면
그 값을 원문에서 찾아 고치거나, 예시라고 본문에 밝힌다.** 예시 값(그림에 든 +0.6 같은 것)은
「예시다」라고 적어 두어야 나중에 데이터로 안 읽힌다.

### 3. 용어는 첫 등장에 괄호로 푼다 — 그림 안 글자도 첫 등장이다

보고서는 카드보다 길어서 같은 말이 여러 절에 흩어진다. **그림 안 상자에 먼저 나오면 그 그림 캡션에서
푼다.** 「그리퍼 7 자유도」를 그대로 내보냈다가 지적받았다.

```bash
# 첫 등장 자리에 괄호가 붙었나 훑는다
PYTHONIOENCODING=utf-8 python -c "
import io,re
h=io.open('대시보드/통합 보고서.html',encoding='utf-8').read()
i=h.index('id=\"sec-report\"'); txt=re.sub(r'<[^>]+>','',h[i:h.index('</section>',i)])
for t in ['그리퍼','자유도','어블레이션','제로샷','파인튜닝','백본','VLM','IDM']:
    j=txt.find(t)
    if j>=0: print(('OK ' if txt[j+len(t):j+len(t)+2].strip().startswith('(') else '없음'), t)
"
```

### 4. 값에는 언제 나온 말인지를 붙인다

바탕 원문이 여러 편이면 발행일이 흩어진다. **가격·생산량·시장 규모·「지금 어디까지 왔나」는 시점이 없으면
못 쓰는 값이다.** SemiAnalysis 로봇 원문 넷은 2025-03 부터 2026-06 까지 열다섯 달에 걸쳐 있다.

- 절 안에서 값을 처음 낼 때 **언제 기준인지**를 적는다 — 「2025년 3월 기준」처럼
- 두 원문이 같은 대상을 다르게 말하면 **나중 것을 앞세우고 앞 것을 밝힌다**
- 사실표를 위임할 때 항목마다 발행일과 소제목을 적어 오게 시킨다

### 5. 회사가 처음 나오면 마일스톤을 붙인다

**주요 회사는 첫 등장에서 무엇을 파는 회사인지와 마일스톤을 밝힌다.** 카드는 그 편에서 다룬 것만
적으면 되지만, 보고서는 회사를 가로질러 읽히므로 「이 회사가 언제부터 무엇을 해 온 곳인가」가
없으면 이름만 흘러간다.

- 재료는 **회사 공식 사이트**(소개·블로그·research)가 먼저다. 없으면 1차 보도로 보완하고 출처를 적는다
- 유튜브 진행자가 말한 값과 회사가 밝힌 값이 어긋나면 **둘 다 적고 어긋난다고 쓴다**
- 조사는 위임한다 — 서브에이전트에 회사 다섯씩 나눠 맡기고 `scratchpad/company_facts_*.md` 로 받는다
- 받은 파일은 그대로 믿지 말고 **URL 이 붙었는지, 「공개 안 됨」을 채워 넣지 않았는지** 본다

## 절을 세우는 법

한 절은 **물음 하나**에 답한다. 절 제목이 「A와 B」면 두 절로 나눈다.

순서는 이 차례가 기본이다.

1. 물음 하나와 답이 갈리는 축 (지도 그림)
2. 말 가르기 — 섞여 쓰이는 이름부터 푼다
3. 병목 — 왜 이 물음이 생겼나
4~6. 축이 가른 방식마다 한 절씩
7. 누가 어디 서 있나 (회사 배치)
8~9. 물건과 돈 — 모델 밖에서 막히는 자리
10. 현장에서 확인한 것 — 발표 자료가 못 하는 말
11. 아직 안 풀린 것과 **우리가 검증하지 않은 것**

마지막 절에는 반드시 **한계 문단**을 둔다. 분류가 우리 것인지, 숫자를 검증했는지, 출처가 어디인지.

## 문장 규칙

`korean-readability` 와 `check_prose` 가 그대로 적용된다. 보고서에서 특히 자주 걸리는 셋.

- **「~는 쪽·자리」를 반복하지 않는다**(P15). 회사·기관 이름을 댄다
- **은유를 주어나 서술어 자리에 두지 않는다**(P14·P16). 「돈이 도는지」 → 「회사가 버티는지」
- **기계를 쓴다.** 「직접 낸다」로 끝내지 말고 **무엇이 출력되는지**를 쓴다 —
  「글자로 관절 값 숫자열을 그대로 뱉는다」처럼
