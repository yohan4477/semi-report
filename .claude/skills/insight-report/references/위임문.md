# 위임문 — 사실표 뽑기와 원문 대조

보고서 한 층은 원문을 열 편 넘게 읽는다. 그걸 메인이 읽으면 컨텍스트가 원문 덩어리로
찬다. **원문을 읽어 사실표를 만드는 일은 sonnet, 초안을 원문과 줄 단위로 대조하는 일은
haiku, 절을 세우고 판단하는 일은 메인**이 한다(CLAUDE.md 「위임 모델 선택」).

아래 둘을 그대로 복사해 재료 이름만 갈아 끼운다. 2026-09-05 선단 패키징 층에서 sonnet
다섯·haiku 둘로 돌려 사실표 12편·인용 136건 대조를 어긋남 0으로 끝냈다.

## 빠지면 안 되는 다섯

어느 위임문이든 이 다섯이 들어간다. 하나라도 빠지면 결과를 그대로 못 쓴다.

```

                          sed -n 'NNNp' 로 다시 열어 확인하고 확인했다고 파일 끝에 적어라
```

아무것도 안 아낀다.

## ① 사실표 뽑기 (sonnet, 재료 두세 편씩)

재료를 두세 편씩 나눠 맡긴다. 열두 편이면 에이전트 다섯쯤이다.

```
저장소 루트: C:\Users\y\semianalysis

「<주제>」 보고서를 쓰기 위한 **사실표**를 만든다. 글을 쓰는 것이 아니라 재료를 뽑는 일이다.

## 읽을 파일 (전문을 읽는다)
1. 라벨 `<라벨>` = `<경로>`   (한국어 변환본, 정본)
2. 라벨 `<라벨영문>` = `<경로>`  (영문 원문 — 변환본에 없는 대목만 확인용)

## 뽑을 것 — <주제>에 한정
<주제에 걸리는 항목을 여덟에서 열둘쯤 나열한다. 총정리 편은 주제가 섞여 있으니
   무엇을 뽑고 무엇을 건너뛸지 여기서 못 박는다>

**<옆 보고서가 이미 다룬 주제>는 뽑지 않는다** — 그건 보고서 <번호>의 몫이다.

## 산출 형식
`scratchpad/<슬러그>_facts_<A>.md` 파일 하나로 쓴다. 다른 파일은 만들지 않는다.

# 사실표 A — <라벨> / <라벨영문>

## <라벨> (발행 YYYY-MM-DD)

### <소주제 이름>
- L123-125 | <사실 한 줄. 값이 있으면 값 그대로> | 성격: 공표 / 추정 / 회사 주장 / 저자 판단 | 언제 것: 2026-05

규칙 — 반드시 지킨다:
- <위 「빠지면 안 되는 다섯」을 그대로 붙인다>
- 값은 원문 표기 그대로(단위·범위·근사 포함). 반올림하거나 환산하지 마라
- 같은 값이 두 편에서 다르면 둘 다 적고 다르다고 표시한다
- 「성격」은 원문이 그렇게 말한 것만. 모르면 `불명`
- 말(팟캐스트·인터뷰)이면 화자를 갈라 적고 단서(들었다·확실치 않다)를 원문 그대로 살린다

분량 제한 없다. 답장에는 뽑은 항목 수와 소주제 목록만 적는다.
```

**총정리 편을 맡길 때가 제일 위험하다.** ECTC·ISSCC 처럼 냉각·메모리·광학이 한 편에 섞인
원문은 「뽑을 것」을 좁게 적지 않으면 주제 밖 사실이 절반을 채운다.

## ② 원문 대조 (haiku, 라벨 서넛씩)

초안을 다 쓴 **뒤에** 돌린다. 쓰는 동안에는 못 본다(CLAUDE.md).

```
저장소 루트: C:\Users\y\semianalysis

초안 하나를 **원문과 줄 단위로 대조**한다. 글을 고치는 일이 아니라 어긋난 데를 찾아
목록으로 내는 일이다.

## 대조할 초안
`insights/reports/<슬러그>.md`

이 글의 문장들은 끝에 `(라벨 L줄번호)` 를 달고 있다. **네가 맡는 라벨은 <N>이다.**

- `<라벨>` = `<경로>`
  …

다른 라벨이 붙은 문장은 **건너뛴다.** 다른 에이전트가 맡는다.

## 하는 일
맡은 라벨이 붙은 문장을 전부 찾아, 원문의 해당 줄을 `sed -n 'NNNp' <파일>` 로 열어 넷을 본다.

1. **값** — 숫자·단위·범위가 그 줄에 있나. 반올림·환산·범위 바꿔치기가 있나
2. **귀속** — 누가 한 말인가. 회사 발표를 저자 판단으로, 저자 추정을 공표로 바꾸지 않았나
3. **유보** — 원문의 단서(~로 보인다, 들었다, 추정, 미검증, 예정)를 단정으로 바꾸지 않았나
4. **줄 번호** — 그 줄에 그 내용이 있나. 없으면 ±5줄을 찾아 맞는 번호를 댄다

## 산출 형식
`scratchpad/<슬러그>_check_<N>.md` 하나로 쓴다. 초안 파일은 **고치지 마라.**

## 요약
- 확인한 인용 / 일치 / 어긋남 / 줄 번호 틀림 / 원문 밖

## 어긋난 것
- [라벨 L95] 초안: "…" / 원문: "…" / 무엇이 다른가: 값·귀속·유보 중 무엇 / 고칠 안: "…"

규칙 — 반드시 지킨다:
- **초안 파일을 편집하지 마라.** 보고만 한다
- 값이 맞으면 맞다고 센다. 억지로 어긋남을 만들지 마라
- 검사기를 우회하는 표현을 제안하지 마라. 문체를 고치라고도 하지 마라
- <원문 자체가 어긋난 것으로 의심되는 대목이 있으면 그 줄을 콕 집어 확인시킨다>

답장에는 요약 다섯 줄만 적는다.
```

**팟캐스트가 재료면 화자 대조를 프롬프트에 못 박는다.** 진행자 둘을 섞어 적는 것이 가장
자주 나는 사고다.

## 받은 뒤

대조가 어긋남 0으로 와도 그대로 믿지 않는다. **메인이 서넛을 골라 직접 다시 연다.**
2026-09-05 에 haiku 둘이 136건을 전부 일치로 보고했고, 메인이 넷을 표본으로 확인해
통과했다. 표본에서 하나라도 틀리면 그 에이전트 몫을 통째로 다시 돌린다.

대조 결과는 원본 frontmatter `fixed:` 에 남긴다 — 확정 규칙 G8. `fixed` 가 없는 글은
대조를 안 거친 글이다.

전수는 기계가 센다. `PYTHONIOENCODING=utf-8 python insights/check_cover.py` 가
frontmatter `labels:` 와 본문 인용을 맞춰 보므로, 재료를 선언만 하고 안 쓴 층은 걸린다.

**json 원문을 인용했으면 `scripts/check_jsoncite.py` 도 돌린다.** T번호가 빈 줄이나 파일
끝을 가리키는 것을 전수로 잡는다. 대조 에이전트는 이 사고를 못 잡는다 — 자기도 같은 기준을
모르면 전부 틀렸다고 하거나 전부 맞다고 한다. 실제로 2026-09-05 에 두 에이전트가 같은 층을
놓고 엇갈리게 보고했고, 기계로 세고 나서야 갈렸다.
