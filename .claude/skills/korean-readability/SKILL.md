# 한글 산문 규칙

두 층이 있다. **문체**는 AI가 쓴 티를 없애는 일이고, **이해도**는 읽고 바로 알아듣게 만드는 일이다. 문체만 고치면 글이 매끄러워질 뿐 이해되지는 않는다. 둘 다 해야 한다.

## 1. 용어 — 남기고 괄호로 푼다 (가장 자주 어긴 규칙)

전문용어를 **쉬운 말로 바꾸지 않는다.** 용어는 그대로 두고 **첫 등장에 괄호로 뜻을 붙인다.** 두 번째부터는 용어만 쓴다.

```
정비사업(재건축·재개발)
후분양(다 짓고 나서 분양하는 방식)
이주비 대출(재건축 때 잠시 다른 집으로 옮겨 살 돈을 빌리는 것)
재건축초과이익환수제(재건축으로 오른 값의 일부를 정부가 걷는 제도)
PF(프로젝트 파이낸싱, 건물을 지어 팔아 갚겠다는 조건으로 빌리는 돈)
방통 미장(바닥 난방 배관 위에 시멘트를 붓는 공정)
구배(물이 배수구로 흐르도록 잡는 기울기)
지목이 대(건축물을 지을 수 있는 땅으로 등록된 것)
```

용어를 통째로 치환하면 독자가 나중에 뉴스에서 그 말을 만났을 때 못 알아본다. 이해를 돕자고 한 일이 학습을 막는다.

문서 앞머리에 용어를 몰아넣는 별도 블록은 만들지 않는다. 본문 첫 등장 자리에서 푼다. TOC가 있는 문서만 사용자 CLAUDE.md 규칙대로 TOC 직후에 Glossary를 둔다.

## 1-B. 회계·금융 — 돈이 움직이는 순서로 쓴다

회계 글에서 가장 자주 나는 사고는 **규정 이름을 순서대로 늘어놓고 끝내는 것**이다. 문단 번호와 용어를 다 적었으니 설명한 것 같지만, 읽는 사람은 무슨 일이 벌어지는지 모른다. 규정은 그 일에 붙은 이름표일 뿐이다.

**돈 한 건을 따라간다.** 언제 장부에 들어가고, 무엇 때문에 나중에 바뀌고, 바뀌면 어느 숫자가 움직이는지. 그 순서로 쓴 다음 규정 번호를 괄호로 붙인다.

이렇게 쓰지 않는다:

```
변동대가 (IFRS 15 문단 50~54). 장려금만큼 매출을 깎아 잡는다
제약 (문단 56~58). 되돌아올 가능성이 낮은 금액만 매출에 넣는다
한 시점 인식 (문단 31) · 본인·대리인 구분 (문단 B34~B38)
```

이렇게 쓴다:

```
삼성전자가 스마트폰을 통신사에 넘기는 날, 그 물량을 매출로 잡는다 (문단 31)
그런데 판매장려금(많이 팔아 준 대가로 유통망에 돌려주는 돈)은 분기 실적을
  집계한 뒤에야 정산한다. 매출을 잡는 날에는 얼마를 줄지 아직 모른다
그래서 앞으로 줄 장려금을 추정해 매출에서 미리 깎고, 그만큼을
  환불부채(나중에 돌려줄 돈)로 쌓아 둔다
장려금을 적게 잡으면 그만큼 영업이익이 크게 남는다. 나중에 실제 정산액이
  더 크면 그때 다시 깎인다
```

붙여야 할 것 넷:

- **주어를 회사로.** "변동대가에 해당한다"가 아니라 "삼성전자가 넘기는 날 매출로 잡는다"
- **시차를 말한다.** 회계 쟁점은 거의 다 "언제 잡고 언제 정산하나"의 어긋남에서 나온다. 그 어긋남을 문장으로 적는다
- **어느 쪽으로 틀리는지 적는다.** "추정이 개입된다"로 끝내지 않는다. 적게 잡으면 이익이 커지는지 작아지는지를 쓴다
- **그래서 뒤가 어떻게 되는지.** 그 숫자를 뒤에서 누가 쓰는지 한 줄 붙인다. "나머지 평가 넷이 전부 그 영업이익에서 출발한다"

**검사기로 안 걸린다.** 명사 나열을 자동으로 잡아 보려 했더니 정상 라벨까지 348건이 걸려 쓸 수 없었다(2026-08-17). 이 규칙은 사람이 지켜야 한다. 회계·세무·재무제표 글을 쓰거나 고칠 때 이 절을 먼저 읽는다.

## 2. 이해도

- **한 문장에 정보 하나.** 나열이 셋을 넘으면 문장을 끊는다. 기관 셋과 항목 넷을 한 문장에 쌓지 않는다.
- **주어와 서술어를 붙인다.** 명사 앞 수식이 세 어절을 넘으면 뒤로 뺀다. "X를 Y한 Z" 대신 "Z가 있는데, 그건 X를 Y한 것이다".
- **논리 관계를 드러낸다.** 문장을 그냥 나란히 놓지 말고 그래서·그런데·대신으로 잇는다.
- **압축 명사구를 동사로 푼다.** "상업적 가치가 증가한다" → "장사가 되는 자리가 된다".
- **숫자는 표로, 논리는 문장으로.** 표에 서사를 넣지 않고 문장에 숫자를 쌓지 않는다.

| ID | 패턴 | 처방 |
|---|---|---|
| J-3 | 대시(—) 부가설명이 문장마다 | 쉼표·괄호·문장 분리로. 다만 대시가 "여기부터 부연"을 표시해 스캔을 돕는 자리는 남긴다 |
| C-8 | "A가 아니라 B" 대구 반복 | **문서당 2회까지** — `check_prose` P9가 세는 값이 정본이다 |
| J-1 | 문장 안에서 볼드 2~3개 | 항목 머리말만. 본문 안 중복 강조 제거 |

## 4. 하지 말 것

- 수치·고유명사·직접 인용은 문체 교정 대상이 아니다. 한 글자도 바꾸지 않는다.
- 원문에 없던 비유나 상투구를 윤문하면서 새로 심지 않는다. 빼기만 한다.
- 격식 등급을 올리거나 내리지 않는다. 원문이 평어체면 평어체로 둔다.
- 문체를 고쳤다고 이해도가 좋아졌다고 보고하지 않는다. 다른 작업이다.

## 5. 적용 순서

새 문서를 쓸 때는 처음부터 1·2·3을 같이 적용한다. 이미 쓴 문서를 고칠 때는 **용어(1) → 이해도(2) → 문체(3)** 순으로 간다. 문체부터 손대면 용어와 문장 구조를 그대로 둔 채 표면만 매끄러워진다.

대시보드 카드와 요약 md는 같은 텍스트를 공유하므로 **둘 다 고친다.** 카드는 `scratchpad/gen_*_dashboard.py`의 `CARDS`에 있고, 고친 뒤 생성기를 재실행해야 반영된다.

## 검사

```bash
python3 -c "
import io,sys
s=io.open(sys.argv[1],encoding='utf-8').read()
print('대시', s.count('—'), '/ 볼드', s.count('**')//2 + s.count('<b>'))
" <파일>
```

대시가 **문단 수의 절반**을 넘거나(P8), 볼드가 문단당 2개를 넘으면(P10) 3을 다시 본다.
임계값의 정본은 `insights/check_prose.py`의 `check_density`·`check_bold`다 — 여기 숫자가
그것과 다르면 검사기 쪽이 맞다.

## 6. 번역투 교정 — 논리구조를 지키는 절차

**「번역투 고쳐」를 통째로 넘기지 않는다.** 넘기면 윤문기가 문장을 새로 짜면서 빈 수사를
없던 주장으로 바꾼다. 이게 의미 드리프트고, 사용자가 겪은 「논리구조가 엉망이 된다」의 정체다.

이 저장소에서 실제로 재보면 번역투 표지가 거의 안 나온다. 2026-08-17에 부동산 교차 인사이트
9편 24,376자를 쟀더니 피동·`~에 의해`·`~를 통해`·`~적인`·무생물 주어가 **전부 0건**이었고,
걸린 것은 「A가 아니라 B」 대구 반복 하나(23건)뿐이었다. **없는 병에 약을 쓰지 않는다.**

### 6-1. 고치기 전에 먼저 잰다

```bash
PYTHONIOENCODING=utf-8 python -c "
import io,re,sys
PAT=[('피동 되어/지어진다',r'되어지|지어진|되어진'),('~에 의해',r'에 의해'),
     ('~에 대한/대해',r'에 대(한|해)'),('~에 있어',r'에 있어'),
     ('~를 통해',r'(을|를) 통(해|하여)'),('~것으로 보인다',r'것으로 (보|여겨|판단)'),
     ('가지고 있다',r'가지고 있|갖고 있'),('복수 -들',r'[가-힣]들(이|은|을|의|과|에|도)\b'),
     ('~라고 할 수 있다',r'라고 할 수 있|할 수 있다'),('~적인',r'[가-힣]적인 '),
     ('무생물주어+시키다',r'[가-힣]+(이|가) [가-힣]*시(킨|킬|켰|킨다)'),
     ('「아니라」 대구',r'아니라'),('것이다',r'핵심은|라는 것이다')]
t=''.join(re.sub(r'^---.*?^---','',io.open(f,encoding='utf-8').read(),flags=re.S|re.M)
          for f in sys.argv[1:])
print('%d자' % len(t))
for n,p in PAT: print('%-18s %3d' % (n,len(re.findall(p,t))))
" <파일들>
```

판정:

| 결과 | 처리 |
|---|---|
| 표지 합계가 1,000자당 1건 미만 | **번역투 아니다.** 손대지 않는다. 재작성은 논외 |
| 특정 표지 하나만 튄다 | 그 표지가 든 **문장만** 고친다 |
| 여러 표지가 고루 나온다 | 문서 단위로 `humanize-korean` 정밀 모드(진단→윤문→finalize) |

「아니라」 대구의 상한은 `check_prose` P9가 정한다 — **문서당 2회까지**다. 3회 이상인 문서만
대상으로 하고, 고칠 때도 2회까지 남긴다. P9가 안 뜨는 문서는 손대지 않는다.

### 6-2. 문장 단위로만 고친다

- **한 번에 한 문장.** 문단을 통째로 다시 쓰지 않는다
- 대구를 풀 때는 뒤집지 말고 **결론만 남긴다.** 「A가 아니라 B다」를 「B다. A는 아니다」로
  바꾸면 부정이 남아 같은 틀이다. 그냥 「B다」로 단언한다
- 문서에서 대구를 **한 개는 남긴다.** 전부 없애면 강조가 평평해진다

### 6-3. 손대지 않는 것

문단 순서 · 절 제목(`## 주장` 등) · 인용 줄번호와 앵커 · 숫자 · 고유명사 · 직접 인용 ·
front matter(`section`·`as_of`·`sources`) · 카드 경계.

### 6-4. 고친 뒤 반드시 확인

```bash
PYTHONIOENCODING=utf-8 python scripts/build_all.py --check     # 검사기 다섯 FAIL 0
git diff --stat <파일>                                          # 바뀐 줄 수 = 고친 문장 수 수준
```

`check_cite`가 인용한 줄에 그 숫자가 있는지 보므로, 숫자나 인용이 흔들리면 바로 FAIL이 뜬다.
**구조가 깨졌는지는 눈이 아니라 이 두 줄로 판정한다.** `git diff --stat`의 변경 줄이 고치기로
한 문장 수보다 훨씬 많으면 그건 윤문이 아니라 재작성이다 — 되돌리고 다시 한다.
