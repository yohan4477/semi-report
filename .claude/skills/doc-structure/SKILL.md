# 문서를 구조로 세우기

절을 늘어놓으면 문서가 아니라 목록이 된다. 2026-08-28에 자금조달 층을 열여섯 절로
쓰고 「도해도 목차도 없고 단순 나열이라 비교가 한눈에 안 된다, 구조가 명시되지도
않았다」는 지적을 받았다. 그때 빠져 있던 다섯이 이 문서의 규칙이다.

## 어느 룰이 어디에 있나

**세우는 법은 글의 길이와 무관하게 같다.** 원문 한 편을 옮긴 카드든 열네 편을 꿴 보고서든
물음 하나·축·목차·절=물음·비교표·도해·한계는 그대로다. 그래서 그 넷은 전부 여기 있다.

갈리는 것은 셋뿐이고 전부 **검증**이다 — 세우는 법이 아니라 거짓이 안 새게 막는 법이다.

```
                  원문 하나짜리                     여러 편을 꿴 글
근거를 어디서       그 원문 줄 번호 하나 (L153)        여러 원문. 편마다 라벨이 붙는다
전수의 뜻          원문의 주장·사실·사건이 다 실렸나    바탕 문서 전부가 본문에 나오나
시차              없다. 한 시점의 글                발행일이 흩어진다. 값마다 언제 것인지
```

```
세우는 법          이 문서
원문 하나짜리 검증   docs/AI Engineer 대시보드 — 만드는 규칙.md
여러 편 검증        insight-report 스킬 — 전수 대조 · check_report · 층 등록
```

**같은 규칙을 두 곳에 적지 않는다.** 적히는 순간 한쪽이 낡는다 — 실제로 AI Engineer 규칙이
생성기 주석과 문서 둘에 있었고 주석 쪽이 형식을 거꾸로 적고 있었다.

## 앞머리 셋 — 본문 전에 반드시 선다

```
물음    이 글이 답하는 물음 하나. 「~에 대하여」가 아니라 물음표가 붙는 문장
바탕    재료가 무엇 몇 편이고 기간이 언제부터 언제까지인가
축      물음을 몇 묶음으로 따라가나. 묶음 이름을 여기서 밝힌다
```

축이 없으면 독자는 절을 하나씩 읽고 스스로 묶어야 한다. **묶는 일을 독자에게 넘기지
않는다.** 축은 둘이나 셋이고 넷을 넘으면 축이 아니라 목록이다.

본보기 — 「돈이 어디서 막히나 · 파는 회사는 얼마를 부르나 · 사는 회사는 얼마를 쓰나」.
셋이 한 물음(AI 인프라 자금조달)을 서로 다른 자리에서 답한다.

## 목차 — 절이 여섯을 넘으면 필수

절 제목을 축 묶음으로 접어 링크로 낸다. 절이 열여섯인데 목차가 없으면 독자는 어디까지
왔는지를 못 잡는다.

**꼴은 손으로 짜지 않는다.** 보고서 층은 `scratchpad/_rep_toc.py` 의 `toc_html` 을 부르고,
절 제목은 같은 파일의 `sec_title` 을 부른다. 번호·줄바꿈·들여쓰기·색은 그 함수가 정한다.

```python
import _rep_toc as rt
GROUPS = [('무엇이 막히나', 1, 3), ('파는 회사', 4, 11), ('사는 회사와 남은 벽', 12, 16)]
rt.toc_html('fund', '이 층은 물음 하나를 세 묶음으로 따라갑니다 — …', GROUPS, TITLES)
```

나오는 꼴은 이렇다. 대단원은 「1. 2. 3.」, 그 아래 절은 「①②③」이고 절은 한 줄에 하나씩이다.

```
1. 무엇이 막히나
   ① 병목이 돈으로
   ② 용어
```

상세 규약은 `docs/글과 도해 — 확정 규칙.md` §4 「차례」가 정본이다. 손으로 짠 층은
`_rep_toc.check_toc` 가 물고 생성기가 멈춘다.

앵커를 걸려면 절 제목에 `id` 가 있어야 한다. 생성기의 `sec()` 가 번호를 세어 붙인다 —
목차 번호와 본문 번호가 같은 함수에서 나와야 어긋나지 않는다.

## 절 하나 = 물음 하나

제목이 「A와 B」면 절이 둘이다. 실제로 「한계와 계획」 절 하나에 이 모델이 못 재는 것과
다음에 할 일이 섞여 있었고, 「측정한계」와 「후속계획」으로 나눠야 했다.

제목에 성격 값(사실·전망·발언)이나 원문 장치 이름(「하나의 차트」)을 쓰지 않는다. 그건
모양이지 물음이 아니다.

## 나열 대신 대비 — 표 한 장이 절 다섯을 이긴다

같은 물음을 여럿에게 물어 한 표에 세운다. 절을 순서대로 읽어야 보이던 대비가 한 화면에
선다.

```
행    비교 대상 (회사·제도·시나리오)
열    모두에게 같은 물음. 「파는 것 · 부르는 값 · 남는 몫 · 돈을 어디서 · 물릴 수 있나」
빈칸  원문에 값이 없으면 「—」. 채우지 않는다
```

**표에는 「언제 것 · 성격」 열을 반드시 둔다.** 이것이 이 스킬에서 가장 자주 빠지는
것이다. 표는 값을 나란히 놓아 비교를 만드는데, 그 나란함이 공표치와 추정치와 저자 제안을
같은 무게로 보이게 만든다. 실측 — 자금조달 층에서 수를 든 문장 67개 중 51개에 누가 한
말인지가 없었고 32개에 때가 없었다.

```
2026-03 · 공표(지수)     회사나 기관이 낸 값
2026 Q1 · 추정          분석가 모델이 낸 값
2026-06 · 제안          저자가 하라고 주장하는 것. 회사 계획이 아니다
```

## 도해 — 절이 말로만 가면 붙인다

한 그림은 하나만 말한다. 그리는 규칙은 `insight-figure` 가 정본이다. 여기서는 자리만
정한다.

```
축을 세운 직후    전체 지도 하나 — 누가 누구에게 무엇을 주나
값이 움직이는 절   시계열 하나 — 점은 원문 값만, 사이 선은 이어 본 것이라고 캡션에 밝힌다
```

**없는 값을 그리지 않는다.** 축 눈금 하나(`$1.50`)를 원문에 없는 값으로 넣었다가
`check_report` 가 잡았다. 그림 속 글자도 전부 대조 대상이다.

## 마지막 절은 한계

무엇을 검증하지 않았나, 절을 세운 방식이 누구 것인가, 재료 기간 밖은 왜 답하지 않나.
이것이 없으면 세운 구조가 이미 답인 것처럼 읽힌다.

## 검사

```bash
PYTHONIOENCODING=utf-8 python insights/check_report.py            # 숫자가 원문에 있나
PYTHONIOENCODING=utf-8 python insights/check_prose.py             # 문체·번역투(P19 포함)
PYTHONIOENCODING=utf-8 python scratchpad/check_fig.py             # 도해 배치
PYTHONIOENCODING=utf-8 python scratchpad/check_fund_cover.py      # 바탕이 전수로 실렸나
PYTHONIOENCODING=utf-8 python scratchpad/check_claim_marks.py sec-fund   # 주체·때가 남았나
```

마지막 둘은 층마다 표식을 새로 적어야 한다 — 바탕 편수와 층 id 가 다르기 때문이다.
`check_claim_marks` 는 거칠게 센다. 숫자를 줄이는 것이 목적이 아니라 **어느 문장이
주체 없이 값만 들고 있는지** 를 보여 주는 도구다.

## 흔한 사고

| 증상 | 원인 | 처방 |
|---|---|---|
| 「단순 나열이다」 | 축을 안 밝혔다 | 앞머리 셋 |
| 「한눈에 비교가 안 된다」 | 절로만 썼다 | 비교표 |
| 「어디까지 왔는지 모르겠다」 | 절이 여섯을 넘는데 목차가 없다 | 목차 |
| 「이게 사실이야 추정이야」 | 표에 성격 열이 없다 | 「언제 것 · 성격」 |
| 「그림이 원문보다 세게 말한다」 | 없는 값을 그렸다 | insight-figure 규칙 1 |
| 「절이 두 말을 한다」 | 제목이 「A와 B」다 | 절을 둘로 |
