# 건강 인사이트 작성법

`대시보드/건강 대시보드.html`은 독립 아카이브다. 생성기는 `scratchpad/gen_health_dashboard.py` 하나뿐이고, HTML은 생성물이라 손으로 고치지 않는다.

## 1. 이 페이지가 다른 이유

- **통합 인사이트와 잇지 않는다.** `insights/notes/`에 노트를 만들지 않고 검증 대장에도 넣지 않는다
- **카드 단위는 영상이 아니라 주제다.** 다른 대시보드는 1영상 = 1카드지만 여기는 다르다
- **그림이 본문에 들어간다.** 몸 이야기는 말로만 하면 안 남는다

## 2. 새 영상이 들어왔을 때

```bash
py -3.13 scratchpad/ytsub.py <영상ID>      # scratchpad/yt_subs/<ID>.txt 로 자막 전문
```

자막을 읽고 **주제를 센다.** 그다음 판단이 갈린다.

| 상황 | 할 일 |
|---|---|
| 새 주제다 | 카드를 새로 만든다 |
| 이미 있는 카드와 같은 이야기다 | **카드를 늘리지 않는다.** 그 카드의 포인트를 보강하고 `meta`의 출처 편수와 `links`에 영상을 더한다 |
| 한 영상에 주제가 여럿이다 | 주제 수만큼 쪼갠다. 다만 인접한 주제는 묶는다 |

주제를 쪼갤 때 과하게 나누지 않는다. 2026-08-17에 EP.155 한 편을 5장으로 쪼갰다가 "1·2·3은 다 염증"이라는 지적을 받고 3장(만성 염증 2 + 뇌·수면 1)으로 합쳤다. **한 카드가 한 논증을 끝내야 한다.**

요약 전문은 `content/health/<채널>/[YYMMDD] 제목 - 화자 (n부).md`에 남긴다. 카드에서 「요약본 전문」으로 건다.

## 3. 카드 스키마

`scripts/card_lib.py`의 슬림 카드를 쓴다. 필요한 키만 적는다.

```python
{
  'section': SEC_INFLAM,                 # (id, 번호, 제목, 한 줄 설명)
  'topic': ('market', '염증 · 면역'),      # 주제 칩
  'title': ...,                          # 카드 제목. 판단 하나를 문장으로
  'gain': ...,                           # 열면 무엇을 알게 되는지
  'meta': META_EP155,                    # [화자, 채널·회차, 날짜, 출처 편수]
  'quote': ...,                          # 전문에서 그대로 가져온 한 마디
  'note': ...,                           # 곁다리. 진단·처방이 아니라는 문구를 여기 둔다
  'links': LINKS_EP155,
  'slim_oneliner': ...,                  # 논지 하나
  'slim_points': [...],                  # 각 항목은 <b>소제목.</b>으로 연다
  'figs': [(anchor, 제목, SVG, 캡션)],     # anchor = 몇 번째 포인트 뒤
  'slim_stats': [(값, 라벨)] * 4,
  'clash': [(누구, 반론)],                 # 가설·본인 유보·오해 방지
}
```

출처가 여럿이면 `meta`의 마지막 칸을 「출처 2편」으로 올리고 `links`에 영상을 더한다.

## 4. 문장 규칙

`korean-readability`를 먼저 읽는다. 그 위에 이 페이지에서 실제로 걸린 것들을 더한다.

**원문에 없는 말을 지어내지 않는다.** 이 세션에서 세 번 걸렸다.

| 내가 쓴 말 | 문제 | 고친 말 |
|---|---|---|
| "소화가 절반쯤 끝난 상태" | 「절반」은 전문에 없는 수량 | "몸이 할 소화를 미리 해 둔 상태" |
| "염증을 계속 켜 둔다" | 스위치 비유가 전문에 없다. 뭘 켜는지 모른다 | "그 반응을 몇 년씩 끌고 간다" |
| 기전 없이 결론만 | "왜 많이 먹게 되는가"가 빠졌다 | 힘이 안 들고 단맛이 바로 올라와 더 먹을 준비를 한다 |

**빠진 고리를 남기지 않는다.** 결론을 쓰면 그 앞의 기전을 반드시 같이 쓴다. 검사기가 못 잡는 유일한 결함이다.

**한 줄 요약에 논지를 쌓지 않는다.** 한 가지만 말하고 나머지는 포인트로 내린다.

밀도는 `check_prose`가 센다. P8 대시 개수, P9 「A가 아니라 B」 2회까지, P10 볼드 밀도, P11 한 문장 쉼표 4개.

뜻이 안 닿는 자리도 잡는다. **P12는 무엇을 먹는지 안 밝힌 조건절**(「먹으면」·「마시면」 앞에 목적어가 없을 때), **P13은 숫자 없이 정도만 말하는 주장**(「크게 늘었다」에 값이 없을 때)이다. 2026-08-17에 "GLP-1은 먹으면 장에서 나오는 호르몬이다"를 내보내고 사용자가 "뭘 먹으면 나온다는 거냐"고 물어서 붙였다. 주어가 있어도 통과시키지 않는다 — 그 문장에도 「GLP-1은」이 있었지만 무엇을 먹는지는 여전히 없었다.

전부 WARN이지만 **건강 대시보드는 0건을 유지한다.**

## 5. 그림 규칙

**도식이 아니라 해부도다.** 박스와 화살표로 흐름만 그리면 이 페이지의 이유가 없어진다.

- **인라인 SVG만.** 외부 이미지 0, 데이터 URI 0
- 색은 직접 쓰지 말고 `card_lib`의 붓을 class로 받는다 — `organ` `organ2` `vessel` `vein` `body` `fat` `cell` `bad` `good`. 다크모드가 이 변수로 돌아간다
- **잘린 면에는 `hatch`나 `hatch-w`를 덮고 절단 가장자리에 `cut`을 준다.** 윤곽선만 있으면 단면인지 겉모습인지 구분이 안 된다
- **화살표를 그림 안에서 꼬지 않는다.** 순서가 있으면 해부 위에 번호를 찍고 설명은 오른쪽 열에 세운다
- 라벨은 열을 맞추고 리더선은 수평·수직으로만
- **한 그림에 한 논지.** 몸통과 동맥 확대를 한 그림에 넣었다가 라벨 자리가 없어 둘로 쪼갠 이력이 있다
- 긴 문장은 viewBox를 넘는다. 두 줄로 끊는다

### 외부 애셋을 쓸 때

- **CC0·퍼블릭도메인 우선.** CC BY는 카드 각주에 출처와 라이선스를 적는다. **CC BY-SA는 쓰지 않는다** — 페이지 라이선스에 영향을 줄 소지가 있다
- 받아온 SVG는 `scratchpad/health_assets.py`에 출처와 변경 내역을 적어 두고 상수로 보관한다. 생성기에서 `<g transform="translate(x,y) scale(s)">`로 앉힌다
- **색은 fill만 바꾸면 안 된다.** 트레이싱된 도해는 윤곽이 `stroke="#010101"` 같은 검정으로 박혀 있어, 선까지 `--fig-line`으로 갈지 않으면 다크모드에서 배경에 묻힌다. 라벨(`<text>`)은 떼고 우리 말로 다시 단다
- Servier Medical Art는 CC BY 4.0이지만 **SVG를 제공하지 않는다**(PPTX·PNG뿐)
- bioicons는 라이선스별로 폴더가 갈려 있어 고르기 쉽지만 장기 종류가 적다. 정밀 해부도(DBCLS)는 500KB를 넘어 인라인에 못 쓴다
- Wikimedia는 연속 요청에 429를 준다. 검색과 다운로드를 몰아 치지 말고 필요한 파일만 받는다

## 6. 내보내기

```bash
PYTHONIOENCODING=utf-8 py -3.13 scratchpad/gen_health_dashboard.py
```

그림을 건드렸으면 브라우저에서 넘침을 확인한다. 로컬 서버를 띄우고 페이지를 연 뒤 아래를 실행해 `ok`가 전부 true인지 본다.

**함정 둘을 먼저 통과해야 검사가 성립한다.**

1. 첫 화면은 「주제 고르기」이고 그때 모든 `section`이 `hidden`이다. 숨은 요소의 `getBBox()`는 0을 돌려주므로, 타일을 누르지 않고 재면 **넘쳐도 통과로 나온다.** 2026-08-17에 이걸로 헛검증을 했다.
2. `transform`이 걸린 그룹의 자식은 로컬 좌표를 돌려준다. 자식 하나하나를 바깥 viewBox와 비교하면 멀쩡한 그림이 넘친 것으로 잡힌다. **루트 `<svg>`의 bbox 하나만 본다** — 거기에 자식 변환이 이미 반영돼 있다.

```js
// 1) 「전체 보기」 타일을 눌러 본문을 띄우고 2) 카드를 모두 펴고 3) 루트 bbox로 잰다
document.querySelector('.stile.is-all, .sec-pick button').click();
await new Promise(r=>setTimeout(r,300));
document.querySelectorAll('.ucard:not(.is-open) .uc-head').forEach(h=>h.click());
// 숨은 채로 재면 전부 0이 나와 조용히 통과한다. 그래서 여기서 먼저 터뜨린다.
if([...document.querySelectorAll('section[id]')].some(s=>s.hidden)) throw new Error('섹션이 숨어 있다 — 측정 무효');
[...document.querySelectorAll('.uc-fig svg')].map((s,i)=>{
  const V=s.getAttribute('viewBox').split(' ').map(Number), b=s.getBBox();
  return {fig:i+1, ok:(b.x>=-2 && b.y>=-2 && b.x+b.width<=V[2]+2 && b.y+b.height<=V[3]+2),
          w:Math.round(b.width), h:Math.round(b.height), vb:V.slice(2)};
});
```

타일 선택자(`.stile`)는 공용 부품(`dash_common`)이 바뀌면 같이 바뀐다. 2026-08-17에도 한 번 바뀌어 스니펫이 헛돌았다. **`secHidden`이 하나라도 true면 그 측정은 버린다.**

그다음 검사기 다섯을 전부 돌린다. FAIL 0이어야 푸시한다.
