# 구조화

이 스킬이 맡는 것은 **케이스 구조** 하나다. 답이 안 보이는 큰 물음을 쪼개 어디부터
팔지 고른다. 절차 본문은 `references/케이스-구조.md` 에 있다. 그 파일을 열고 따른다.

## 입력이 원문이면 이 스킬이 아니다

```
물음이 먼저 있다 (왜·어디부터·되나·얼마나)   →  여기. references/케이스-구조.md
원문이 먼저 있다 (파일 경로·링크·붙여 넣은 글) →  노트 한 장이면 insight-note
                                             층 하나면 insight-report 의 사실표 경로
카드 올리기·요약                             →  insight-upload
```

**원문 각도 레인(A)은 걷혔다**(2026-08-28, 커밋 `9e36cbd4`). `insights/angles/` 스물다섯 편과
`check_angles.py`·`references/원문-각도.md` 가 함께 지워졌다. 고르는 데는 빨랐는데 세우는
데는 줄 번호와 저자 논지가 모자랐다. **각도를 뽑으라는 지시는 낡은 것이다** — 원문에서
층을 세우는 길은 `insight-report` 의 사실표 경로이고, 그쪽이 줄 번호와 화자를 처음부터
들고 간다.

## 이름을 찾을 때는 grep 이 아니다

이름을 찾을 때는 `entity-search` 를 부른다. 개체 사전이 별칭과 영문 표기를 알고, 답에
줄 주소와 영수증이 붙는다 — 실측이 엔비디아 grep 743줄 대 색인 1,385줄이었다.

```bash
PYTHONIOENCODING=utf-8 python scripts/q.py 앤트로픽 --cap 20
```

가지에 근거를 붙일 때 이것을 쓴다. 줄마다 시제·연도·확실도·낡음이 붙어 나오니
「임팩트 크고 이미 확실함」과 「불확실함」을 나누는 그 판정에 바로 먹인다.

**개념으로 묻는 물음은 못 찾는다.** 이름을 모르면 `insights/notes/` 의 `topics` 를
훑거나 사람에게 이름을 묻는다.

## 컷을 어디서 얻나

**케이스 구조의 등뼈는 원문이 아니라 물음이다.** 재료가 모자라면 원문으로 돌아가지 말고
물음을 더 쪼갠다. 컷 셋은 이렇게 나온다.

```
대상   행위자·이해관계자 컷. entity-search 로 그 이름이 나온 줄을 모아 온다
때     시간 컷. 원문 발행일이 흩어지므로 값마다 언제 것인지를 같이 들고 온다
성격   가지에 붙인 근거가 사실인지 저자 가정인지 — 안 갈라 두면 가정이 사실로 굳는다
```

가지 하나가 원문 여러 편을 물고 늘어져 층 한 편이 될 것 같으면 거기서 멈추고
`insight-report` 의 사실표 경로로 넘긴다. 이 스킬은 어디를 팔지까지만 고른다.
