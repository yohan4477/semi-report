# 구조화

레인이 둘이다. 하는 일도 산출도 다르다. **먼저 어느 레인인지 가른다.**

## 레인 가르기

입력이 정한다. 취향이 아니다.

```
원문이 먼저 있다 (파일 경로·링크·붙여 넣은 글)   →  A 원문 각도
물음이 먼저 있다 (왜·어디부터·되나·얼마나)        →  B 케이스 구조
둘 다 있다                                      →  A 를 먼저 하고, 그 산출을 B 의 재료로
둘 다 아니다 (카드 올리기·요약·노트)              →  이 스킬이 아니다. insight-* 로 간다
```

**가른 것을 한 줄로 적고 시작한다** — 「A 레인. 입력은 `content/.../[260708] ....md`」.
안 적으면 원문을 받아 놓고 이슈 트리를 짜거나, 물음을 받아 놓고 표를 채우게 된다.

| | A 원문 각도 | B 케이스 구조 |
|---|---|---|
| 입력 | 원문 1편 | 물음 1개 |
| 하는 일 | 글이 담은 것을 각도별로 가른다 | 물음을 쪼개 어디부터 팔지 고른다 |
| 범위 | 글 한 편 안에 갇힌다 | 글 여러 편을 가로지른다 |
| 판단 | 안 한다. 성격만 단다 | 판단이 산출물이다 |
| 산출 | `insights/angles/<yymmdd>-<슬러그>.md` | 보고서. 저장소에 안 쌓는다 |
| 절차 | `references/원문-각도.md` | `references/케이스-구조.md` |

**절차 본문은 레인 파일에만 있다.** 고른 레인의 파일을 열고 그대로 따른다.
**두 파일을 같이 열지 않는다** — A 의 각도 이름과 B 의 컷 표가 한자리에 있으면 둘 다
메뉴가 된다. 두 레인이 각각 「목록에서 고르지 마라」로 경고하는 그 사고다.

## 둘이 공유하는 것

셋뿐이다. 나머지는 레인마다 다르다.

```
1  저장소 루트 C:\Users\y\semianalysis. 콘솔이 cp949라 파이썬 실행에 PYTHONIOENCODING=utf-8
2  설계 SSOT  docs/superpowers/specs/2026-08-27-구조-도구-design.md
   본보기      docs/superpowers/specs/2026-08-27-구조-도구-본보기.md  — 한 바퀴 돈 실물
3  미리 만든 목록에서 고르지 않는다. A 는 각도를 글에서 자라게 하고, B 는 컷을 먼저
   지어낸 뒤 표와 대조한다. 훑고 고르면 그 순간 목록이 메뉴가 된다
```

## A 에서 B 로 넘어가는 자리

각도를 쌓는 이유가 이것이다. **A 의 등뼈가 그대로 B 의 재료가 된다.**

```
대상   B 의 행위자·이해관계자 컷이 여기서 나온다
때     B 의 시간 컷이 여기서 나온다. 시계열을 A 에서 중첩시키지 않는 이유
성격   가지에 붙인 근거가 사실인지 저자 가정인지 — 안 갈라 두면 가정이 사실로 굳는다
```

거꾸로도 쓴다 — B 를 펴다가 어느 가지에 자료가 비면, 그 대상을 다루는 원문을 A 로 뽑는다.

