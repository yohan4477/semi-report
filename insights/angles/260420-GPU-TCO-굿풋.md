# GPU 클러스터 TCO 와 굿풋 이론

저자는 Jordan Nanos·Bryan Shan·Cheang Kang Wen(§표지). GPU 시간당 임대료 하나만
비교하는 관행을 깨고, 저장장치·네트워크·지원·장애손실·구축·디버깅까지 합친
총소유비용(TCO)과, 그중 장애손실을 재는 굿풋(Goodput) 이론을 계산기로 공개한
글이다. 값 대부분이 SemiAnalysis 의 시나리오 가정과 모델 산출이라 `가정`·`추정`이
많다 — §8 이 밝히듯 모든 입력값·기본값은 2025년 8월 시점 가격 데이터 스냅샷이다.

## 굿풋 복구 방식

굿풋은 처리량 중 실제로 쓸모 있는 작업만 걸러낸 값이다 — GPU 가 버스에서
이탈하거나 NCCL(GPU 간 통신 라이브러리)이 멈추거나 체크포인트 저장 직전
메모리 부족(OOM)이 나면 "돌아가고 있어도 나쁜 처리량"이다  [GPU 클러스터 · — · §3 · 개념]
클러스터·작업 규모가 커지면 개별 노드 장애 빈도가 늘고 MTBF(장애와 장애 사이
평균 시간)가 줄어, 대형 작업일수록 굿풋 손실이 커진다        [GPU 클러스터 · — · §3 · 추정]
클러스터의 80%를 쓰는 작업이 재시작(10~15분)하면 그 시간 전부 + 마지막
체크포인트 이후 계산이 통째로 날아간다                       [GPU 클러스터 · — · §3 · 추정]

좋은 사업자의 조건 셋.
```
① 깨끗한 데이터센터를 노련한 운영팀이 관리한다                 [GPU 클라우드 시장 · — · §3 · 추정]
② 장애를 빠르게 식별한다(가능하면 사전 예측)                   [GPU 클라우드 시장 · — · §3 · 추정]
③ 예비 노드 풀과 물량 보장으로 빠르게 복구한다                 [GPU 클라우드 시장 · — · §3 · 추정]
```

굿풋 손실을 계산하는 3가지 시나리오.
```
콜드 스페어   사업자가 관리하는 예비 노드, 수리·교체까지 대기
             → 몇 시간~며칠, 최악 시나리오                                [GPU 클라우드 시장 · — · §3 · 개념]
핫 스페어    고객 또는 상위 사업자가 관리, 유휴 노드로 즉시 재시작
             → 상위 사업자는 전체의 2~6%를 예비 풀로 상시 확보              [GPU 클라우드 시장 · — · §3 · 사실]
장애 허용    작업이 멈추지 않고 계속 실행
             → 단일 노드 추론에서는 표준, 학습에서는 아직 미성숙            [GPU 클라우드 시장 · — · §3 · 추정]
```

세 시나리오 모두 쓰는 입력값 — 장애 식별 시간(t_id) · 체크포인트 주기(t_chkpt) ·
학습 재시작 시간(t_init) · 노드 수리·교체 시간(t_repair, MTTR) · 블라스트 반경
(b_radius, 예: 8기 서버 단위 또는 NVL72 의 64기 단위) · 장애 빈도(MTBF)
                                                    [굿풋 계산 모델 · — · §3 · 개념]

기준으로 본 민감도 분석이다(§10).

| 추론 사업자 | 토큰 판매가 | 100만 토큰당 3달러(블렌디드) | — | §10 | 가정 |
