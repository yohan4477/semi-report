## 이 문서가 주장하는 것

10년 경력의 ML 컴파일러 엔지니어가 1월엔 사람이 직접 설계한 퍼저로 몇 주에 걸쳐 LLVM 버그 5개를 찾았는데, 5월엔 모델 세대교체와 서브에이전트 오케스트레이션만으로 며칠\~몇 시간 만에 수백 건의 컴파일러 버그를 찾아냈다. 코드를 직접 읽게 하는 방식이 퍼징보다 훨씬 빨랐고, 원자적 저장 명령이 조용히 데이터를 손상시키는 버그처럼 퍼징으로는 찾기 어려운 유형도 섞여 있었다. 이 속도를 사려면 하루 오후에 1만 달러 이상이 들지만, 저자는 "5개월 전엔 불가능했던 일이 이제는 그냥 비쌀 뿐"이라며 예산 격차가 곧 능력 격차가 되는 시대를 진단한다.

## 수치

- 저자는 2026년 5월 어느 하루 오후 AI 에이전트를 컴파일러 코드에 풀어 1만 달러 이상을 지출했다 ([260528] L47)
- 1월 개인 프로젝트에서는 몇 주 만에 instcombine 버그 5개를 찾아 직접 고쳤다 ([260528] L68)
- ptxas 퍼징은 3일 만에 미스컴파일 40개, 1주일 뒤엔 80개로 늘었다 ([260528] L90)
- 서브에이전트 50개를 동시에 투입하자 버그 발견 속도가 4분에 1개꼴로 올라갔다 ([260528] L159)
- x86 백엔드에서는 발견 속도가 분당 거의 2개로 더 빨라졌다 ([260528] L178)
- 검토한 약 30건의 에이전트 발견 버그 중 하나가 원자적 저장 명령을 비원자적 명령 2개로 바꾸는 버그였다 ([260528] L180)

## 저자가 추정이라고 밝힌 것

- ptxas 퍼저가 1월 LLVM 실험보다 쉬웠던 이유를 ChatGPT 5.2\~5.5 세대교체로 추정할 뿐 확실한 근거는 대지 않는다 ([260528] L111)
- x86 백엔드 발견 속도가 빨라진 게 AMDGPU 백엔드가 특별히 버그투성이란 뜻은 아니라는 판단도 저자의 해석일 뿐이다 ([260528] L178)
- 6월 1일 추가 업데이트의 "비용 5분의 1" 수치는 저자 스스로 오차 범위가 매우 크다고 밝힌 예비 실험 결과다 ([260528] L13)

## 이 문서가 반박하거나 뒤집는 것

- "AI 에이전트는 사람을 보조할 뿐 대체하지 못한다"는 통념에 반례 — 저자는 자신이 만든 가치보다 AI가 만든 가치가 더 컸던 첫 경험이라고 명시한다 ([260528] L223)
- 정교하게 설계된 퍼저가 무작정 코드를 읽는 것보다 항상 효율적이라는 가정을 뒤집는다 — 몇 시간에 1개이던 퍼저 발견 속도가 코드 판독 에이전트에선 4분에 1개까지 빨라졌다 ([260528] L159)
- 폐쇄소스 컴파일러는 소스 없이 깊은 버그를 찾기 어렵다는 전제도 흔들지만, ptxas(바이너리만 있음)엔 아직 적용해보지 못해 미검증으로 남는다 ([260528] L224)
