# 씨모어 밸류체인 추출 위임문

## 하는 일

씨모어 전사 원문 한 편을 읽고, 그 안에 나온 **밸류체인(가치사슬)**을 단계 사슬로 뽑아 JSON 하나로 적는다.

## 밸류체인이란 (이 작업 기준)

원자재·투입에서 최종 소비자까지 **돈과 물건이 지나가는 순서**. 진행자가 "밸류체인을 까 본다"고 말한 편이 대표적이지만, 그렇게 말하지 않아도 다음이 있으면 체인이다.

- 산업의 단계를 순서대로 늘어놓고 각 단계에 회사를 붙인 대목 (예: 우라늄 채굴→변환→농축→발전→폐기물)
- 돈이 누구를 거쳐 누구에게 가는지 설명한 대목 (예: 제약 유통 — 제약사→도매→약국→PBM→보험사)
- 어느 단계가 문지기(gatekeeper)·병목이라 마진을 가져간다고 판단한 대목

**아니면 안 뽑는다.** 종목 하나를 뜯어본 회차, 시황 회차, 투자 습관 회차에는 체인이 없을 수 있다. 없으면 `"chains": []` 로 적는다. 억지로 만들지 않는다.

## 절대 규칙

1. **원문에 없는 것은 안 적는다.** 네가 아는 업계 지식으로 단계를 채우거나 회사를 보태지 않는다. 진행자가 말한 것만.
2. **모든 항목에 줄 번호를 붙인다.** `L45~L47` 꼴. 줄 번호는 **파일 전체를 1부터 센 번호**다 — frontmatter(`---` 로 감싼 머리)와 빈 줄도 포함해서 센다. `sed -n '45,47p' <파일>` 로 확인해서 그 줄에 그 내용이 실제로 있어야 한다. **적기 전에 표본 세 개는 반드시 sed 로 확인한다.**
3. **진행자 말과 사실을 섞지 않는다.** 판단(`judgment`)과 사실(`desc`)을 필드로 나눠 적는다.
4. 회사 이름은 원문 표기 그대로. 자동 자막이 뭉갠 이름(예: "카밀코"→카메코)은 `name` 에 바른 표기, `raw_name` 에 원문 표기를 남긴다.
5. 숫자는 원문에 있는 것만. 단위 포함.

## 산출 형식

파일 하나당 JSON 하나. 경로: `insights/chains/extract/<원문 파일명에서 .md 뗀 것>.json`

```json
{
  "file": "content/understanding/채널 씨모어/raw/2025-06-29-nuclear-valuechain.md",
  "slug": "2025-06-29-nuclear-valuechain",
  "date": "2025-06-29",
  "title": "원문 frontmatter 의 title 그대로",
  "chains": [
    {
      "industry": "원전·SMR",
      "chain_name": "우라늄 연료 사슬",
      "chain_lines": "L40~L120",
      "summary": "진행자가 이 체인을 왜 깠는지 한 문장",
      "stages": [
        {
          "order": 1,
          "name": "우라늄 채굴",
          "desc": "원문이 이 단계를 설명한 내용. 사실만.",
          "lines": "L44~L46",
          "companies": [
            {"name": "카자톰프롬", "raw_name": "카자톰프롬", "country": "카자흐스탄",
             "role": "세계 우라늄의 43%를 담당", "numbers": "점유율 43%", "lines": "L52~L54"}
          ],
          "bottleneck": "high",
          "bottleneck_why": "농축 권한을 가진 나라가 많지 않아 아무나 못 들어온다",
          "bottleneck_lines": "L60~L62",
          "judgment": "진행자가 이 단계를 두고 내린 판단. 없으면 빈 문자열"
        }
      ],
      "notes": "체인 전체에 걸린 진행자 판단·경고. 없으면 빈 문자열"
    }
  ]
}
```

- `bottleneck` 은 `"high" | "mid" | "low" | ""` 넷 중 하나. **원문이 진입장벽·독과점·문지기라고 말한 단계만 high.** 네 짐작으로 매기지 않는다. 근거가 없으면 빈 문자열.
- `country`·`numbers`·`judgment` 는 원문에 없으면 빈 문자열.
- 한 편에 체인이 둘 이상이면 `chains` 배열에 여럿 넣는다 (예: 큰 체인 + 발전 단계를 확대한 하위 체인).
- 하위 체인이면 `"parent_chain": "우라늄 연료 사슬"`, `"parent_stage": "발전"` 을 chain 에 덧붙인다.

## 금지

- 원문에 없는 회사·숫자·단계 보태기
- 줄 번호 어림잡기 (확인 안 한 번호는 적지 않는다)
- 요약을 매끄럽게 하려고 원문이 안 한 인과("그래서 ~ 때문에")를 만들기
- JSON 밖에 설명 늘어놓기
