안녕하십니까. 시니어 기술 전문가 관점에서 이번 OpenAI의 할라피뇨(Jalapeño) 인퍼런스 칩 발표의 핵심 구조와 제원, 그리고 그러한 설계를 채택한 기술적 배경을 분석해 드리겠습니다.

이 칩은 철저하게 '엔드 유저의 사용 경험(마지막 토큰이 나오는 시간)'과 '전력 대비 효율(Joule당 토큰)'에 초점을 맞춘 추론 전용 가속기입니다.

### 1. 할라피뇨 핵심 구조 및 하드웨어 제원

현재 공개되거나 추정되는 할라피뇨의 물리적 제원은 다음과 같습니다.

* **공정 노드:** TSMC N3 (N3P 추정)
* **메모리:** 삼성 HBM4 (추정)
* **호스트 CPU:** AMD 튜린(Turin) 클래스 x86 CPU
* **열 설계 전력(TDP):** 700W (엔비디아 블랙웰의 1200W 이상 대비 매우 높은 전력 효율)
* **스케일업 네트워크:** 브로드컴 Tomahawk 6 스위치 (칩당 600Gbps), ESUN 프로토콜 (200Gbps 인터커넥트)
* **토폴로지:** 하프 플래튼(Half-flattened) 2레벨 Clos 구조 (최대 16개 랙, 2048개 칩까지 확장)

### 2. 주요 아키텍처 설계와 채택 이유

할라피뇨 아키텍처의 가장 큰 특징은 하드웨어의 이론적 최대 성능(Flops)보다 '실제 달성 가능한 유효 성능'을 끌어올리는 데 집중했다는 점입니다.

#### 2.1 NUMA 스타일 로컬 HBM 슬라이스

가장 눈에 띄는 설계는 통합 메모리 서브시스템을 버리고, 각 가속기 코어마다 전용 HBM 슬라이스를 할당한 NUMA(Non-Uniform Memory Access) 스타일의 채택입니다.

설계 채택 이유:
HBM 대역폭이 아무리 넓어도 여러 코어가 동시에 메모리에 접근하면 경합(Contention)이 발생합니다. 데이터가 제때 연산기에 도착하지 못하는 '지연 현상'이 발생하면 연산 코어는 그대로 멈춰 있게 됩니다. 이를 해결하기 위해 HBM을 잘게 쪼개어 각 연산부에 전용으로 할당하고 전용 저지연 버스로 연결했습니다. 특히 추론에서 가장 큰 병목을 일으키는 KV 캐시 데이터를 이리저리 옮기지 않고 로컬에 머물게 하여 처리 속도를 극대화했습니다.

[통합 HBM 구조의 한계]
연산 코어 A ──┐
연산 코어 B ──┼── 병목 및 경합 발생
연산 코어 C ──┘   (데이터 도착 지연)
│
[통합 HBM]

[할라피뇨의 NUMA 스타일 구조]
연산 코어 A ──── 전용 로컬 HBM
연산 코어 B ──── 전용 로컬 HBM
연산 코어 C ──── 전용 로컬 지연 버스
(경합 제거 및 KV 캐시 로컬화 달성)

#### 2.2 다크 실리콘(Dark Silicon)의 적극적 활용

OpenAI 설계팀은 "다크 실리콘이 유휴 가속기보다 저렴하다"는 철학을 아키텍처에 반영했습니다. 다크 실리콘이란 칩 내부에서 현재 사용되지 않아 전원이 차단된 영역을 뜻합니다.

설계 채택 이유:
LLM 추론 워크로드는 초안 생성(Draft)과 검증(Verify), 또는 사전채우기(Pre-fill)와 디코딩(Decode)의 비율이 모델과 상황에 따라 계속 변합니다. 기존 하드웨어 업계는 사전채우기용 칩과 디코딩용 칩을 물리적으로 분리하는 방식을 썼지만, 이는 특정 워크로드가 줄어들면 랙 전체가 노는(Idle) 자원 낭비를 초래합니다.
할라피뇨는 모든 연산과 IO를 단일 칩에 균형 있게 집어넣고, 당장 쓰지 않는 기능 블록의 전원을 꺼버리는 방식을 택했습니다. 하드웨어의 범용성을 유지하면서 전력 효율을 극대화하기 위함입니다.

[워크로드 분리 방식의 문제점]
사전채우기 전용 칩 (100% 가동)
디코딩 전용 칩 (대기 상태 = 자원 낭비)

[할라피뇨의 다크 실리콘 접근법]
단일 칩 내부:
[사전채우기 블록] -> 활성화
[디코딩 블록] -> 전원 차단 (다크 실리콘)
(워크로드 변화 시 즉각적인 전환 가능)

#### 2.3 스케일업(Scale-up) 네트워크 설계

데이터센터 레벨에서 128개의 할라피뇨 칩이 하나의 스케일업 도메인(랙 단위)으로 묶이며, 브로드컴의 ESUN 기술을 통해 최대 2,048개의 칩이 하나의 거대한 추론 인프라로 동작합니다.

설계 채택 이유:
LLM 추론은 파라미터 크기가 수백 기가바이트를 넘어가므로 단일 칩에 적재가 불가능합니다. 칩 간의 데이터 이동 지연이 전체 사용자 대기 시간을 결정짓기 때문에, 대규모 모델(Kimi K2.5 등)을 병렬로 분산 처리하면서도 마치 하나의 거대한 칩처럼 작동하게 하려면 600Gbps급의 고대역폭 스위치와 저지연 토폴로지(Clos)가 필수적이었습니다.

### 3. 개발 방법론: AI를 활용한 9개월 설계 주기

전통적으로 새로운 반도체 아키텍처를 설계하고 테이프아웃(Tape-out)하기까지는 최소 2~3년이 소요됩니다. 그러나 할라피뇨는 이 과정을 9개월로 단축했습니다.

채택 이유 및 방식:
OpenAI는 하드웨어 설계 과정(RTL 작성 등)에 자체 보유한 GPT-3 클래스 이상의 대형 언어 모델을 적극 투입했습니다. 백지상태에서 레거시 호환성에 얽매이지 않고, AI가 AI를 위한 칩을 코딩하는 방식을 통해 한정된 인력으로 단기간에 루빈(Rubin) 클래스에 필적하는 고성능 칩을 구현해냈습니다. 기존 상용 칩들의 '점진적 개선' 방식이 아닌 '극단적 최적화'를 달성하기 위한 공학적 결단이었습니다.
