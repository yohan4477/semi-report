### 에이전틱 AI 플랫폼

이 글은 초기 로컬 에이전트 구동 방식과 최근 등장한 클라우드 기반 에이전트 플랫폼을 대비하여, 컴퓨팅 수요가 어떻게 폭발적으로 증가하는지 분석합니다.

**①초기 모델의 한계는 무엇인가**
초기 에이전틱 AI(오픈 클로, 헤르메스 등)는 사용자가 직접 하드웨어와 환경을 관리해야 하는 진입 장벽이 있었습니다. 사용자는 메인 PC의 보안 위협을 피하고자 별도의 맥 미니(Mac Mini)를 구매하여 샌드박스 환경을 구축했습니다. 하지만 이 방식은 전력 유지, 인터넷 연결, VPN 네트워킹 등을 개인이 모두 통제해야 하므로 대중화되기 어려웠습니다.

**②그록 봇이 파는 가치는 무엇인가**
최근 출시된 그록 봇(Grok bot)은 사용자가 신경 써야 할 모든 인프라 관리를 클라우드 가상 머신(VM)으로 넘겨버린 '쉬운 버튼(Easy Button)'입니다. 설치 즉시 클라우드에 독립된 VM이 할당되며, 구글 캘린더나 피그마 같은 업무 도구가 미리 연동된 샌드박스 환경을 제공합니다. 보안과 네트워킹은 서비스 제공자가 책임집니다.

**③대중화가 서버 수요를 어떻게 키우는가**
이러한 편의성은 일반 대중을 에이전틱 AI 시장으로 끌어들입니다. 한 명의 사용자가 여러 개의 에이전트를 가동할 때마다 클라우드 내에 수많은 가상 머신과 호출이 발생합니다. 이는 더 이상 로컬 데스크톱(맥 미니) 판매가 아닌, 데이터센터 내 서버 CPU 및 GPU에 대한 막대한 수요 창출로 직결됩니다.

### 에이전틱 CPU

원문은 AI 워크로드를 처리하는 중앙처리장치의 역할을 기업 조직에 빗대어 세 가지로 나눕니다.

**①천재를 돕는 호스트 노드 CPU는 무엇인가**
비싼 몸값을 자랑하는 '천재(GPU)' 곁에서 끊임없이 일거리를 물어다 주는 '비서' 역할입니다. 이 CPU는 GPU가 연산을 쉬지 않도록 코어당 속도가 매우 빨라야 하며, GPU와 직접 통신할 수 있는 일관성(Coherency) 연결 기술이 필수적입니다. 코어 수보다는 단일 코어의 성능과 데이터 전달 속도가 핵심입니다.

**②잡무를 쳐내는 에이전틱 CPU는 무엇인가**
GPU가 뱉어낸 무수한 보조 작업(웹 스크래핑, SEC 공시 자료 수집 등)을 처리하는 '실무 부서' 역할입니다. 이 작업을 호스트 노드 CPU가 맡으면 GPU가 멈추게 되므로, 다수의 코어(128~288개)를 가진 별도의 CPU 무리가 필요합니다. 기업이 예산에 따라 저렴한 주니어 직원을 대거 고용하거나, 숙련된 중간 관리자를 고용하듯 코어당 비용(TCO)과 작업 성격에 맞춰 설계됩니다.

**③일반 목적 CPU의 역할은 무엇인가**
운영체제(OS)를 돌리거나 기본적인 데이터베이스를 관리하는 '시설 관리자' 혹은 '안내원' 역할입니다. 특화된 성능보다는 범용적인 클라우드 업무 환경을 유지하는 기본 바탕이 됩니다.

### 랙 스케일과 오케스트레이션

하드웨어 단위가 개별 칩에서 서버 랙(Rack) 단위로 커지면서 밸류체인과 소프트웨어의 역할이 변하고 있습니다.

```mermaid
flowchart LR
  A[칩 제조사] -->|CPU 랙 공급| B[클라우드 사업자]
  B -->|가상 머신 대여| C[플랫폼 제공자]
  C -->|소프트웨어 구독| D[일반 사용자]

```

**①클라우드 사업자의 구매 방식은 어떻게 달라지는가**
인텔과 AMD 같은 칩 제조사는 더 이상 단일 칩이 아닌, 성능 특화 랙(P-rack)과 효율 특화 랙(E-rack) 형태의 '랙 스케일(Rack Scale)' 솔루션을 팝니다. 하이퍼스케일러(클라우드 사업자)는 각자 유치하려는 AI 워크로드의 성격에 맞춰 특정 스펙의 랙을 대량으로 구매합니다.

**②에이전틱 AI 밸류체인은 어떻게 흐르는가**

1. **칩 제조사 (AMD, 인텔 등):** 에이전틱 CPU, 호스트 노드 CPU 등을 랙 단위로 설계하여 클라우드 사업자에게 팝니다.
2. **클라우드 사업자 (하이퍼스케일러):** 칩 제조사로부터 랙을 구매해 인프라를 구축하고, 플랫폼 제공자에게 가상 머신(VM)과 컴퓨팅 파워를 임대합니다.
3. **플랫폼 제공자 (그록 등):** 클라우드 자원을 빌려 사용자 친화적인 에이전틱 AI 소프트웨어를 구축하고 최종 소비자에게 팝니다.
4. **일반 사용자:** 인프라 관리 없이 플랫폼에 비용을 지불하고 에이전트를 활용합니다.

*(※ 원문에는 각 밸류체인 단계별 마진율이나 참여자 간의 구체적인 교섭력에 대한 언급이 없어 이 글에서는 다루지 않습니다.)*

**③오케스트레이션 소프트웨어는 왜 필요한가**
성격이 다른 하드웨어(고속 GPU, 대용량 GPU, P-코어 CPU, E-코어 CPU 등)가 데이터센터에 혼재하게 되면서, 주어진 과제를 가장 적합하고 저렴한 하드웨어에 배분하는 스케줄링이 중요해졌습니다. 엔비디아 다이나모(Nvidia Dynamo), 모듈러(Modular), 김렛 랩스(Gimlet Labs) 등이 이 오케스트레이션 층위에서 비용 최적화 경쟁을 벌이고 있습니다.

### 논의의 한계

**①원문이 추측한 숫자는 무엇인가**

* **그록 봇 구독료:** 월 200달러 (2026년 8월 대담 기준 공표치)
* **미래 컴퓨팅 수요:** 1,000만 명의 사용자가 각각 100개의 에이전트를 구동하여 약 10억 개의 코어 수요가 발생할 수 있음 (대담자 Austin의 미래 시나리오 추정치)

**②원문에 없는 밸류체인 정보는 무엇인가**
원문은 클라우드 환경을 주축으로 서술하며, 일반 엔터프라이즈 기업들이 에이전틱 CPU 랙을 클라우드를 거치지 않고 직접 온프레미스(사내 구축형)로 구매할 것인지에 대한 확정적 결론을 내리지 않습니다. 또한, OpenAI나 Anthropic 등 파운데이션 모델 개발사들이 실제로 범용 CPU와 에이전틱 CPU에 워크로드를 어떤 비율로 배분하고 있는지에 대한 내부 데이터는 검증되지 않은 추측 영역으로 남겨두었습니다.
