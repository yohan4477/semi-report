### 1. 한두 문장으로 이 회차의 기술적 요지

OpenAI가 브로드컴(Broadcom)과 협력해 공개한 첫 자체 추론 전용 ASIC 할라피뇨(Jalapeño)는 범용 GPU의 고정 오버헤드를 걷어내고 전력 및 지연 시간 최적화에 집중한 칩입니다. 단일 토큰 예측(Single-token)만으로도 엔비디아의 블랙웰(GB200/GB300) 대비 **전력당 처리량(Tokens/kW) 1.5~1.9배, 종단간 지연 시간(Latency) 1.7~3.6배 개선**을 입증하며 AI 설계 루프를 통한 초고속 칩 개발의 시작을 알렸습니다.

---

### 2. 설계 지표를 무엇으로 잡았고 왜 그 둘인지

설계의 양대 핵심 지표는 전력당 처리량(Throughput per Kilowatt, mixed tokens/s/kW)과 인터랙티브 지연 시간(Time-Between-Tokens, TBT / End-to-End Latency)입니다.

| 핵심 설계 지표 | 선택 이유 및 배경 |
| --- | --- |
| 전력당 처리량<br>

<br>(Tokens/kW) | **데이터센터 전력(Power Wall)이 절대적인 물리적 병목**<br>

<br>서버 랙 공간이나 칩 구매 비용보다 사용 가능한 전력(MW/GW)이 AI 서비스 확장 한계를 결정하므로, 단순 피크 FLOPS가 아니라 '1kW당 뽑아내는 유효 토큰 수'가 사업 경제성을 좌우합니다. |
| 토큰 간 생성 간격<br>

<br>(TBT / Latency) | **에이전트(Agentic) 워크로드 및 체감 반응 속도 극대화**<br>

<br>수십~수백 번의 추론 스텝을 직렬로 밟아야 하는 에이전틱 작업에서는 토큰 간 지연 시간(TBT)이 누적되어 병목이 됩니다. 이를 밀리초 미만(Sub-millisecond) 수준으로 낮추는 것이 핵심입니다. |

### 3. HBM 대역폭을 다 쓰지 못하는 이유와 그 해법

#### (1) 대역폭을 다 쓰지 못하는 원인

단순 HBM 이론 대역폭(128개 칩 기준 1PB/s 이상)만 계산하면 사용자당 초당 1,000~2,000 토큰(투기적 디코딩 적용 시 5,000~10,000 토큰)이 나와야 하지만, 실제 칩은 이에 크게 못 미칩니다.

* **긴 메모리 접근 경로(Long-latency paths)**
* **단일 통합 메모리 하위 시스템에서의 경합(Contention)**
* **전역 메모리 펜스(Global Memory Fences) 오버헤드로 인한 연산 유닛의 유휴(Starvation)**

#### (2) 할라피뇨의 아키텍처 해법

* **슬라이스(Sliced) 메모리·연산 구조:** 연산 코어와 HBM을 여러 슬라이스로 분할하여 각 코어가 로컬 메모리에 초저지연으로 접근하도록 설계.
* **전용 컬렉티브 네트워크(Dedicated Collective Network):** 슬라이스 간 예측 가능한 데이터 교환을 온칩 전용 네트워크로 처리하여 GPU식 캐시 계층 경합 제거.
* **비순차 실행(Out-of-Order) 코어 + L1 캐시/프리페칭:** 메모리 대기 지연을 효과적으로 은폐.
* **AI 생성 최적화 커널:** 어텐션(Attention) 및 MoE 커널을 AI로 최적화하여 전문가가 작성한 기존 커널 대비 1.5~1.8배 빠른 속도 달성.

```
[ Traditional GPU ]                [ Jalapeño Sliced Architecture ]
+----------------------------+     +-------------+ +-------------+
| Shared Memory Subsystem    |     | Slice 0     | | Slice 1     |
| (High Contention / Fences) |     | [Core][HBM] | | [Core][HBM] |
+--------------+-------------+     +------+------+ +------+------+
               |                          |               |
        +------+------+                   +-------+-------+
        | Compute CU  |                           | (Dedicated Collective Net)
        +-------------+                   +-------+-------+
                                          | Slice 2 ...   |

```

### 4. 프리필(Prefill)과 디코드(Decode)를 왜 한 칩에 몰았는지

최근 업계 트렌드인 P/D 분리(Prefill-Decode Disaggregation)를 따르지 않고 단일 하드웨어 풀로 통합 유지했습니다.

* **동적 트래픽 변동에 따른 용량 낭비(Stranded Capacity) 방지:**
실제 프로덕션 환경에서는 긴 프롬프트(Prefill 위주)와 긴 출력(Decode 위주)의 비율이 시시각각 변합니다. 물리적으로 프리필 전용 서버와 디코드 전용 서버를 쪼개놓으면 비율 변화 시 한쪽 하드웨어가 놀게 됩니다.
* **KV 캐시 전송 오버헤드 제거:**
프리필 노드에서 생성된 거대한 KV 캐시를 네트워크를 통해 디코드 노드로 복사하는 네트워크 레이턴시 및 대역폭 비용을 원천 차단합니다.
* **위상별 전력 게이팅(Phase-based Gating):**
동일 칩 내에서 프리필 시에는 연산 엔진을 최대 가동하고, 디코드 시에는 미사용 연산 블록을 전력 게이팅하여 전력 효율을 유지합니다.

### 5. 스케일업 도메인 구성과 네트워크 규격

할라피뇨는 랙 단위의 긴밀한 스케일업(Scale-up)과 데이터센터 단위의 스케일아웃(Scale-out)을 명확히 이원화했습니다.

```
[ 2,048-ASIC Scale-out Domain ] (27 EFLOPS / 432 TiB)
  │  ▲
  │  └── 200 GB/s Global Interconnect (Broadcom Tomahawk 6 Switch 계층)
  ▼
[ 128-ASIC Scale-up Domain ] (단일 랙/팟 로컬 풀)
  │  ▲
  │  └── 600 GB/s Low-latency Local Interconnect
  ▼
[ 단일 Jalapeño ASIC ]
  ├─ 공정: TSMC 3nm (N3)
  ├─ 연산 성능: 13.4 PFLOPS (MXFP4)
  ├─ 메모리: 216 GiB HBM4 (6 스택, 15.4 TB/s)
  └─ 전력: 700W TDP (실측 550W 이하)

```

*(회차 밖 배경지식: HBM4 베이스 다이는 삼성전자 공급망 협력 관련 보도가 있으며, 글로벌 스케일아웃은 브로드컴의 51.2T/102.4T급 Tomahawk 6 스위치 실리콘 기반 표준 이더넷/로컬 패브릭 아키텍처가 결합됩니다.)*

### 6. 벤치마크에서 나온 결과와 그 비교의 한계

#### (1) 주요 실측 결과 (SemiAnalysis InferenceX 벤치마크 기반)

* **비교 대상:** NVIDIA GB200 (1,200W), GB300 (1,400W)
* **테스트 모델:** GPT-OSS 120B, DeepSeek R1 (670B MoE, MXFP4), Kimi K2.5 (1T MoE)
* **지표별 수치:**
* **전력당 혼합 처리량:** GB200/GB300 대비 **1.5배 ~ 1.9배 향상**
* **종단간 지연 시간(Latency):** **1.7배 ~ 3.6배 단축**
* **최소 TBT(토큰 생성 주기):** 0.69 ~ 1.44 ms 달성 (GB 시리즈는 1.87 ~ 5.90 ms로 **2.7~4.1배 빠른 속도**)
* **GB 최고 TBT 동일 기준 처리량 비교(Matched-TBT):** DeepSeek R1 기준 **최대 104.3배**, Kimi 기준 **56.1배** 격차



#### (2) 비교의 한계 및 주의점

1. **정격 전력(TDP) 기준 정규화:**
결과치는 칩의 정격 TDP(할라피뇨 700W vs GB200 1.2kW, GB300 1.4kW) 기준으로 환산되었습니다. 할라피뇨의 실측 소비 전력은 550W 이하이나, 엔비디아 시스템의 실측 전력이 비공개라 대등한 실측치 비교가 아닙니다.
2. **단일 토큰(Single-Token) vs 다중 토큰(MTP/Speculative):**
할라피뇨는 순수 단일 토큰 생성으로 측정되었고, 비교 대상인 엔비디아 베이스라인은 다중 토큰/투기적 디코딩이 포함된 결과와 비교되었습니다. *(반대로 할라피뇨에 투기적 디코딩을 적용하면 3~5배의 추가 여력이 존재함을 의미하기도 함)*
3. **차세대 칩(Vera Rubin)과의 미비교:**
벤치마크 대상이 블랙웰(GB200/GB300) 중심이며, 테이프아웃 시기가 비슷한 엔비디아의 차세대 '베라 루빈(Vera Rubin)'과의 정면 비교 데이터는 아직 부족합니다.
4. **엔지니어링 샘플 한계:**
실제 100MW~GW급 대규모 양산 배치가 이루어졌을 때의 수율, 랙 패키징 열 관리, 드라이버 안정성 등 운영상의 변수는 아직 검증 단계입니다.

### 7. 첫 RTL 부터 테이프아웃까지 9개월이 뜻하는 것

통상 첨단 공정(3nm)의 대형 AI 칩 개발은 아키텍처 정의부터 테이프아웃(Tape-out)까지 최소 18~24개월 이상 소요됩니다. 할라피뇨가 9개월 만에 테이프아웃을 완료한 것의 함의는 다음과 같습니다.

1. **AI 지원 칩 설계(AI-Assisted EDA) 루프의 실현:**
OpenAI의 내부 LLM(Codex 등)을 RTL 작성, 테스트벤치 검증(Verification), 타이밍 클로저, 커널 최적화 전반에 직접 투입하여 설계 반복 주기를 압축했습니다.
2. **검증된 ASIC 파트너십의 분업 효과:**
복잡한 피지컬 디자인, SerDes, 패키징 및 고속 인터커넥트 IP는 수십 년간 축적된 브로드컴(Broadcom)의 ASIC 실행 파이프라인을 그대로 활용하고, OpenAI는 LLM에 특화된 디지털 로직과 소프트웨어 계층에만 집중했습니다.
3. **반도체 산업 패러다임 변화:**
거대 AI 랩이 범용 GPU 제조사의 로드맵에 종속되지 않고, 자신의 모델 요구사항에 맞춘 맞춤형 실리콘을 소프트웨어 배포에 가까운 속도로 빠르게 시장에 내놓을 수 있음을 증명했습니다.
