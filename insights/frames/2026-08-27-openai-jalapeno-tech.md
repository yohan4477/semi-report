### 설계 철학

**① 사용자 경험을 어떤 지표로 측정했는가?**
칩 설계의 최우선 목표인 사용자 경험을 '첫 토큰 생성 시간'이 아닌 '마지막 토큰 도달 시간(종단 간 지연 시간)'으로 정의했습니다. 연산이 얼마나 빨리 시작되느냐보다 최종 결과물을 얼마나 빨리 완성해서 넘겨주느냐가 실제 서비스 품질을 결정하기 때문입니다.

**② 성능과 전력 소모를 어떻게 조율했는가?**
속도와 전력 소모는 서로 상충합니다. 단순히 전력을 더 부어 속도를 올리는 식의 설계를 피하기 위해, 요청당 에너지(줄당 토큰 수)를 핵심 지표로 삼았습니다. 단일 성능 수치 대신 파레토 곡선을 통해 한쪽을 높일 때 다른 쪽이 어떻게 변하는지를 설계 단계부터 측정하고 검증했습니다.

### 메모리 병목

**① 대역폭이 넓어도 처리량이 떨어지는 이유는 무엇인가?**
통합 메모리 구조에서는 여러 가속기가 하나의 거대한 메모리 풀을 공유합니다. 칩 자체가 최신 HBM의 막대한 물리적 대역폭을 갖추고 있어도, 네트워크 위에서 서로 데이터를 차지하려는 경합이 발생하면 연산에 필요한 데이터가 제때 도착하지 않습니다. 데이터가 오기를 기다리며 연산기가 멈춰 서면 전체 하드웨어 활용률이 급락합니다.

**② 경합을 막기 위해 메모리 배치를 어떻게 바꿨는가?**
Jalapeño는 NUMA(가속기마다 자기 몫 메모리를 따로 두는 방식) 구조를 도입했습니다. 모든 가속기가 고효율·저지연 전용 버스를 통해 자신만의 국소 HBM 슬라이스에 접근합니다.

```mermaid
flowchart LR
    subgraph 메모리 할당 방식 — 통합 공유형
        공유가속기1(가속기) --> 단일통합(통합 HBM)
        공유가속기2(가속기) --> 단일통합
        단일통합 --> 지연발생(데이터 대기)
    end
    subgraph 메모리 할당 방식 — 국소 전용 NUMA
        전용가속기1(가속기) --> 개별할당1(전용 HBM)
        전용가속기2(가속기) --> 개별할당2(전용 HBM)
        개별할당1 --> 즉시공급(대기 없음)
        개별할당2 --> 즉시공급
    end

```

### 다크 실리콘

**① 작업 부하가 상황마다 달라지는 원인은 무엇인가?**
추론 과정에서 '추측 해독' 기법을 쓰기 때문입니다. 작은 모델이 여러 토큰을 한 번에 추측해서 던지면(Draft), 큰 모델이 그중 맞는 것을 골라냅니다(Verify). 사용자 요청이나 모델 설정에 따라 추측과 검증 작업의 비율은 시시때때로 변합니다.

**② 실리콘을 끄는 것이 가속기를 놀리는 것보다 나은 이유는 무엇인가?**
작업별로 칩을 쪼개면(예: 사전 채우기 전용 랙, 해독 전용 랙) 작업 비율이 달라질 때 한쪽 랙 전체가 통째로 쉬게 됩니다. OpenAI는 하나의 칩이 모든 작업을 처리할 수 있도록 컴퓨팅, 메모리 대역폭, I/O를 균형 있게 설계했습니다. 당장 안 쓰는 회로 구역의 전원을 끄는 것(다크 실리콘)이 칩 하나를 통째로 놀리는 것보다 저렴하고 유연합니다.

### 기회비용

**① 설계 시 면적보다 우선한 기준은 무엇인가?**
실리콘 바닥 면적을 차지하는 한계비용보다, 특정 기능을 뺐을 때 수요를 감당하지 못해 겪는 기회비용(후회 요소)을 더 무겁게 뒀습니다. 한정된 칩 크기 안에 모든 것을 넣을 수는 없으므로, 아키텍처 팀은 당장 포기하면 치명적인 기능 위주로 남기고 나머지는 다음 세대 칩으로 넘기는 결단을 내렸습니다.

**② 왜 자사 모델 전용이 아닌 범용 칩을 만들었는가?**
알고리즘은 계속 진화합니다. 자사의 특정 모델 구조에만 맞게 칩을 하드코딩하면 극한의 성능을 뽑을 수는 있지만, 모델 아키텍처가 바뀌는 순간 칩이 무용지물이 됩니다. GPT OSS부터 Kimi까지 다양한 오픈소스 모델을 모두 소화하도록 설계해 향후 발생할 알고리즘 변화에 대비했습니다.

### 사양과 연결망

**① 개별 칩의 전력 소모와 공정은 어떠한가?**

* **공정:** TSMC N3 계열 (Hot Chips 공표)
* **전력:** 700W TDP (Hot Chips 공표)
* **선택 이유:** 경쟁 제품인 Blackwell(약 1200W)처럼 전력 소비를 극단적으로 끌어올려 절대 성능을 높이기보다, 설계 철학에 맞춰 '전력 대비 토큰 처리량'을 극대화하는 수준에서 열 설계 전력을 묶었습니다.



**② 단일 랙과 전체 시스템의 연결 규모는 어떠한가?**

* **단일 랙 (스케일업):** 128개 칩 연결, 600 Gbps Broadcom Tomahawk 6 스위치 (Hot Chips 공표)
* **전체 시스템 (스케일업):** 2,048개 칩(16랙) 연결, 200 Gbps ESUN 통신 (Hot Chips 공표)
* **선택 이유:** 국소 메모리를 쓰면 칩 밖으로 데이터를 보낼 때 복잡도가 오릅니다. 이를 랙 내부의 초고속망과 랙 간의 광역망 등 2계층으로 나누어, 2048개 칩이 하나의 거대한 메모리 풀처럼 작동하게 만들면서도 물리적 연결 비용과 대역폭을 타협했습니다.



### 한계

**① 검증 환경에서 부족했던 조건은 무엇인가?**
Jalapeño의 성능을 입증한 Inference X 벤치마크는 8K 입력, 1K 출력이라는 비교적 짧은 컨텍스트 환경에서 진행되었습니다(공표치). 수백만 단위의 초장문 컨텍스트나 에이전트 기반 작업(AgentX) 등 부하가 극심한 환경에서의 성능 저하 여부는 아직 검증되거나 공개되지 않았습니다.

**② 회차에서 추측이나 미해결로 남겨둔 대목은 무엇인가?**
HBM4의 공급사가 삼성일 것이라는 점과 시스템 단위 설계를 Celestica가 맡았다는 점은 팟캐스트 진행자와 외부 분석가의 추정치입니다. 또한 광역 스케일업에 쓰인 '절반 평탄화 2계층 Clos 토폴로지'의 정확한 네트워킹 원리와 구조는 회차 안에서 다루지 못했습니다.
