# 수도리무브 카드 만들기 — 위임 규격

영상 한 편을 받아 파일 셋을 만든다. **생성기를 돌리지도, 커밋하지도 않는다.** 그건 메인이 한다.

## 받는 것

- 영상 ID 하나. 자막 전문은 `scratchpad/yt_subs/<ID>.txt`
- 메타(제목·업로드일·길이·조회수·설명란)는 `scratchpad/_sudo_subs.json` 에서 그 ID 항목
- 설명란(`desc`)에 챕터 목차와 논문·회사 링크가 있다. **자막이 자동 인식이라 회사·모델 이름이
  깨져 있으므로 고유명사는 반드시 설명란과 링크로 맞춘다.** 자막에 「로다」로 나와도 설명란이
  Rhoda AI 면 Rhoda AI 라고 쓴다

## 만드는 것 셋

### ① 변환본 — `content/understanding/피지컬AI/[YYMMDD] <짧은 제목>.md`

```markdown
# [YYMMDD] <짧은 제목>

> 출처: sudoremove 유튜브 「<원제>」(YYYY-MM-DD, N분, 진행 JB·JC). 자동 자막 전문을 **요약**한
> 것이며 전문 재수록이 아니다. 원문 https://youtu.be/<ID> · SemiAnalysis 코퍼스와 별개의 제3자
> 해설이고, 투자 판단 근거로 쓰지 말 것.

## 한 줄 요약
(3~5문장. 무엇을 다뤘고 결론이 무엇인지)

## <주제별 소제목>
- **소제목.** 내용. 숫자와 고유명사를 남긴다.
(소제목 2~4개, 항목 총 12~20개)

## <대조표가 있으면>
| | A | B |

## 진행자들이 유보한 것
- (모른다고 밝힌 것, 추정이라고 밝힌 것)

## 곁가지
- (본 주제 밖 언급)
```

### ② 노트 — `insights/notes/<YYMMDD>-<슬러그>.md`

```markdown
---
source: "content/understanding/피지컬AI/[YYMMDD] <짧은 제목>.md"
title: "<짧은 제목>"
date: YYYY-MM-DD
corpus: third
lang: ko
actors: [회사1, 회사2]
topics: [주제1, 주제2]
---

## 이 문서가 주장하는 것

(한 문단. 6~9문장)

## 수치

- 서술 (<라벨> L12)
- ...

## 저자가 추정이라고 밝힌 것

- 서술 (<라벨> L34)
```

**인용 규칙이 제일 중요하다.**
- `(<라벨> L12)` 의 라벨은 변환본 **파일 이름 앞 18자와 일치**해야 한다.
  파일이 `[260621] 로봇 손 세 종을 직접...` 이면 라벨은 `[260621] 로봇 손 세 종` 처럼 쓴다
- `L12` 는 **변환본 파일의 실제 줄 번호**다. 파일을 다 쓴 뒤 줄 번호를 세어서 박는다.
  줄 번호가 틀리면 `check_notes` 가 FAIL 낸다
- `## 수치` 항목은 **전부** 인용을 달아야 한다. 하나라도 빠지면 FAIL
- 노트 전체 3KB 이하

### ③ 카드 — `scratchpad/cards_sudo/<ID>.py`

`CARD = { ... }` dict 하나만 있는 파이썬 파일. UTF-8, 파일 첫 줄 `# -*- coding: utf-8 -*-`.

```python
CARD = {
    'section': 'sec-model',            # 아래 목록에서 고른다. 문자열 id만 쓴다
    'date': '2026-06-21',              # 업로드일. 섹션 안 정렬 기준
    'topic': ('infra', '주제 칩 문구'),  # 두 번째 값이 카드 위 작은 글씨
    'title': '문장형 제목',
    'gain': '이 편을 열면 무엇을 알게 되는지. 두세 문장. 접힌 채로 고르는 기준이라 반드시 쓴다',
    'meta': ['sudoremove <b>JB · JC</b>', '2026-06-21', '73분', 'YouTube'],
    'links': [('▶ 원본 영상', 'https://youtu.be/<ID>', ''),
              ('📄 자막 기반 변환본',
               'https://github.com/yohan4477/semi-report/blob/main/'
               'content/understanding/%ED%94%BC%EC%A7%80%EC%BB%ACAI/<URL 인코딩한 파일명>',
               'secondary')],
    'slim_oneliner': '두세 문장. 이 편이 무엇을 말하는지',
    'slim_points': [                    # 6~8개. 각 한두 문장. <b>소제목.</b>으로 연다
        '<b>소제목.</b> 내용.',
    ],
    'slim_stats': [('값', '라벨')],      # 4개. 자막에 실제로 나온 숫자만
    'points': [ ... ],                  # 원본 포인트 5~8개. slim 과 겹쳐도 된다
    'stats': [('값', '라벨')],           # 3~4개
    'quote': '자막에 그대로 있는 한 마디',
    'clash': [('누구/무엇', '반론 내용')],  # 2~3개. 필수
    'note': '...',                       # 아래 문구를 그대로
}
```

`note` 는 이 문구로 시작한다(뒤에 그 편에만 해당하는 주의를 덧붙여도 된다):

> 유튜브 자동 자막 전문을 <b>요약</b>한 카드입니다. 자동 인식이라 회사·모델 이름이 흔들리는
> 대목이 있어 영상 설명란과 논문으로 맞춰 적었습니다. 숫자는 진행자가 말한 것을 그대로
> 옮겼고 따로 검증하지 않았습니다. 투자 추천이 아닙니다.

## 섹션 id

| id | 무엇이 들어가나 |
|---|---|
| `sec-base` | 용어 정의, 범용화 조건, 데이터 병목 같은 기초 |
| `sec-model` | 특정 모델·회사의 방법을 뜯어보는 편 (VLA·DVA·RFM·액션모델) |
| `sec-world` | 월드모델이 주제인 편 |
| `sec-hand` | 로봇 손·하드웨어 |
| `sec-biz` | 회사 자금·시장·흥망 |
| `sec-field` | 학회·전시장·해커톤·실습기 |

## 글 규칙 — 어기면 검사기가 막는다

1. **전문용어는 쉬운 말로 바꾸지 말고 첫 등장에 괄호로 푼다.**
   예: `VLA(Vision-Language-Action, 시각·언어·행동 통합 모델)`,
   `PPO(Proximal Policy Optimization, 잘한 행동 쪽으로 정책을 조금씩 미는 강화학습 방법)`
   `slim_oneliner`·`slim_points` 안에서 첫 등장에 괄호가 없으면 `check_slim` 이 경고한다
2. **인용은 자막에 있는 말만.** `quote` 필드도 마찬가지다 — 자막을 열어 그 문장을 찾아 복사한다.
   `check_slim` 은 `quote` 필드를 보지 않으므로 지어내도 안 걸린다. 2026-08-23에 실제로
   지어낸 문장 하나가 그대로 나갔다. 자동 자막이 뭉갠 말(「텔레업」 같은 오인식)은 인용하지 말고
   제대로 된 말로 서술한다.
3. **사람의 사생활을 옮기지 않는다.** 진행자들이 농담이나 소문으로 흘린 개인 신상·사적 관계는
   빼고 기술적 사실만 남긴다. 2026-08-23에 실명 두 사람의 사적 관계 추측이 노트에 실렸다.
4. **회사 이름은 정본으로.** `insights/actor_alias.json` 의 오른쪽 이름을 쓴다.
   널리 쓰는 회사는 한글(엔비디아·오픈AI·앤트로픽), 로보틱스 신생사는 라틴(Physical Intelligence·
   Sunday Robotics·Generalist AI·Sharpa·Rhoda AI). 노트 frontmatter 의 `actors` 가 별칭이면
   `check_notes` 의 N9 가 FAIL 을 낸다. 카드 본문 표기도 같은 이름으로 맞춘다.
5. **따옴표 인용은 자막에 있는 말만.** 우리가 만든 표현이면 따옴표를 떼고 서술한다.
   `check_slim` 이 자막과 유사도 0.55 미만이면 FAIL
6. **숫자는 자막에 나온 것만.** 추정치를 만들지 않는다
7. **일반론 금지.** 「중요하다」 「주목된다」 「~할 것으로 보인다」로 끝나는 문장을 쓰지 않는다.
   숫자·명명된 주체·비직관적인 것으로 쓴다
8. **은유를 주어 자리에 두지 않는다.** 「돈이 도는 자리가 옮겨 간다」류. 무엇이 움직이는지를
   이름으로 댄다. `check_prose` P14 가 FAIL 로 막는다
9. **반론(`clash`)은 필수.** 한 편만 읽고 결론 내리지 않게, 같은 채널의 다른 편이나 이 카드
   자체의 약점(표본 하나, 데모만 있고 수치 없음, 회사 자기 발표)을 박아 둔다
10. **영어 구조를 그대로 옮긴 말을 쓰지 않는다.** 「위층·아래층」(upper/lower layer),
   「~에 대한」, 「~를 가진다」, 「~되어진다」가 대표적이다. 위계 제어를 설명할 때는
   **판단**(무엇을 할 차례인지 정하는 몫)과 **반사**(몸에 익어 생각하지 않고 나가는 동작)로
   쓴다. 2026-08-23에 「위층/아래층」으로 냈다가 되돌렸다
11. **검사기를 피하려고 표현을 비틀지 않는다.** 규칙에 걸리면 문장을 고치는 것이지 검사기가
   못 알아보게 바꾸는 것이 아니다

## 하지 말 것

- 생성기(`gen_sudoremove_dashboard.py`) 를 고치거나 돌리지 않는다
- 커밋·푸시하지 않는다
- 다른 카드 파일·다른 대시보드를 건드리지 않는다
- 자막 전문을 그대로 옮기지 않는다. 요약만 남긴다
- 카드 파일에 `figs`(그림)를 넣지 않는다. 그림은 생성기의 `EXTRA_FIGS` 가 영상 ID로 붙인다 —
  상자·화살표 helper 가 생성기에만 있어서 카드마다 SVG 를 베끼면 좌표 규칙이 갈라진다

## 마치면

만든 파일 셋의 경로와, 카드 제목 한 줄만 보고한다. 본문을 되풀이하지 않는다.
