# 사실표 위임 — AI 모델 층 (공통 지시)

저장소 루트: C:\Users\y\semianalysis

「AI 모델 기술 문서」를 쓰기 위한 **사실표**를 만든다. 글을 쓰는 일이 아니라 재료를 뽑는 일이다.
완성될 문서는 기술 문서다 — 모델 사양, 구조, 학습 절차, 수식과 수치, 설계 선택의 이유와 대가가 중심이다.
그래서 **기계적 디테일을 최대한 많이** 뽑는다. 「효율이 좋아졌다」 같은 말보다 「KV 캐시가 토큰당 X KB에서 Y KB로」 같은 값과 메커니즘이 필요하다.

## 뽑을 것 — AI 모델 자체에 한정

1. **모델 사양** — 모델 이름, 출시일, 총 파라미터 / 활성 파라미터, 층 수, 은닉 차원, 전문가 수·활성 전문가 수·공유 전문가, 어텐션 헤드, 컨텍스트 길이, 어휘 크기, 정밀도(BF16·FP8·FP4), 라이선스(오픈 웨이트 여부)
2. **아키텍처 기법** — 이름(MLA·희소 어텐션·선형 어텐션·MTP·Engram 등), **무엇을 어떻게 바꾸는지(동작 원리)**, 무엇을 줄이나(KV 캐시 바이트·FLOPs·메모리 대역폭), 대가가 무엇인가, 수식이나 크기 계산이 있으면 그대로
3. **학습** — 사전학습 토큰 수, 학습 컴퓨트(GPU 종류·수·GPU 시간·FLOPs·비용), 데이터, 미드트레이닝, 사후학습(SFT·RLHF·RL), 증류
4. **강화학습** — 알고리즘(GRPO·PPO 등), 보상 설계, 검증 가능한 보상, RL 환경, 보상 해킹 사례, 학습기·생성기 구조, 동기·비동기, 정책 지연(staleness), 처리량 수치
5. **학습 시스템** — MFU, 병렬화 방식, 장애·체크포인트, 클러스터 규모 (단 칩 자체의 사양 비교는 뽑지 않는다)
6. **추론에서 드러나는 모델 성질** — 프리필·디코드의 연산 강도, KV 캐시 크기 계산, 모델 구조가 메모리·대역폭 요구를 어떻게 바꾸나
7. **성능·벤치마크** — 벤치마크 이름, 점수, 잰 날짜, 비교 대상 모델
8. **경쟁과 랩** — 오픈 대 클로즈드 격차(몇 달·몇 점), 랩별 모델 전략·조직·학습 컴퓨트 규모, 가격(토큰당), 마진
9. **저자의 판단·예측** — 원문이 내린 결론과 그 근거

**뽑지 않는 것** — 칩·랙끼리 성능 비교(GPU 대 TPU 처리량 순위 등), 데이터센터·전력·재무 세부(모델 랩 학습 컴퓨트 지출 규모는 뽑는다), 에이전트 하네스·코딩 도구 사용법.

## 산출 형식

지정된 파일 하나로 쓴다. 다른 파일은 만들지 않는다.

```
# 사실표 <번호> — <라벨> / <라벨>

## <라벨> (발행 YYYY-MM-DD)

### <소주제 이름>
- L123-125 | <사실 한 줄. 값이 있으면 값 그대로> | 성격: 공표 / 추정 / 회사 주장 / 저자 판단 | 언제 것: 2026-05
```

소주제는 위 1~9 중 해당하는 것으로 이름 붙이되, 원문의 고유한 대목(예: 「Kimi Delta Attention 동작」)은 따로 소주제로 세운다.
**동작 원리 설명은 한 줄로 줄이지 말고 여러 항목으로 쪼개 순서대로 적는다** — 기술 문서에서 메커니즘을 다시 세워야 한다.
표가 원문에 있으면 표의 행을 항목으로 옮긴다.

## 규칙 — 반드시 지킨다

- **줄 번호를 지어내지 마라.** Read 도구가 붙인 번호를 그대로 쓴다. 다 뽑은 뒤 무작위로 열 줄을 다시 Read(offset/limit) 로 열어 확인하고, 확인했다고 파일 끝에 「확인한 줄: L.., L..」로 적어라
- **원문에 없는 것을 만들지 마라.** 값도 회사 이름도 모델 이름도. 네가 아는 지식으로 채우지 마라
- **검사기를 우회하지 마라.** 표현을 바꾸라고 제안하지도 마라
- **없으면 없다고 적어라.** 빈칸을 채우지 마라
- **파일 하나만 만들어라.** git 명령을 쓰지 마라. 다른 파일을 고치지 마라
- 값은 원문 표기 그대로(단위·범위·근사 포함). 반올림하거나 환산하지 마라
- 같은 값이 두 편에서 다르면 둘 다 적고 다르다고 표시한다
- 「성격」은 원문이 그렇게 말한 것만. 모르면 `불명`
- **재료는 전부 영문 원문 클리핑**(`C:/Users/y/clippings/semianalysis/`)이다. 한국어 변환본(`content/newsletter/`)은 열지 마라. 줄 번호는 영문 파일의 번호다
- 사실은 한국어로 옮겨 적되 고유명사·기법 이름은 영문 그대로 둔다. 숫자가 든 대목은 원문 영어 구절을 따옴표로 함께 붙인다 — 대조할 때 그 줄에서 찾는다. 화자의 단서(we think·we believe·reportedly)는 「~로 본다/~라고 전해진다」로 살린다
- 페이월 뒤가 잘린 클리핑이면(유료 구독자 전용 문구로 끝나면) 어디서 끊겼는지 파일 끝에 적는다
- 원문 전문을 읽는다. 큰 파일은 offset/limit 으로 나눠 끝까지 읽는다. 앞부분만 읽고 끝내지 마라

분량 제한 없다. **답장에는 뽑은 항목 수와 소주제 목록만** 적는다. 파일 내용을 답장에 붙이지 마라.
