에이전틱 추론의 메모리 드라이버 — 세션 하나의 HBM 은 모델에 따라 열 배 넘게 갈리고, DRAM·SSD 는 모자란 용량을 채운다

모델 KV 구조에 따라 세션 수가 13.9배 갈리고, HBM 여유 용량과 DRAM·SSD 층이 그 뒤를 잇는다

▾

앞 층은 루빈 글의 1메가와트당·1달러당 토큰을 공개 측정 행으로 다시 냈다. 이 층은 한 단 더 내려가 그 처리량을 메모리가 얼마나 정하는지 본다. 메모리 층은 셋이다. HBM(고대역폭 메모리)은 GPU 옆에 붙은 메모리다. DRAM 은 서버 본체의 CPU 에 붙은 메모리이고 SSD(반도체 저장 장치)는 그보다 크고 느린 저장 장치다. 물음도 셋이다. GPU 한 장이 받는 세션 수를 무엇이 정하나, HBM 이 차면 DRAM 과 SSD 가 무엇을 대신하나, 그 드라이버들의 크기 순서가 어떻게 되나.

재료는 InferenceX 가 GitHub Actions 에 남긴 실행 요약 파일이다. 공개 API 는 이 파일에서 서버 지표 몇 칸을 뺀다. 요약 파일에는 GPU·DRAM 에 잡은 KV 캐시(앞서 계산한 어텐션 값) 저장 공간, 그 사용률, 입력 토큰을 GPU 캐시·바깥 층·새 계산 셋으로 나눠 센 값이 다 있다. 바깥 층은 DRAM 이나 SSD 처럼 GPU 밖에 KV 를 내려놓아 두는 곳이다. 실행 72개에서 769행을 옮겼고 모델은 여덟이다.

답부터 적는다. 세션 하나가 차지하는 HBM 은 모델에 따라 5.9GB 에서 82.4GB 까지 13.9배 갈린다. 같은 모델에서 HBM 을 넓히면 세션은 여유 용량보다 조금 더 빨리 는다. DRAM 과 SSD 는 HBM 이 모자란 자리에서 캐시 용량을 채우고, 같은 사용자 속도에서 처리량을 중앙값 1.18배 올린다. 원문이 기대한 CPU-GPU 연결 속도의 효과는 이 데이터로 확인되지 않는다.

에이전틱 작업은 앞 턴의 출력이 다음 턴 입력에 붙으므로 입력 대부분을 저장해 둔 KV 에서 꺼낸다. 원문도 그 비율은 KV 를 담아 둘 저장 공간이 얼마나 되느냐에 달렸다고 적었다. 서버가 출처를 센 400행에서 새로 계산한 입력의 비중은 중앙값 6.3퍼센트다. 출력 토큰은 전체의 0.77퍼센트다. GPU 가 실제로 연산하는 토큰은 공표 처리량의 한 자릿수 퍼센트라는 뜻이다.

DeepSeek V4 Pro 를 B200 8장에서 SGLang(오픈소스 추론 엔진) 으로 돌리며 동시 세션 수(동시성)를 바꿔 간 스윕이 층 사이 이동을 가장 잘 보여 준다. 동시 세션 64에서 GPU KV 사용률이 0.99 에 닿는다. 그 뒤로 세션을 160까지 늘리면 GPU 캐시에서 꺼낸 비율이 89.8퍼센트에서 27.0퍼센트로 줄고 DRAM 에서 꺼낸 비율이 6.6퍼센트에서 67.8퍼센트로 는다. 새로 계산한 비율도 5.7퍼센트에서 9.3퍼센트로 조금 오른다. 동시 세션 160에서 입력 13.53억 토큰 가운데 DRAM 이 9.17억을 냈다. 같은 실행에서 DRAM 에 잡은 KV 저장 공간은 17,909,760토큰 가운데 15,064,832토큰이 찼다. 이 구간에서 GPU 한 장 처리량은 35,282에서 46,955토큰으로 늘다가 멈춘다. 동시 세션을 96에서 160으로 1.7배 늘렸을 때 처리량은 44,109에서 46,955토큰으로 6퍼센트만 늘었다.

여유 HBM 은 규격 용량의 90퍼센트에서 가중치(파라미터 수 × 정밀도별 바이트 ÷ 텐서 병렬 수)를 뺀 우리 가정입니다.

한 노드 실행마다 GPU KV 사용률이 0.95 를 처음 넘는 동시 세션 수를 찾았다. 0.95 는 사용률이 1.0 에 붙기 직전을 잡으려고 둔 우리 문턱이다. GPU 한 장의 여유 HBM 은 규격 용량의 90퍼센트에서 가중치 크기를 뺀 값으로 잡았다. 90퍼센트는 vLLM 이 GPU 메모리를 쓰는 기본 비율 0.9 에 맞춘 가정이다. 가중치는 HF(허깅페이스, 모델 공개 저장소) 의 파라미터 수에 파라미터 하나당 바이트(FP4 0.53, FP8 1.03, 블록 스케일 크기를 얹은 우리 가정)를 곱하고 텐서 병렬 수로 나눴다. 여유 HBM 을 그 지점의 GPU 한 장당 세션 수로 나누면 세션 하나가 쓰는 HBM 이 나온다.

같은 AgentX 트레이스를 돌리므로 세션 길이는 모델끼리 같다. 그래서 모델 사이의 차이는 토큰 하나에 드는 KV 크기의 차이로 읽는다. DeepSeek V4 Pro 가 중앙값 5.9GB, Qwen3.5 가 8.2GB, MiniMax M3 가 18.2GB, GLM-5.2(지푸 AI 의 공개 모델) 가 82.4GB 다. 가장 큰 모델과 가장 작은 모델이 13.9배 갈린다. 같은 HBM 을 단 GPU 가 받는 동시 세션 수가 모델 구조에 따라 열 배 넘게 바뀐다는 뜻이다.

세션당 HBM 추정은 거칠다. 동시성을 듬성듬성 재서 차는 지점이 한두 칸씩 흔들린다. 엔진이 가중치 말고 따로 잡는 메모리도 90퍼센트 가정 하나로 뭉쳤다. 같은 DeepSeek V4 Pro·B200 에서도 vLLM 은 세션당 2.8GB, SGLang 은 7.0GB 가 나와 엔진 차이만 2.5배다. Kimi K3 는 설정 셋이 8.6GB 에서 150.1GB 까지 흩어져, 모델 사이 순서를 보는 데만 쓰고 크기 비교에는 안 쓴다. 설정 하나는 엔진에 따라 2.5배까지 흔들리지만 모델 사이 차이 13.9배가 그보다 커서 순서는 남는다. 그래서 설정 하나의 세션당 HBM 보다 모델 사이 자릿수 차이만 결론으로 삼는다.

④ 같은 모델에서 HBM 을 넓히면 세션은 여유 용량보다 빨리 는다

같은 모델·정밀도·병렬 설정에서 HBM 만 다른 짝이 있다. Qwen3.5 를 FP4·텐서 병렬 2로 돌리면 B200 은 여유 HBM 이 55.1GB 이고 GPU 한 장이 9.0세션에서 찬다. B300 은 여유 HBM 이 152.3GB 이고 28.0세션에서 찬다. 여유 HBM 이 2.76배일 때 세션이 3.11배 늘었다.

규격 용량으로 보면 B300 은 B200 의 1.60배뿐이다. 가중치가 두 칩에서 같은 크기로 빠지므로 남는 여유분의 비는 2.76배로 벌어진다. HBM 용량을 조금 늘려도 KV 에 쓸 여유는 더 크게 늘어나는 구조다. 이 짝은 하나뿐이고 두 칩은 연산 성능도 다르므로 용량만의 효과로 못 박지는 않는다.

DRAM 내려놓기를 끈 곡선과 켠 곡선을 같은 사용자 속도에서 견줄 수 있는 칸은 11개다. 켠 곡선이 끈 곡선보다 중앙값 1.18배, 범위 1.06~1.90배 처리량을 낸다. 나머지 설정은 두 곡선이 겹치는 속도가 없다. 레시피를 보면 내려놓기를 켠 실행은 동시성이 높은 쪽에, 끈 실행은 낮은 쪽에 몰려 있다. DeepSeek V4 Pro·B200·SGLang 은 끈 곡선의 최대가 4,011토큰이고 켠 곡선의 최대가 46,955토큰이다. 켠 곡선은 끈 곡선이 닿지 않는 느린 속도 쪽으로 뻗는다.

SSD 는 공개 결과에 없다. 원문은 NVMe(PCIe 로 붙는 SSD 규격) 내려놓기를 미뤘다고 적었고 다음 단계로 SSD 층을 넣겠다고 했다. 그런데 실험 브랜치 실행에서 MiniMax M3 를 H100 8장으로 돌리며 내려놓기를 넷으로 나눠 잰 기록이 남아 있다. 공개 대시보드에 오르지 않은 실험이라 이 층의 다른 표보다 약하게 읽는다. 동시 세션 8에서 내려놓기를 끄면 GPU 한 장 처리량이 370토큰이고 새로 계산한 토큰이 15,952,572개로 불어난다. DRAM 은 945토큰, SSD 는 1,035토큰이다. SSD 가 DRAM 의 1.10배고, 끈 쪽은 DRAM 의 0.39배다. 동시 세션 10에서는 DRAM 과 SSD 모두 바깥 층이 적중의 64퍼센트를 맡고 첫 토큰 지연이 125~137초로 늘어난다.

원문의 예측은 이 데이터로 확인되지 않는다. 바깥 층 적중 최댓값을 칩별로 모으면 PCIe 5.0 의 H100 이 85.5퍼센트, H200 이 83.3퍼센트, NVLink-C2C 의 GB200 이 56.9퍼센트, GB300 이 31.6퍼센트다. 바깥 층을 많이 쓰는 칩은 연결이 넓은 칩이 아니라 HBM 이 작은 칩이다. 다만 칩을 바꾼 실행은 엔진과 서빙 방식도 함께 바뀌었다. 차이가 연결에서 왔는지 엔진에서 왔는지 가를 짝이 없어서, 연결 속도가 처리량에 주는 효과는 아직 떼어 낼 수 없다.

⑥ 메모리 드라이버의 순서와 검증하지 않은 것

지금까지 잰 크기로 드라이버를 세우면 이렇다. ①모델의 토큰당 KV 크기가 가장 크다. 같은 HBM 에서 받는 세션 수가 이것 하나로 13.9배 갈린다. ②HBM 여유 용량이 다음이다. 같은 모델에서 여유 HBM 2.76배가 세션 3.11배로 이어졌다. 짝 하나에서 나온 값이라 순서만 세우고 크기는 약하게 읽는다. ③DRAM·SSD 층은 HBM 이 모자란 자리에서만 크다. 같은 속도의 이득은 중앙값 1.18배다. 그래도 HBM 이 극단적으로 모자란 H100 에서는 층이 없으면 처리량이 절반 아래로 무너진다. ④CPU-GPU 연결 속도는 이 데이터로 크기를 못 쟀다.

검증하지 않은 것을 넷 적는다. ①여유 HBM 은 우리 가정이다. 쓸 수 있는 비율 90퍼센트와 정밀도별 바이트(FP4 0.53, FP8 1.03)는 실측이 아니며 엔진마다 다른 메모리 예약을 뭉쳤다. ②B200 HBM 은 원문끼리 180GB 와 192GB 로 갈린다. 이 층은 180GB 를 썼다. ③SSD 실험은 실험 브랜치의 한 번 측정이다. 층마다 내려놓기 소프트웨어가 다르고 사용자 속도가 초당 3~7토큰이라 실제 서비스 조건과 멀다. SSD 모델과 PCIe 세대도 기록에 없다. ④전력은 GPU 보드만 재므로 DRAM·SSD 가 먹는 전력은 이 층에 없다.
