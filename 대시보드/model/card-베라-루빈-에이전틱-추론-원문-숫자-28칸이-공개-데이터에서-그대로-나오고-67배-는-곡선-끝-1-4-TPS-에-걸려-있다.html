베라 루빈 에이전틱 추론 — 원문 숫자 28칸이 공개 데이터에서 그대로 나오고, 「67배」는 곡선 끝 1.4 TPS 에 걸려 있다

같은 사용자 속도에서 1메가와트당 토큰은 일곱 설정이 다 맞고, 67배는 170 이 아니라 171.4 TPS 에서 나온다

루빈 글(2026년 9월 14일 발행)은 베라 루빈 NVL72 가 에이전틱 추론에서 GB300 NVL72 보다 1달러당 토큰을 67배 낸다고 적었다. 에이전틱 추론은 한 세션이 수십~수백 번 턴을 주고받고, 앞 턴의 출력이 다음 턴 입력에 붙어 컨텍스트가 쌓이는 작업이다. 그래서 입력 대부분을 KV 캐시(앞서 계산한 어텐션 값을 저장해 둔 것)에서 다시 꺼내 쓴다. 원문은 결과 배수만 적고 그 배수를 낸 처리량과 단가는 적지 않았다.

그 계산에 쓰인 재료는 공개돼 있다. InferenceX 가 측정 행을 API 로 내놓고 대시보드 앱이 칩 전력·시간당 원가·보간 코드를 저장소에 올려 두었다. 이 글은 두 재료로 원문 숫자를 다시 낸다.

답부터 적는다. 대조한 원문 숫자 35칸 가운데 28칸이 반올림 안에서 맞는다. 100 TPS 에서 메가와트당 토큰은 일곱 설정이 전부 둘째 자리까지 같다. 어긋난 일곱 칸 가운데 가장 큰 제목값 「67배」는 GB300 에 TRT-LLM(엔비디아가 내놓은 추론 엔진)을 올린 곡선이 끝나기 직전에 선 값이라 사용자 속도를 1 TPS(사용자 한 명이 초당 받는 토큰 수) 옮기면 3배 넘게 바뀐다.

루빈 글의 메가와트당·1달러당·기가와트당 숫자를 InferenceX 가 공개한 측정 행과 앱 코드로 다시 냅니다. 대조한 35칸 가운데 28칸이 맞고, 제목값 「67배」는 GB300 TRT-LLM 곡선이 끝나기 직전에 선 값이라 속도에 따라 크게 바뀝니다.1. 계산을 세운다① 원문 숫자는 측정 행 하나와 칩 상수 셋에서 나온다

전력과 원가는 InferenceX 대시보드 앱 코드(커밋 6f17111)의 값이고, 측정 점과 속도 범위는 API 스냅숏에서 셌습니다. 프런티어는 더 빠르면서 처리량도 큰 점이 있는 점을 버린 것입니다.

재료는 셋이다. ①측정 행. AgentX 는 사내 Claude Code 세션 393개를 익명화해 다시 틀어 주는 부하다. 입력 길이 중앙값이 14만 2천 토큰, 출력이 444토큰이라 입력이 출력의 300배를 넘는다. 설정마다 동시 세션 수를 바꿔 가며 잰 행이 여럿이고 행마다 GPU 한 장 처리량과 P90 속도가 붙는다. P90 속도는 토큰과 토큰 사이 지연의 90번째 백분위수로 1초를 나눈 값이다. 사용자 한 명이 초당 받는 토큰 수로, 느린 쪽 10퍼센트를 뺀 스트리밍 속도다.

②칩 상수. 앱은 칩마다 전력과 시간당 원가 둘을 둔다. 전력은 칩 하나가 아니라 서버·망·냉각에 드는 전력까지 얹은 값이다. GB300 의 2.12kW 는 원문이 10메가와트(10,000킬로와트)에 GPU 4,716장이 든다고 적을 때 쓴 한 장 전력과 같다. 원가는 대형 클라우드가 사서 운영할 때와 3년 약정으로 빌릴 때 둘이다. 루빈 임대가 $8.50 은 원문이 적은 「$8.5 이상」의 하한이다.

③토큰 가격. 새 입력 백만 토큰당 $1.32, 캐시에서 꺼낸 입력 $0.044, 출력 $3.96 이다. 캐시 입력이 새 입력의 30분의 1이라는 점이 5절에서 매출 순서를 바꾼다.

② 같은 속도에 선을 그어 곡선을 읽는다

한 설정의 측정 행은 동시 세션을 늘릴수록 처리량이 오르고 속도가 떨어지는 곡선이 된다. 두 칩을 견주려면 같은 속도에서 처리량을 읽어야 하는데 측정 점이 그 속도에 떨어지는 일은 드물다. 원문 표도 측정 점 사이를 이어 읽은 보간값이라고 밝혔다.

앱은 두 단계로 읽는다. 먼저 어떤 점보다 느리면서 처리량도 낮은 점을 버려 바깥 경계만 남긴다. H200 은 다섯 점 가운데 셋만 남는다. 다음으로 남은 점 사이를 단조 3차 곡선(점 사이에서 위아래로 튀지 않게 만든 곡선)으로 잇는다. 이 곡선을 쓰는지가 결과를 바꾼다. 점 사이를 곧은 선으로 이으면 100 TPS 에서 GB300 두 엔진의 처리량 비가 원문보다 1퍼센트 벌어지고, 단조 3차 곡선으로 이으면 원문과 같아진다. 측정 범위 밖은 읽지 않는다. 루빈 곡선이 74 TPS 에서 끝나서 원문이 말한 60 TPS 쪽은 이 데이터로 잴 수 없다.

처리량은 프런티어를 단조 곡선으로 보간한 값이고, 장수는 1,000킬로와트를 칩당 전력으로 나눈 값입니다. 차이가 1퍼센트 안이면 일치로 적었습니다.

메가와트당 토큰은 GPU 한 장 처리량에 1메가와트에 드는 장수를 곱한 값이다. 루빈은 한 장이 3.3kW 를 먹어 1메가와트에 303장이 들고, GB300 은 472장이 든다. 장수에서 루빈이 3분의 2로 줄어도 한 장 처리량이 GB300 SGLang(오픈소스 추론 엔진)의 3배를 넘어 메가와트당으로 2.08배가 남는다. 원문은 2.09배다.

일곱 칸 모두 원문과 둘째 자리까지 같다. 맞추는 데 필요했던 판단은 둘이다. 루빈은 9월 10일 측정을 써야 맞는다. 앱 코드는 화면이 루빈을 그릴 때 9월 9일 측정을 쓰도록 날짜를 고정해 두었다. 두 날의 측정 점이 달라서 9월 9일 곡선으로는 원문 값이 안 나온다. B300 vLLM 은 8월 11일과 21일 측정을 한 곡선으로 모아야 5.56 이 나온다. 21일 측정만으로는 속도가 120 TPS 아래로 안 내려가 100 TPS 를 못 읽는다.

같은 메가와트당 토큰으로 150 TPS 에서 루빈이 내는 37백만 tok/s, 170 TPS 에서 루빈이 GB300 TRT 의 62.9배라는 값도 맞는다.

④ 「67배」는 곡선 끝 바로 앞에 선 값이다

1달러당 토큰은 GPU 한 장 처리량을 시간당 원가로 나눈 값이다. 사서 운영할 때 원가는 루빈 $3.61, GB300 $2.31 이다. 170 TPS 에서 이 값으로 배수를 내면 62.6배다. 원문은 67배다.

어긋난 까닭은 GB300 TRT-LLM 곡선에 있다. 이 설정이 잰 가장 빠른 점이 171.53 TPS 다. 170 TPS 는 끝에서 1.5 TPS 앞이다. 거기서 GB300 은 동시 세션 4개를 돌리던 점 근처라 GPU 한 장 처리량이 1천 토큰 아래로 떨어진다. 같은 곡선이 100 TPS 에서는 한 장에 44,832토큰을 낸다. 분모가 끝에서 그렇게 작아지니 속도를 조금만 옮겨도 배수가 크게 바뀐다. 169 TPS 에서 59.9배, 171.4 TPS 에서 67배가 된다. 원문의 67배는 170 TPS 라는 글자와 1.4 TPS 어긋난 자리에서 나온다.

같은 비교를 GB300 이 실제로 많이 돌 속도로 옮기면 배수가 작아진다. 원문은 60~100 TPS 에서 1.4~3배라고 적었다. 모델은 루빈이 잴 수 있는 75~100 TPS 에서 1.44~2.80배를 낸다. 원문도 170 TPS 배수를 인용할 때 엔진 이름이 반드시 붙어야 한다고 적었다. 같은 170 TPS 에서 GB300 SGLang 대비로는 5.56배이기 때문이다.

토큰 가격과 가동률은 앱의 기본값입니다. GB300 TRT 의 캐시 적중만 서버가 재지 않아 트레이스 이론값이 들어갔습니다.

원문은 75 TPS·가동률 60퍼센트에서 루빈이 기가와트당 연 매출 $159.5십억, 이익 $149.9십억을 낸다고 적었다. 모델도 같은 값을 낸다. 계산은 GPU 한 장 처리량에 섞은 단가를 곱하고, 1기가와트에 드는 GPU 의 한 해 시간과 가동률을 곱한다. 섞은 단가는 입력 비중 × (캐시 적중 × 캐시 입력가 + (1 − 캐시 적중) × 새 입력가) + 출력 비중 × 출력가다.

여기서 순서가 뒤집힌다. 75 TPS 에서 GB300 TRT-LLM 은 한 장 처리량이 93,574토큰으로 SGLang 의 80,187토큰보다 많다. 그런데 기가와트당 매출은 TRT 가 $94.1십억, SGLang 이 $114.5십억이다. 입력이 전체 토큰의 99퍼센트를 넘으니 매출은 입력을 얼마에 파느냐에 달렸다. 캐시에서 꺼낸 입력은 30분의 1 값에 팔린다. TRT 의 캐시 적중이 96.9퍼센트, SGLang 이 93.2퍼센트라 TRT 토큰이 더 싸게 팔린다.

그 96.9퍼센트는 잰 값이 아니다. GB300 TRT 행은 서버가 캐시 적중을 보고하지 않아 앱이 이론값을 대신 넣는다. 이론값은 녹화된 세션의 요청 순서만 보고, 캐시가 하나도 안 지워진다고 칠 때 입력 가운데 얼마를 다시 쓸 수 있는지 센 값이다. 실제 서버는 메모리가 차면 캐시를 지우므로 이론값이 실측보다 높게 서기 쉽다. SGLang 은 같은 GB300 에서 실측이 93.2퍼센트였다. SGLang 과 루빈은 서버가 잰 값을 쓴다. 그래서 원문이 매출 비교에서 SGLang 을 GB300 의 가장 강한 설정으로 고른 것은 엔진 성능보다 측정 방식에서 온 차이일 수 있다.

10메가와트짜리 GPU 묶음으로 옮겨도 맞는다. GB300 4,716장이 하루 253만 달러, 루빈 3,030장이 하루 430만 달러로 1.7배다. 하루 매출에는 가용률 0.9796 을 곱했다. 앱이 평균 고장 간격 24일을 고장 간격과 복구 시간 12시간의 합으로 나눠 낸 값이다.
